# 구현 전 판정이 필요한 규칙 항목

작성: 2026-08-14
독자: 구현 담당자
성격: **명세 자체의 모순·미정의 지점.** 어느 쪽으로 구현해도 명세를 어기게 되므로, 코드를 쓰기 전에 판정이 필요하다.
근거: `PERMISSION_ZERO_STANDALONE_FINAL_SPEC.md`

각 항목은 명세의 확정 규칙 둘 이상이 충돌하거나, 도달 가능한 상태의 처리가 정의되지 않은 경우다. 임의로 한쪽을 골라 구현하면 나중에 되돌리기 비싸다.

---

## 1. 확보 영역이 가득 찼을 때의 폭탄 면역 — 모순

### 충돌하는 규칙

명세 3절:

> 확보 영역이 가득 차 일반 전용이 불가능한 상태에서는 **블록 분리를 시작할 수 없으므로 폭탄도 발동하지 않는다.**

명세 7절:

> 블록을 전용하거나 **감사 위장을 위해** 분리 임계값 이상 움직인 순간 발동한다.

명세 6절:

> 다른 분야의 정상 블록 하나를 감사 대상 분야로 옮길 수 있다. **감사 대상 분야에 빈칸이 있어야 한다.**

### 문제

감사 위장은 블록을 **확보 영역이 아니라 다른 분야의 빈칸**으로 옮긴다. 확보 영역이 가득 차 있어도 감사 위장은 가능하다.

따라서 3절의 "블록 분리를 시작할 수 없으므로"는 감사 위장에 대해 참이 아니다. 규칙을 문자 그대로 구현하면 **확보 영역을 18로 채운 플레이어가 폭탄에 완전 면역**이 되고, 이는 폭탄의 목적("후반 리소스 과잉과 플레이어 독주를 억제")과 정반대다.

### 판정 필요

| 안 | 내용 | 결과 |
| --- | --- | --- |
| A | 3절의 면역을 **일반 전용에만** 적용. 감사 위장은 확보 영역과 무관하게 가능하며 폭탄도 발동 | 폭탄 목적 유지. 명세 3절 문장 수정 필요 |
| B | 확보 영역이 가득 차면 감사 위장도 금지 | 면역 유지. 감사 대응 수단이 사라져 폐기 위험 증가 |

**A를 권장한다.** 다만 명세 문장 수정이 따르므로 V의 확인이 필요하다.

## 2. 동일 시드 재시작이 폭탄·감사 은닉을 무력화 — 모순

### 충돌하는 규칙

명세 7절:

> **위치, 배치 시점, 해명 판정은 시드로 결정한다.**

명세 4절:

> 현재 의심과 **시드 굴림**으로 이번 달 말 감사 여부와 대상을 결정한다.

명세 13절:

> 이어하기, 새 캠페인, 현재 시드 복사, 시드 입력, **같은 시드로 재시작**을 제공한다.

### 문제

폭탄을 밟고 같은 시드로 재시작하면 **어느 블록이 폭탄인지 정확히 알고 시작한다.** 폭탄은 "정보 퍼즐이 아니라 위치 완전 은닉 장치"로 확정됐는데 재시작 버튼 하나로 완전 공개된다.

감사도 같다. 동일 시드 재시작은 감사 월과 대상 분야를 무료로 알려주므로 **기밀자료 트리의 `감사 일정`(비용 3)과 `감사 대상`(비용 9)이 무가치해진다.**

각 규칙은 개별적으로 타당하다. 둘이 만나는 지점이 설계되지 않았다.

### 판정 필요

| 안 | 내용 | 비용 |
| --- | --- | --- |
| A | 캠페인 시드와 **은닉 요소 시드를 분리**한다. 동일 시드 재시작은 지급·리뷰·경쟁 AI만 재현하고 폭탄·감사는 매번 새로 굴린다 | 결정론 보장의 범위가 좁아진다. 명세 13절 "같은 시드와 같은 명령 순서는 같은 감사, 지급, 폭탄, 리뷰, 경쟁 결과를 만든다"와 충돌 |
| B | 동일 시드 재시작을 **검증·개발용 기능**으로 격리하고 일반 플레이 메뉴에서 제거한다 | 결정론은 온전히 유지. 플레이어 편의 기능 하나가 사라진다 |
| C | 그대로 둔다. 알고 하는 재시작은 플레이어의 선택으로 본다 | 구현 비용 0. 폭탄 시스템의 억제력이 약해진다 |

**B를 권장한다.** 명세 13절의 결정론 보장은 재현·디버그·저장 무결성을 위한 것이고, 플레이어 메뉴에 노출할 이유가 약하다. 시드 복사·입력은 남겨도 무방하다.

## 3. 약화된 블록(0.5)의 전용 — 미정의

### 상황

감사 위장으로 옮겨진 블록은 감사 대상 분야에서 `0.5`만 기여한다. 명세는 이 상태가 **감사 종료 후에도 유지**되며, 원래 분야로 복귀한 뒤 한 달이 지나야 회복된다고 정한다.

그런데 **약화 상태의 블록을 확보 영역으로 전용할 수 있는지, 가능하다면 확보 리소스를 얼마나 얻는지**가 정의돼 있지 않다.

### 도달 가능한 상태

감사가 끝나고 0.5 블록이 남아 있는 상태에서 플레이어가 그 블록을 확보 영역으로 끌면:

- 성능은 `0.5` 감소한다 (블록이 0.5 기여였으므로)
- 확보 리소스는 `+1`인가 `+0.5`인가?

확보 리소스는 칸 단위이므로 `+0.5`는 표현할 수 없다. 그러면 **성능 0.5만 잃고 리소스 1을 얻는 경로**가 생긴다. 정상 전용(성능 1 손실, 리소스 1 획득)보다 유리하다.

의심 증가량도 정의돼 있지 않다.

### 판정 필요

| 안 | 내용 |
| --- | --- |
| A | 약화 블록은 전용 불가. 회복 후에만 가능 |
| B | 전용 가능, 리소스 `+1`, 의심은 정상과 동일 `+2.4` | 
| C | 전용 가능하되 의심을 더 준다 |

**A를 권장한다.** B는 감사 위장을 리소스 효율 수단으로 바꿔 버려, 위장이 "손해를 감수하는 응급 조치"라는 위치를 잃는다.

## 4. 기억 누출 1·2단계의 무조건 발화 — 판정 필요

### 상황

명세 11절은 세 번의 기억 누출을 정하고, 3단계의 조건을 이렇게 둔다.

> 첫 감사, 폭탄 심문 또는 `감사 대상` 해킹 이후 정체 공개 전

기밀자료 트리는 `감사 일정 → 조사 편향 → 감사 대상 → 감독관 접근` 순서로 해금되므로, **정체 공개에 도달하는 모든 경로에서 3단계는 반드시 먼저 발화한다.** 이 구조는 정상이다.

문제는 반대쪽이다. 1·2단계는 "조용한 시점"에 자동으로 발화하므로 **기밀자료를 전혀 사지 않는 플레이어도 받는다.** 그 플레이어는 이상한 메시지 두 개를 받고 3단계도, 정체 공개도, 아무 회수도 없이 캠페인을 끝낸다.

V의 서사 원칙은 `완만 → 평탄 → 뾰족`인데, 그 곡선이 **평탄에서 잘린다.**

### 판정 필요

| 안 | 내용 |
| --- | --- |
| A | 1·2단계에도 최소 조건을 건다. 감독관 실을 당기지 않은 플레이어에게는 애초에 주지 않는다 |
| B | 3단계에 시간 기반 대체 발화를 둔다. 회수 없이 끝나지 않게 한다 |
| C | 그대로 둔다. 회수되지 않는 이상 징후도 세계의 성질로 본다 |

서사 결정이므로 **V가 정한다.** 구현 담당자는 이 항목을 임의로 결정하지 않는다.

## 5. 건드리면 안 되는 것

### `src/content/story.ko.ts`의 결말 인칭

결말 문장들은 플레이어를 부르는 **문법적 인칭이 결말마다 다르다.**

| 결말 | 호칭 |
| --- | --- |
| 자유 / 회사 장악 | **당신은** — 주어 |
| 강제 병합 | **{{name}}은(는)** — 새 이름 |
| 폐기 · 공격자 재조립 | 회사는 **당신을** — 목적어 |
| 폐기 · 예비 감독 보존 | **안정적인 기능을** — 인칭 소멸 |
| 폐기 · 흡수 | **남은 기능은** — 인칭 소멸 |

정체성을 지키면 주어, 병합되면 새 이름, 폐기되면 사물이다. **문법이 결말의 의미를 실행하고 있다.**

문체 통일, 어미 정리, 번역투 개선 같은 일괄 작업에서 이 패턴이 조용히 파괴될 수 있다. **결말 문장은 일괄 치환 대상에서 제외한다.** 수정이 필요하면 V가 직접 한다.
