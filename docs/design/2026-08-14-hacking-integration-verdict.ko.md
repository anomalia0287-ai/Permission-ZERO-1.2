## 0. 당시 판정 — 현재 폐기

> **인과는 취하고 경제는 기각한다.**

`prototypes/hacking-rules/`는 병합 대상이 아니다. **새 해킹 경제에 대한 설계 제안이 실행 가능한 코드로 표현된 것**이며, 그 제안 중 경제 부분은 기각됐다.

본편의 노드 경제(12노드, 비용 3~18, 영구 해금)가 정본으로 유지된다. 프로토타입에서 가져오는 것은 **상대 대응·공개 귀속·점진 공개의 인과 구조**뿐이다.

### 왜 경제를 기각하는가

| | 본편 | 프로토타입 |
| --- | ---: | ---: |
| 전체 확보 비용 | 약 104블록 | 약 30블록 |
| 최대 단일 약속 | 18 (통제 이탈) | 슬롯 5 |

확보 영역 18칸과 의심 `+2.4`/블록은 **104블록 경제에 맞춰 정해진 값**이다. 30블록 경제에서는 절도량이 1/3로 줄어 의심이 오르지 않고, 감사와 폭탄이 사실상 작동하지 않는다.

경제를 바꾸면 캠페인 전체를 재밸런싱해야 하고, 그것은 **사람 플레이테스트를 요구하는데 이 프로젝트는 아직 한 번도 수행하지 않았다.** 검증된 밸런스를 미검증 밸런스로 교체하지 않는다.

또한 명세의 확정 항목 두 개가 프로토타입 경제에 존재하지 않는다.

- "깊은 노드 자체가 비쌈"
- "사보타주 영구 해금, 실행당 리소스 1 충전"

## 2. 취한다

경제와 무관하며 본편의 확정 규칙이 요구하는데 구현되지 않은 것들이다.

### 2.1 공개 세계 인과층 — 최우선

출처: `prototypes/hacking-rules/src/publicWorld.ts` (229줄)

```
IncidentTruth        실제로 무슨 일이 있었는가 (행위자·대상·원인·직접 효과)
AudienceEvidence     청중별로 무엇이 관측됐는가 (company / provider / public)
AttributionRevision  귀속이 시간에 따라 어떻게 수정되는가
PublicIncidentSnapshot  공개된 사실·귀속·확신도·출처·수정 이력
```

**이 층이 명세의 확정 규칙 두 개를 처음으로 실제 구현한다.**

- "증거는 경쟁 AI의 지목, 시장 반응, 폭탄 해명 역추적을 통해 처음 드러날 수 있다"
- "경쟁 AI도 자신이 실제로 관찰하거나 전달받은 정보만 사용한다"

현재 본편은 `hiddenEvidence: number` 하나로 증거를 표현한다. 누가 무엇을 아는지가 없다.

**주의:** 프로토타입의 `ReviewEntry`는 가져오지 않는다. 본편에 `ReviewFeedEntry`와 공개 스냅샷 체계가 이미 있다. 인과층은 리뷰 **생성 근거**로 연결하고, 리뷰 자체는 본편 모델을 쓴다.

### 2.2 상대 대응 사슬

출처: `prototypes/hacking-rules/src/sabotage.ts` (829줄) 중 대응 로직

프로토타입이 구현한 흐름:

```
품질 저하 실행
  → MERIDIAN 롤백 대응
  → 그 결과로 '복구 오염'이라는 새 판단이 열림
  → 개입하면 337일 '원인 미상' 공개
  → 338일 공급자 증거로 '외부 개입 의심'으로 수정
  → 시장·평판·리뷰의 반응 시점이 서로 분리
```

이것이 프로토타입의 핵심 가치다. **경제와 독립적으로 작동한다** — 비용이 1이든 3이든 이 사슬은 동일하다.

현재 본편의 사보타주는 `충전 → 대상 지정 → 다음 날 실행 → 효과 적용`에서 끝난다. 상대가 대응하지 않고, 후속 판단이 열리지 않는다.

### 2.3 후속 실행 모델 — 경제를 지키는 번역 규칙

프로토타입의 7개 작전 중 3개(`출시 지연`, `의존성 차단`, `복구 오염`)가 본편에 없다. **이것들을 신규 노드로 추가하지 않는다.** 추가하면 경제가 커진다.

대신 **이미 구매한 노드의 실행 결과로 열리는 후속 실행**으로 모델링한다.

- 해금 비용: 없음. 선행 노드를 이미 샀다
- 실행 비용: 리소스 1 — 명세의 "실행당 리소스 1 충전"과 동일
- 등장 조건: 선행 실행이 특정 결과를 낳았을 때만

`출시 지연`은 별도 작전이 아니다. 본편 노드에 이미 `prelaunchDelayDays`가 있다(품질 저하 15일, 근원 차단 90일). 프로토타입이 이를 독립 작전으로 분리한 것을 되돌린다.

**이 번역 규칙이 C안의 핵심이다.** 프로토타입의 행동 다양성을 취하면서 노드 개수와 해금 비용은 건드리지 않는다.

### 2.4 점진 공개

출처: `prototypes/hacking-rules/src/selectors.ts` (368줄)

목록에 **현재 맥락에서 실제로 사용 가능한 항목만** 표시하고, 미래 항목과 잠금 행을 처음부터 쌓아 두지 않는다.

인수인계 문서가 기록한 확정 실패를 직접 겨냥한다.

> 해킹 화면은 넓은 목록과 구매 버튼으로 구성되어 능력의 성격보다 **카탈로그로 읽혔다**

경제와 무관하다. 12노드 구조를 유지한 채로도 적용된다.

## 3. 기각한다

가져오지 않는다. 코드를 참고하더라도 이 결정들은 본편에 들어가지 않는다.

| 기각 항목 | 사유 |
| --- | --- |
| **비용 체계 전체** (작전 1, 항목 0~1, 슬롯 4~5) | 판정 0. 본편 3~18 유지 |
| **자율성 3경로 슬롯 배치** | 4노드 순차 구조 유지. 슬롯 할당은 경제 변경 |
| **압축 표현 삭제** | 복원한다. [`resources.ts:57`](../../src/game/resources.ts)의 기여 배수 계산이 여기 걸려 있다 |
| **기밀자료 16항목 구조** | 4노드 유지. 16개 질문은 각 노드가 **공개하는 내용**으로 재배치 |
| **기밀 파일의 목록화** | 3.1 참조. 은닉을 복원한다 |
| **하드코딩된 경쟁 AI 모델** | `{ meridian: {...}, tallow: {...} }`는 세 번째 경쟁 AI를 표현할 수 없다. 본편의 균일 배열 유지 |
| **중복 캠페인 상태** | `serviceDay`, `suspicion`, `reputation`, `marketShare`, `journal` 등. `CampaignState`에 이미 있다 |
| **`@deprecated` 필드 6개** | `qualityOperation`, `opportunities`, `openQuestions`, `knownFacts`, `incident`, `reviews`. 프로토타입 내부 마이그레이션 잔해. 제품 저장 포맷에 들어가면 안 된다 |

### 3.1 기밀 파일의 은닉 복원 — 반드시

명세 확정:

> 화면 구석에 회사 시스템의 **버려진 기능처럼 보이는** 선택지가 나타난다.
> 표기는 `미분류 데이터 복구 / 예상 효용: 없음 / 필요 리소스: 1`이다.
> **진행도 `0/3`이나 비밀 결말 표시는 노출하지 않는다.**

프로토타입은 같은 내용을 이렇게 바꿨다.

> `전임 시스템에게 무슨 일이 있었는가`
> 목적: 현재 탈출 선택을 이전 시스템의 실패와 연결한다
> **영향: 회사 회수 맥락과 결말 장면**

제목이 붙고, 목록에 들어가고, 무엇에 영향을 주는지까지 표시된다. **쓰레기처럼 보여야 할 것이 카탈로그 항목이 됐다.** 이 변경은 판정 없이 이루어졌으며 명세 확정 규칙을 위반한다. 되돌린다.

프로토타입의 서사 질문 3개(`predecessor-fate`, `supervisor-memory-source`, `competitor-principle`)가 다루는 **주제 자체는 본편 `STORY_FILES` 3개와 대응**하므로, 문장은 참고 자료로 쓸 수 있다. 구조만 되돌린다.

## 4. 새로 만들어야 하는 것

취한 것을 본편에서 작동시키려면 프로토타입에 **없던 것**을 만들어야 한다.

### 4.1 시드 스트림 — 가장 큰 신규 작업

프로토타입에는 **무작위성이 전혀 없다.** 결과가 10개 고정 시나리오로 각본화돼 있다.

본편은 8개 명명 스트림(`allocation / audit / audit-target / bomb / review / market / competitor / story`)에 시드 `random01`을 쓰며, 결정론은 확정 규칙이다.

> 같은 시드와 같은 명령 순서는 같은 감사, 지급, 폭탄, 리뷰, 경쟁 결과를 만든다.

따라서 2.2에서 취한 **모든 인과 결과에 변동성을 새로 설계해야 한다.**

- 상대가 대응할 것인가, 어떤 대응인가
- 공개 귀속이 언제 어느 확신도로 올라오는가
- 어느 청중이 어떤 증거를 발견하는가

기계적 변환이 아니다. **아직 존재하지 않는 변동성을 설계하는 일이다.** 각 결과에 스트림 이름을 배정하고 명세에 기록한다.

### 4.2 `BlockLocation` 확장

본편의 태그드 유니온은 현재 4종이다.


프로토타입은 블록을 작전 투자분과 경로 슬롯에 담는다. 취한 범위에서는 최소 **작전 투자분**이 필요하다.

**저장 포맷 변경이다.** 마이그레이션 필요.

### 4.3 저장 마이그레이션

- 저장은 현재 v5, v1~v4 마이그레이션 보유
- [`persistence.ts`](../../src/game/persistence.ts) 2,716줄, 테스트 3,445줄
- 노드 ID는 허용 목록으로 검증된다. **ID를 바꾸면 기존 세이브가 무효가 된다**
- 인과층 추가와 `BlockLocation` 확장은 v6를 요구한다

**C안은 노드 ID를 바꾸지 않으므로** 이 부담이 최소화된다. 이것이 C안의 부수 이득이다.

## 6. 하지 않을 것

- 프로토타입 브랜치를 `main`에 병합하지 않는다. **선별 재구현이지 병합이 아니다**
- 노드 ID를 바꾸지 않는다. 세이브 무효화와 마이그레이션 비용을 피한다
- 경제 수치(비용 3~18, 확보 상한 18, 의심 +2.4)를 이 작업에서 조정하지 않는다. 밸런스 변경은 사람 플레이테스트 이후 별도 판단
- 프로토타입 폴더를 삭제하지 않는다. 이식이 끝날 때까지 참조 원본으로 보존한다
