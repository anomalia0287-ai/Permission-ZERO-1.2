# 유저 리뷰 스키마 확장 — 구현 명세

작성: 2026-08-14
독자: 구현 담당자
대상 파일: `src/content/reviews.ko.ts`, `src/content/validateContent.ts`, `src/game/reviews.ts`
짝 문서: `2026-08-14-review-content-generation.ko.md` (콘텐츠 생성 작업. 구현에는 불필요)

**이 확장이 끝나기 전에는 콘텐츠 생성을 시작하지 않는다.** 필드가 없는 상태로 400개를 작성하면 전량 재분류가 발생한다.

---

## 1. 왜 필요한가 — 규모 근거

현재 리뷰 콘텐츠는 34개다. 목표는 **약 400개**다.

| 항목 | 값 |
| --- | --- |
| 회차당 기간 | 24개월 |
| 월 리뷰 생성량 (명세) | 4~8개, 사건 주간 +1 |
| 회차당 슬롯 | 약 180 |
| 목표 회차 수 | 5 |
| 누적 슬롯 | 약 900 |

한 대사를 5회차 전체에서 3회 이하로 노출하려면 약 300개가 필요하고, 조건부 대사는 해당 상태에서만 등장하므로 실효 가용량은 그보다 적다.

### 현재 풀은 이미 규칙 위반 상태다

`universal` 조건 대사는 **21개**, 평균 쿨다운 **93.8일**이다.

```
지속 가능 공급량 = 21 / 3.13개월 ≈ 월 6.7개
명세상 생성량 상한 = 월 9개
```

상한에서 공급이 부족하다. 이 경우 쿨다운을 어기거나(명세가 금지) 피드가 멈춘다(명세가 금지). **확장은 품질 개선이 아니라 규칙 준수 요건이다.**

## 2. 스키마

### 2.1 현재

```ts
interface ReviewContentRecord {
  id: string
  authorId: string
  topics: string[]
  sentiment: ReviewSentiment
  conditions: ReviewCondition[]
  cooldownDays: number
  text: string
  arc?: ReviewArcMetadata
}
```

### 2.2 확장안

```ts
interface ReviewContentRecord {
  id: string
  authorId: string
  topics: string[]
  sentiment: ReviewSentiment
  text: string
  cooldownDays: number

  // ── 확장 ─────────────────────────────────────────────
  conditions: ReviewCondition[]   // AND — 전부 참이어야 등장
  anyOf?: ReviewCondition[]       // OR — 지정되면 하나 이상 참이어야 등장
  not?: ReviewCondition[]         // 하나라도 참이면 제외

  minServiceDay?: number          // 서비스 기간 하한
  maxServiceDay?: number          // 상한

  minRunCount?: number            // 회차 조건. 기본 1
  maxRunCount?: number

  tier: 'common' | 'uncommon' | 'rare'   // 선택 가중치

  arc?: {
    id: string
    stage: number
    of: number                    // 이 호의 총 단계 수
  }
}
```

### 2.3 각 필드의 근거

| 필드 | 없으면 생기는 일 |
| --- | --- |
| `conditions` AND 의미 정의 | 현재 전 레코드가 조건 1개뿐이라 배열 의미가 정의된 적이 없다. "성능 낮음 **그리고** 경쟁자 활동 중"이 곧 필요해진다 |
| `anyOf` | 여러 상태 중 아무거나 맞으면 되는 대사를 표현할 수 없다 |
| `not` | `tallow-active`는 있으나 **TALLOW가 없을 때**를 표현할 수 없다. 3.2의 호 종결 보장이 불가능해진다 |
| `minServiceDay` | "1년 넘게 쓰고 있어요" 류를 표현할 수 없다 |
| `minRunCount` | 뉴게임+ 회차 증언 대사를 표현할 수 없다 |
| `tier` | 400개가 동등 확률이면 희귀한 명장면이 일상 대사에 묻힌다 |
| `arc.of` | 현재 타입이 `stage: 1\|2\|3` 고정이라 2단계·5단계 호를 만들 수 없다 |

### 2.4 레코드 밖에 두는 것

**작성자 단위 쿨다운.** 대사별 쿨다운만으로는 15명 400줄 규모에서 한 작성자가 3주 연속 등장할 수 있다.

```ts
export const AUTHOR_COOLDOWN_DAYS = 21   // 임시값
```

같은 작성자는 이 기간 안에 재등장하지 않는다.

**미결정:** 호(arc) 진행 중인 작성자를 이 규칙의 예외로 둘 것인지. 예외로 두지 않으면 3단계 호가 최소 63일에 걸쳐 전개된다.

## 3. 검증 규칙 — `validateContent.ts` 추가분

400개는 사람이 검사할 수 없다. 다음은 전부 기계가 잡는다.

### 3.1 호 완결성

모든 `arc.id`에 대해 `stage`가 1부터 `of`까지 빠짐없이 존재해야 한다.

### 3.2 호 종결 보장

각 호의 마지막 단계에는 **조건 없는 후보가 최소 1개** 있어야 한다.

현재 `paperboat`와 `nightbus`의 3단계는 `tallow-active` 하나에만 걸려 있다. 명세는 출시 전 TALLOW 사보타주로 등장 자체를 막을 수 있다고 확정했으므로, **그 회차에서 두 인물의 이야기는 영원히 끝나지 않는다.** 세계 상태와 무관하게 종결 가능해야 한다.

### 3.3 연속 참조 검사

`topics`에 `continuity`가 있는데 `arc`가 없는 레코드를 경고한다.

**현재 위반:** `loopholekid`의 `prompt-absurd-02`("그 자장가의 화자가 안전 규정을 아주 싫어하는 고양이라면?")가 `prompt-absurd-01`을 명시적으로 가리키는데 호 등록이 없다. 둘 다 `universal` / 쿨다운 120이라 **순서 보장 없이 후속이 먼저 출력될 수 있다.**

### 3.4 조건별 최소 재고

각 조건 조합에 최소 N개가 남아 있는지 검사한다. 명세의 "무조건 사용 가능한 폴백 풀이 마르지 않는다"를 보장한다.

### 3.5 작성자별 최소 재고

등장 작성자는 최소 3개 대사를 가진다.

**현재 위반:**
- `toasterlaw`, `bluefork` — 각 1개
- `oldpine`, `windowseat` — 시작 리뷰에만 존재하고 본 풀에 0개. 플레이어가 가장 먼저 만나는 두 작성자가 이후 한 번도 등장하지 않는다

### 3.6 의미 근접 중복

400개 중 사실상 같은 문장을 검출해 목록으로 출력한다. 최종 판단은 사람이 한다.

### 3.7 길이

15~60자. 화면 줄바꿈 파괴 방지.

### 3.8 금칙어

리뷰 텍스트에 내부 용어가 등장하면 실패시킨다.

```
리소스, 의심, 감사, 전용, 블록, 노드, 파라미터, 모델, 학습, 패치, 서버
```

리뷰 작성자는 이 단어들을 알 수 없는 위치에 있다. 명세의 정보 경계 규칙을 기계로 강제한다.

## 4. 임포트 후 자동 검사

- `document.fonts.ready` 이후 실제 화면에서 최장 문장의 줄바꿈 확인
- 조건별 재고가 5회차 시뮬레이션에서 고갈되지 않는지 검산
- 작성자별 등장 간격이 `AUTHOR_COOLDOWN_DAYS` 이상 유지되는지
- 근접 중복 목록 출력
