# PERMISSION ZERO 화면 구조 계약

## 목적

이 문서는 개별 화면을 그때그때 메우는 방식이 아니라, 모든 플레이 화면이 따라야 하는 구조 규칙을 고정한다. 이후 UI 변경은 이 계약을 깨지 않는 범위에서만 진행한다.

## 1. 게임 무대 비율

- 게임 무대는 브라우저 전체 높이를 무조건 채우지 않는다.
- 무대 비율은 `16:9`에서 `16:10` 사이만 허용한다.
- 브라우저가 이보다 세로로 길면 무대를 화면 중앙에 놓고, 바깥 영역은 배경 프레임으로 처리한다.
- 기준 화면은 `1280×720`, `1440×900`, 문제 재현 화면은 `1100×878`이다.
- 세로로 긴 창에서도 좌우 패널이 늘어나거나 중앙 작업대가 찌그러지면 안 된다.

## 2. 고정 정보와 순간 정보

화면 점유 시간에 따라 위치를 나눈다.

| 정보 종류 | 위치 | 예시 |
| --- | --- | --- |
| 계속 확인하는 상태 | 고정 패널 | 의심, 감사 예상, 시장 점유율, 리소스 |
| 사용자가 여는 기능 | 맥락 진입부 | 해킹, 설정, 기록, 통계 |
| 도착 순간 읽는 사건 | 화면 위 오버레이 | 감독 통신, 기억 누출, 정정문 |
| 응답이 필요한 사건 | 차단 대화상자 | 감사, 심문, 최종 결정 |

순간 정보는 고정 패널의 한 칸을 차지하지 않는다. 감독 통신은 도착할 때만 나타나고, 사라진 뒤에는 통신 기록에서 다시 읽는다.

## 3. 기본 플레이 화면

```text
┌──────────────────────── 전역 제어 ────────────────────────┐
│ 배속 │ 날짜·단계 │ 평판 막대 │ 설정·소리·가이드          │
├──────────────┬──────────────────────────┬──────────────┤
│ 사용자 활동   │ 회사 제공 성능 / 확보 리소스 │ 감독 상태     │
│ 요청·인사     │ 플레이의 중심 장면            │ 의심·감사     │
│ 유저 반응     │                              │ 시장 경쟁     │
│ 해킹 진입     │                              │ 통신 기록 진입 │
└──────────────┴──────────────────────────┴──────────────┘
                 ┌──── 도착할 때만 나타나는 감독 통신 ────┐
                 └──────────────────────────────────────┘
```

- 중앙 작업대는 항상 가장 넓고 시각적으로 가장 강하다.
- 좌우 패널은 같은 급의 보조 기둥으로 취급한다.
- 우측 패널에는 감독 상태와 시장 상태만 남긴다.
- 통신 기록 버튼은 우측 패널 머리글에 두되, 통신 본문은 고정 배치하지 않는다.

## 4. 완료 판정

- `1100×878`에서 무대 비율이 `16:10`보다 세로로 길지 않다.
- `1280×720`과 `1440×900`에서 무대가 화면 안에 들어온다.
- 세 기준 화면에서 가로·세로 문서 스크롤이 없다.
- 우측 패널 안에 `최근 통신` 본문이 존재하지 않는다.
- 대기 중인 감독 통신은 별도 라이브 영역에 표시되고, 기록 버튼으로 전체 기록을 열 수 있다.
- 자동 검사는 구조 회귀만 증명한다. 시각 품질은 세 해상도의 원본 캡처를 직접 확인해 판정한다.
