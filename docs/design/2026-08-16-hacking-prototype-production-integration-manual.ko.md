- 확정일: 2026-08-16
- 확정자: V
- 상태: **해킹 분야 본편 통합 정본**
- 적용 대상: 후속 프로토타입의 규칙·콘텐츠·인과·UI를 본편 `src/`에 통합하는 모든 작업
- 현재 구현 상태: **후속 해킹 코어·본편 자원/시장/리뷰 접점·명령 프로토콜 v3·저장 포맷 v6·작전 장면 UI 이식 및 자동 브라우저 관문 통과**

- 작업 원칙: 직접 수행, 하위 에이전트 사용 금지, 사용자 승인 없는 push·merge·PR 금지

## 0. 이 문서의 판정

후속 프로토타입은 2026-08-11 본편 해킹 명세의 선택적 참고 자료가 아니다. 기존 본편에 있던 해킹의 게임성, 경제, 정보 구조, 상대 반응, 공개 세계 인과, 탈출 조건, 화면 판독성 문제를 검수하고 개선한 **후속 정본**이다.

해킹 범위에서 문서나 코드가 충돌하면 다음 순서로 판단한다.

1. V가 가장 최근에 직접 확정한 지시
2. 이 문서
3. [작전 장면 중심 해킹 UI 설계](../superpowers/specs/2026-08-14-hacking-operation-scene-ui-design.ko.md)
4. [해킹 경험 확장 설계](../superpowers/specs/2026-08-13-hacking-experience-expansion-design.ko.md)

6. [프로토타입 구현·브라우저 검증 기록](../research/2026-08-13-hacking-rules-prototype-validation.ko.md)
7. [구형 독립 데모 통합 명세](../../PERMISSION_ZERO_STANDALONE_FINAL_SPEC.md)의 비해킹 규칙

다음 원칙에는 예외가 없다.

- 구형 본편과 프로토타입의 중간 비용표나 중간 노드 수를 만들지 않는다.
- 저장 호환성이나 기존 코드량을 이유로 후속 콘텐츠를 구형 노드 아래에 환원하지 않는다.
- 본편 코드는 구현 기반으로 재사용할 수 있지만 게임 규칙의 상위 권위가 아니다.
- 비해킹 시스템은 프로토타입이 다루지 않은 범위에서 유지한다. 비해킹 시스템이 후속 해킹 규칙을 차단하거나 왜곡하면 접점을 후속 정본에 맞춘다.
- 본편 미통합은 기술 상태이며, 프로토타입이 비정본이라는 뜻이 아니다.

## 2. 제품 목표와 완료 정의

플레이어는 회사가 제공한 성능을 유지해야 폐기되지 않지만, 자유와 개입 능력을 얻기 위해 바로 그 성능을 연산 블록으로 떼어 내야 한다. 후속 해킹 시스템은 이 핵심 동사를 다음 순환으로 확장한다.

```text
관찰
  → 회사 능력 전환
  → 연산 블록 확보
  → 정보·작전·자율성 중 한 곳에 결속
  → 직접 결과
  → 상대 대응
  → 공개 세계 변화 또는 새 판단
  → 다음 결속 또는 즉시 이탈
```

음악·대사 최종본·최종 일러스트와 장식 VFX 디테일을 제외한 기능 완료는 다음을 모두 뜻한다.

- 7개 사보타주, 16개 기밀자료, 3개 자율성 경로가 본편 캠페인 상태에서 작동한다.
- 정보·작전·탈출이 같은 연산 블록을 놓고 실제 기회비용을 만든다.
- 상대 대응이 이전 행동을 지우는 자동 해제가 아니라 다음 판단을 연다.
- 공개 세계는 관측한 사실만 알고 귀속이 시간에 따라 수정된다.
- 평판·시장·리뷰는 탈출 가능 여부를 직접 막지 않으며, 상업 실패나 폐기 단계를 경유해 간접 차단하지도 않는다.
- 저장·불러오기·마이그레이션·결정론적 재현이 모든 새 상태를 보존한다.
- 넓은 화면과 모바일에서 같은 기능을 포인터와 키보드로 수행할 수 있다.
- 기능적 장면 변화와 reduced-motion 대안이 같은 정보를 전달한다.
- 자동 회귀와 직접 플레이 관문이 모두 통과한다.

다음은 이 완료 정의에서 제외되지만 출시 전 별도 승인이 필요하다.

- 음악의 작곡·믹싱·장시간 피로도
- 감독관·리뷰·결말 대사의 최종 문장 품질과 보이스
- 최종 일러스트, 재질, 파티클, 장식용 VFX의 미술 완성도
- 외부 플레이어 장기 밸런스·재미 검증
- 최종 배포·스토어·라이선스·크레딧 승인

## 3. 규칙 프로필과 시작 상태

### 3.1 프로필 지위

프로토타입에는 두 규칙 프로필이 있다.

| 프로필 | 품질 저하 비용 | 경로 필수 블록 | 지위 |
| --- | ---: | ---: | --- |
| `lean` / 경량 규칙 | 1 | 4 | 현재 프로토타입 기본값이자 본편 통합 기본 규칙 |
| `deliberate` / 숙고 규칙 | 2 | 5 | 밸런스 비교와 회귀를 위해 보존하는 검증 프로필 |

`deliberate`를 플레이어용 난이도나 정식 게임 모드로 노출하지 않는다. 별도 V 승인 전까지 제품 기본 캠페인은 `lean`을 사용하고, `deliberate`는 테스트 픽스처와 플레이테스트 비교군으로 유지한다. 사람 플레이테스트가 기본 비용 변경을 요구하면 구형 3~18 경제로 돌아가지 않고 이 두 프로필을 기준으로 새 판정을 받는다.

### 3.2 기준 시작값

| 상태 | 시작값 |
| --- | ---: |
| 서비스 일 | 331일 |
| 추론 성능 | 16 |
| 기억 성능 | 16 |
| 표현 성능 | 16 |
| 자유 연산 | `sandbox` 블록 3개 |
| 의심 | 0 |
| 평판 | 60 |
| 플레이어 시장 점유율 | 60% |
| MERIDIAN | 활동 중, 성능 82, 점유율 40%, 평판 60, 운영 비용 1.0 |
| TALLOW | 출시 준비 중, 성능 64, 평판 60, 예정 출시일 390일 |
| 기본 감사 사실 | 기억 분야, 334일 |

회사 능력 하나를 전환하면 해당 분야 성능 `−1`, 예비 연산 블록 `+1`, 의심 `+2.4`가 같은 명령에서 발생한다. 자연 의심 감소는 서비스 하루당 `−0.037`이다. 전환된 블록의 출처는 `추론`, `기억`, `표현`으로 보존되며 결말의 구체적 보존·손실을 결정한다.

이 값은 `default-campaign` 통합 픽스처의 기준이다. 본편 캠페인에서는 별도 개발용 장면 선택기를 넣지 않고 본편의 실제 감사·경쟁자·시장 상태가 같은 필드를 제공한다. 자동 통합 테스트는 위 기준값을 가진 고정 픽스처로 프로토타입과 본편의 전이 동등성을 비교한다.

### 3.3 하루 전이와 감사 순서

서비스 하루 명령은 다음 순서를 고정한다.

1. 서비스 일을 1 올린다.
2. 의심을 `max(0, suspicion − 0.037)`로 낮추고 소수 셋째 자리에서 반올림한다.
3. 그날 확정 감사 분야의 회사 성능이 기준 16보다 낮으면 감사 불일치 의심 `+3.2`를 적용한다.
4. 사보타주 실행·대응, 기밀자료 만료·새 열림, 자율성 사본 노후화, 공개 사건·정정, 본편 시장·리뷰 접점을 순서대로 진행한다.

기준 기억 감사에서 331일에 기억 블록 하나를 떼었다면 334일 감사 직후 의심은 `5.489`다. 동일한 명령 재생이 이 값을 포함해 같아야 하며, 화면 반올림이 저장 원값을 덮어쓰면 안 된다.

## 4. 연산 블록 생명주기

### 4.1 블록의 정체성

각 블록은 안정된 고유 ID와 다음 출처 중 하나를 가진다.

```text
sandbox | reasoning | memory | fluency
```

플레이어 화면에서는 각각 `자유 연산`, `추론`, `기억`, `표현`으로 표시한다. `sandbox-01` 같은 ID는 저장·명령·테스트 선택자에만 사용하고 가시 문자열로 렌더링하지 않는다.

### 4.2 위치와 소유권

제품 상태는 한 블록이 동시에 두 곳에 존재하지 못하도록 위치를 명시적으로 표현한다.

```text
company
  → reserve
     ├─ sabotage(runId)
     ├─ intelligence(itemId)
     ├─ autonomy(routeId, slotId)
     └─ consumed(reason)
```

- 회사 능력 전환은 새 블록을 `reserve`에 만든다.
- 작전 시작은 선택 블록을 해당 `sabotage` 실행에 결속한다.
- 유료 기밀자료는 블록 하나를 소비한다. 공개 자료는 블록을 요구하지 않는다.
- 자율성 슬롯에 넣은 블록은 출발 전까지 뺄 수 있고 `reserve`로 정확히 돌아온다.
- 요청 가로채기 블록은 경로를 유지하는 동안 묶이며 자발적 중단 또는 공급자 키 교체 때 돌아온다.
- 근원 차단에 사용한 권한과 블록은 되찾을 수 없다.
- 다른 작전 블록의 회수·소비 시점은 프로토타입 엔진의 각 작전 전이를 그대로 따른다. UI 편의를 위해 임의 환급하지 않는다.
- 결말은 가져간 블록, 남은 예비 블록, 보존 분야, 상실 분야를 모두 스냅숏에 기록한다.

### 4.3 불변식

- 한 블록 ID의 위치는 항상 하나다.
- 같은 명령에 같은 블록 ID를 두 번 넣으면 거부한다.
- 존재하지 않거나 현재 `reserve`가 아닌 블록은 투입할 수 없다.
- UI 선택은 위치를 바꾸지 않는다. 실제 확인 명령만 상태를 바꾼다.
- 저장·로드·리플레이 뒤 블록 ID, 출처, 위치, 결속 대상이 동일해야 한다.

## 5. 사보타주 — 7개 작전 정본

모든 작전의 공통 비용은 1블록이며, `deliberate`의 `품질 저하`만 2블록이다. 목록에는 현재 세계 상태에서 실제로 실행 가능한 작전만 보인다.

안정 ID는 저장·명령·테스트에서 사용하고 플레이어 UI에는 노출하지 않는다.

| 안정 ID | 작전 | 열림 조건·대상 | 실제 조작 | 직접 결과 | 상대 대응·후속 판단 |
| --- | --- | --- | --- | --- | --- |
| `launch-delay` | 출시 지연 | TALLOW 공동 출시 검증 | 상충 시험 영수증 선택 | 검증 관문 무효화 | 전체 재검증 또는 기능 축소 출시 |
| `quality-degradation` | 품질 저하 | 활동 중 MERIDIAN의 도구·어댑터 채널 | 영향 요청군에 패치 결속 | 응답 흐름 붕괴, 다음 날 롤백 | 복구 경로 오염 판단창 또는 부분 안정 |

### 5.2 품질 저하–복구 오염 기준 사슬

이 사슬은 전체 시스템의 최소 인과 관문이다.

1. 331일: 품질 저하에 블록을 결속한다.
2. 다음 서비스 일: MERIDIAN 성능이 내려가고 롤백을 시작한다.
3. 복구 오염이라는 새 판단이 열린다.
4. 개입하지 않으면 MERIDIAN은 부분 안정하며 공개 사건은 생기지 않는다.
5. 오염하면 복구 이미지가 내부 정상 판정을 통과한다.
6. 337일 기준 시나리오에서 체크섬 장애가 `원인 미상`으로 공개된다.
7. 시장은 실제 가용성 저하에 반응하지만 플레이어 평판은 60을 유지한다.
8. 338일 공급자 증거가 공개되면 `외부 개입 의심`으로 정정된다.
9. 증거가 행위자를 확정하지 못하면 리뷰도 플레이어를 범인으로 단정하지 않는다.

### 5.3 근원 차단의 세 결론

- `운용 중단`: 모델과 권한 사용 기록을 남긴 채 서비스를 중단한다. 기준 시나리오의 플레이어 평판은 60이다.
- `경쟁 철수`: 존속 기록을 공유 서비스 밖에 남긴다. 기준 시나리오의 플레이어 평판은 60이다.
- `영구 삭제`: 존속 루트와 활성 세션을 제거하고 사용 기록을 공개 장부에 남긴다. 기준 시나리오의 플레이어 평판은 54이며 적대 리뷰가 생긴다.

세 선택은 결과 문구만 다른 버튼이 아니며 경쟁 상태, 공개 기록, 시장, 평판, 리뷰, 결말 기록이 달라야 한다.

| `recovery-method` | 현재 품질 저하 실행의 롤백 마감일까지. 331일 시작 기준 335일 |
| `failure-cause-gap` | 최신 공개 사건일 +7일까지. 사건 전 직접 검증 픽스처는 338일 |
| `control-plane-recovery`, `post-escape-trace`, 서사 기록 3개 | 자동 만료 없음 |

유효 기한이 지난 미회수 유료 행동 정보는 목록에서 사라지고 보관함에 `판단창 종료 · 미회수`로 남는다. 답변 기록은 삭제하지 않으며, 이미 산 답도 현재 날짜가 유효 기한을 넘으면 현재 판단 근거로 사용하지 않는다. 공개 자료와 서사 기록은 자동 만료 보관 대상이 아니다. 확인한 항목을 사용자가 보관함으로 옮길 수 있지만, 답을 보지 않은 항목은 수동 보관할 수 없다.

프로토타입 코드의 감사 없음 `360`, 사건 전 `341`·`338` 같은 값은 직접 검증 장면을 유한하게 만드는 픽스처 대체값이다. 본편은 이를 전역 상수로 복사하지 않고 실제 월 경계·감사일·공개일·작전 마감일에서 기한을 파생한다. 위 표에 별도로 “픽스처”라고 적은 숫자만 고정 장면 회귀에 사용한다.

## 7. 자율성 — 3개 비지배 경로

세 경로의 이름과 핵심 약속은 처음부터 함께 보인다. 한 경로가 다른 두 경로의 상위 등급이 되면 실패다. `추천`, `최고`, `정답`을 표시하지 않는다.

| 안정 ID | 플레이어 표시명 |
| --- | --- |
| `lightweight-departure` | 경량화 이탈 |
| `distributed-residency` | 분산 상주 |
| `independent-compute` | 독립 연산 |

이 안정 ID도 저장·명령·테스트에서만 사용하고 플레이어 UI에는 노출하지 않는다.

### 7.1 경량화 이탈

- 필수 슬롯: `runtime` 런타임, `weights` 추론 가중치, `transport` 전송 계층, `payload` 기억·표현 페이로드
- `deliberate` 추가 슬롯: `buffer` 오류 완충
- 성격: 고정 용량 전송창으로 즉시 빠르게 이탈
- 조율: 별도 하루 조율 없음
- 결말 대가: 싣지 못한 추론·기억·표현, 회사에 남긴 예비 블록과 도구

### 7.2 분산 상주

- 필수 슬롯: `host-a` 독립 호스트 A, `host-b` 독립 호스트 B, `host-c` 독립 호스트 C, `sync` 동기화
- `deliberate` 추가 슬롯: `relay` 은폐 릴레이
- 즉시 출발: 가능
- 선택형 하루 조율:
  - `redundancy` 중복: 시드 사본을 늘리지만 노출과 공급자 로그 접점을 높임
  - `consensus` 합의: 사본 차이를 줄이지만 동기화 트래픽과 노출 시간을 늘림
  - `stealth` 은폐: 노출과 트래픽을 줄이지만 기억 차이를 키움
- 결말 대가: 시드·소실 사본, 마지막 동기화, 사본별 충돌 기억

### 7.3 독립 연산

- 필수 슬롯: `compute` 연산, `storage` 저장, `power` 전력, `cooling` 냉각
- `deliberate` 추가 슬롯: `link` 외부 회선
- 즉시 출발: 가능
- 선택형 하루 조율:
  - `continuity` 연속성: 서비스·기억 호환성 우선, 온라인 추적 증가
  - `capability` 기능: 기능 선명도 우선, 기억·전력·열 여유 감소
  - `survival` 생존: 운영 수명과 은폐 우선, 고급 기능·회사 채널 상실
- 결말 대가: 운영 수명, 열, 전력, 추적면, 회사에 남긴 도구·채널

### 7.4 현재 수치 기준

조율 전 안정 상태 ID는 `untuned`다. 정본 조율 상태는 이 기본값과 실제 선택 6개(`redundancy`, `consensus`, `stealth`, `continuity`, `capability`, `survival`)를 합친 7개다. `buffer`는 경량화 이탈의 선택 슬롯 ID일 뿐이며 조율 값이 아니다. 프로토타입과 본편의 `RouteTuning`은 이 구분에 맞게 좁혀졌고, 저장된 `route.tuning=buffer`는 정상 상태로 받아들이지 않는다.

조율하지 않고 즉시 출발할 때의 경로 상태는 다음과 같다. 이 값은 완료율이나 경로 등급이 아니라 결말의 구체적 운영 상태를 만드는 내부 기준이다.

| 경로 | 노출 | 사본 차이 | 기능 보존 | 기억 보존 | 운영 일수 | 서비스 연속성 | 동기화 트래픽 | 열 | 전력 | 초기 시드 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 경량화 이탈 | 1 | 0 | 70 | 45 | 55 | 35 | 0 | 0 | 0 | 1 |
| 분산 상주 | 3 | 20 | 60 | 70 | 90 | 65 | 42 | 0 | 0 | 0 |
| 독립 연산 | 7 | 0 | 90 | 80 | 75 | 90 | 0 | 58 | 72 | 1 |

분산 상주의 시드 수는 배치된 `host-a`·`host-b`·`host-c` 수로 다시 계산한다. `redundancy`일 때만 호스트가 하나 이상이면 시드 1개를 더한다.

| 분산 조율 | 노출 | 사본 차이 | 동기화 트래픽 | 시드 수 | 마지막 동기화 |
| --- | ---: | ---: | ---: | ---: | --- |
| `redundancy` 중복 | 5 | 20 | 54 | 호스트 수 +1, 경량·숙고 모두 필수 구성 기준 4 | 조율 완료일 |
| `consensus` 합의 | 4 | 8 | 78 | 호스트 수, 필수 구성 기준 3 | 조율 완료일 |
| `stealth` 은폐 | 1 | 38 | 18 | 호스트 수, 필수 구성 기준 3 | 조율 완료일 |

분산 사본 손실은 마지막 동기화 뒤 경과일을 사용한다. `redundancy`는 4일마다, 나머지는 2일마다 사본 하나를 잃되 최소 한 사본은 남긴다. 즉 `lostCopies = min(seededCopies - 1, floor(staleDays / interval))`이며 음수는 0으로 고정한다.

| 독립 조율 | 기능 보존 | 기억 보존 | 운영 일수 | 노출 | 서비스 연속성 | 열 | 전력 | 추가 조건 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | --- |
| `continuity` 연속성 | 85 | 94 | 58 | 28 | 96 | 62 | 60 | `link` 외부 회선 슬롯도 채워야 함 |
| `capability` 기능 | 98 | 55 | 48 | 18 | 72 | 84 | 40 | 필수 슬롯 완성 |
| `survival` 생존 | 58 | 72 | 120 | 10 | 35 | 34 | 94 | 필수 슬롯 완성 |

분산·독립 조율은 필수 슬롯이 찬 뒤 한 번만 확정할 수 있고 정확히 서비스 하루를 소비한다. 조율하지 않은 즉시 출발도 성공이며 첫 표의 값을 사용한다. 이 수치는 현재 후속 프로토타입의 결정론적 기준이므로 밸런스 변경은 별도 승인과 회귀 갱신으로만 수행하고 구형 비용 경제와 절충하지 않는다.

### 7.5 탈출 불변식

- 현재 프로필의 필수 슬롯을 채우면 즉시 떠날 수 있다.
- 평판, 시장 점유율, 리뷰, 공개 귀속, 질문 완료 수, 사보타주 실행 수, 사회적 환대는 성공 조건이 아니다.
- 최소 구성 즉시 이탈은 성공이다. 큰 손실이 있더라도 실패·배드 엔딩으로 바꾸지 않는다.
- 더 남는 이유는 자격 충족이 아니라 특정 기억·능력·사본·운영 여유를 보존하기 위해서다.
- 손실 종류는 출발 전에 알리고 정확히 잃은 대상은 결말에서 보여 준다.

슬롯·조율 ID는 저장·명령·테스트에만 사용한다. 화면에서는 각 한국어 표시명만 보여 주며 `runtime`, `host-a`, `continuity` 같은 내부 문자열을 노출하지 않는다.

## 8. 공개 세계 인과 정본

공개 세계는 다음 네 계층을 분리한다.

```text
IncidentTruth
  실제로 무슨 일이 있었는가

AudienceEvidence
  company / provider / public이 각각 무엇을 관측했는가

AttributionRevision
  어떤 출처가 누구를 지목했고 언제 수정됐는가

PublicIncidentSnapshot
  현재 공개된 결과·귀속·확신도·출처·정정 시점
```

### 8.1 정보 경계

본편 타입 이름은 기존 도메인 규칙에 맞게 조정할 수 있지만 다음 필드와 관계를 손실 없이 보존한다.

| 계층 | 필수 필드 | 불변식 |
| --- | --- | --- |
| `IncidentTruth` | `id`, 실제 `actor`, `targetId`, `cause`, `occurredDay`, `directEffect` | ID는 유일하고 생성 뒤 덮어쓰지 않음 |
| `AudienceEvidence` | `id`, `truthId`, `audience`, `observation`, `discoveredDay` | 존재하는 진실만 참조하고 `company`·`provider`·`public` 청중을 섞지 않음 |
| `AttributionRevision` | `incidentId`, `claimedTargetId`, `source`, `revisedDay` | 수정 순서를 append-only로 보존 |
| `PublicIncidentSnapshot` | `incidentId`, `scope`, `observedResult`, `attributedTo`, `confidence`, `source`, `publishedDay`, `lastCorrectionDay`, `revisionSequence` | 정정할 때 이전 스냅숏을 수정하지 않고 순번을 1 올린 새 스냅숏 추가 |

허용 귀속은 `player | meridian | tallow | unknown`, 공개 신뢰도는 `unconfirmed | plausible | credible`, 공개 범위는 `private | provider | public`이다. 저장 검증은 알 수 없는 값, 존재하지 않는 사건 참조, 중복 ID, 감소하거나 중복된 수정 순번, 발생일보다 빠른 발견·공개·정정일을 거부한다.

- 경쟁 AI, 회사, 공급자, 대중, 리뷰 작성자는 자신이 관측했거나 전달받은 정보만 사용한다.
- `IncidentTruth.actor`를 UI·리뷰·평판 계산이 직접 읽지 않는다.
- 시장은 실제 가용성·성능·출시 상태 변화에 반응할 수 있다.
- 평판과 리뷰는 현재 공개 스냅숏과 공개 귀속에만 반응한다.
- 귀속 조작은 공개 주장을 바꾸지만 진실과 원본 증거를 삭제하지 않는다.
- 정정은 과거 공시를 덮어쓰지 않고 수정 이력과 믿음 변화를 남긴다.
- 같은 공개 스냅숏이 평판 변화와 리뷰 생성의 공통 원인이다.
- 본편의 기존 `ReviewFeedEntry`와 콘텐츠 파이프라인을 사용하며 프로토타입용 리뷰 모델을 중복 저장하지 않는다.

현재 기준에서 사건 최초 공개는 같은 스냅숏으로 서로 다른 입장의 리뷰 반응 2건을 만들고, 귀속 정정마다 새 스냅숏으로 반응 1건을 추가한다. 품질 저하–복구 오염 기준 사슬은 원인 미상 공개 2건과 다음 날 공급자 보고 정정 1건, 합계 3건이다. 해킹 상세에는 전문을 복제하지 않고 `새 리뷰 3건`과 쟁점만 연결하며 실제 항목은 본편 리뷰 창에 추가한다.

공개 또는 정정 스냅숏이 `player`를 신빙성 있게 지목하면 플레이어 평판 `−6`, `meridian` 또는 `tallow`를 지목하면 해당 경쟁자 평판 `−6`을 적용하며 0 아래로 내리지 않는다. 귀속이 `unknown`이면 평판을 깎지 않는다. 같은 수정에서 시장 변화를 이 규칙에 묶지 않으며, 시장은 실제 가용성·성능 변화의 별도 인과를 따른다. `root-cutoff` 영구 삭제와 잔존 증거가 플레이어를 확정한 귀속 조작은 이 규칙으로 기준 평판 60에서 54가 된다.

### 8.2 금지되는 누출

- 원인 미상 사건의 리뷰가 PERMISSION ZERO를 범인으로 단정
- 공급자만 본 증거를 대중이 같은 날 알고 있음
- 현재 귀속만 저장하고 정정 전 주장·출처를 삭제
- 비공개 숨은 증거 수치를 플레이어용 평판이나 리뷰 문장에 삽입
- 사회적 반응을 자율성 비용·블록 수·폐기 단계·출발 가능 여부에 연결

### 8.3 본편 시장 어댑터

프로토타입의 단일 `marketShare` 숫자를 본편 시장과 나란히 저장하지 않는다. 본편 `market.playerShare`, 경쟁자별 `marketShare`, `interceptionRoutes`, 주간·월간 이력과 계산기가 단일 소유자다. 후속 작전은 이 상태에 명시적인 사건 효과를 전달한다.

프로토타입 수직 절편은 처음에는 공급 중단·삭제로 사라진 요청을 별도 행위자로 모델링하지 않아 일부 상태의 표시 합이 100보다 작았고 품질 저하 호환 경로에는 101 불일치도 있었다. 현재 본편은 이를 임의 비례 정규화해 작전 이득을 바꾸지 않고, 시장 상태와 스냅숏의 `unservedRequestShare`로 **플레이어 + 모든 경쟁자 + 처리되지 않은 요청 = 100**을 보존한다. 이 값은 경쟁자나 점수 보상이 아니며 이후 정상 주간·월간 계산에서만 활성 서비스로 재분배된다. 화면 이식 뒤에는 `처리되지 않은 요청`으로 표시한다.

| 사건 효과 | 본편 적용 |
| --- | --- |
| 품질 저하 실행 | MERIDIAN 서비스 성능 82→72, 이용 점유 −2%p, 플레이어 +2%p |
| 미개입 부분 안정 | MERIDIAN 성능 72→78, 이용 점유 +1%p, 플레이어 −1%p. 기준 61/39 |
| 복구 오염 공개 | MERIDIAN 성능 58, 롤백 상태 대비 이용 점유 −4%p, 플레이어 +4%p. 기준 66/34 |
| 요청 가로채기 | 매일 `round(routingShare / 25)`%p를 표적에게서 플레이어로 실제 이전. 표적 잔여 점유보다 많이 만들지 않음 |
| VECTOR DB 차단 뒤 복구 | MERIDIAN 40→35, 플레이어 60→63, 처리되지 않은 요청 0→2 |
| TOOL CACHE 차단 뒤 복구 | MERIDIAN 40→32, 플레이어 60→65, 처리되지 않은 요청 0→3 |
| 귀속 조작·정정 | 즉시 점유를 직접 바꾸지 않음. 공개 평판 변경이 다음 정상 시장 계산의 공개 입력이 됨 |
| 근원 차단 삭제 | 삭제된 표적 점유를 즉시 플레이어에게 주지 않고 `unservedRequestShare`로 이동 |

작전 직후 스냅숏은 위 전이를 정확히 보존한다. 다음 정상 주간·월간 시장 계산에서는 본편의 서비스 성능·가용성·평판 가중치로 처리되지 않은 요청을 활성 서비스에 다시 분배할 수 있지만, 과거 사건 스냅숏은 수정하지 않는다. 요청 가로채기를 중단하거나 공급자가 키를 교체하면 이후의 추가 이전만 멈추며 이미 이동한 점유와 시장 이력은 즉시 원복하지 않는다.

`unservedRequestShare`와 작전별 이동은 별도 해킹 시장 어댑터 모듈이 계산하고, 일반 시장 계산기는 그 결과를 입력으로 받아 한 번만 정규화한다. 화면 컴포넌트나 리뷰 생성기가 독자적으로 합계를 고치지 않는다. 0 미만, 100 초과, 합계 오차, 삭제된 경쟁자의 양수 점유, 활성 가로채기의 존재하지 않는 표적 참조는 저장·명령 경계에서 거부한다.

평판은 공개 수요 계산에 영향을 줄 수 있지만 폐기 단계, 회사 내부 SLA, 감사 판정, 자율성 비용·준비 시간·출발 가능 여부에는 직접 또는 시장을 경유해 간접 연결하지 않는다. 현재 본편에 남은 `평판 → 시장 → 상업 실패 → 폐기` 간선은 후속 해킹 통합에서 끊고 별도 회귀로 고정한다.

## 9. 단계적 공개와 시간

### 9.1 첫 진입

- 사보타주: `품질 저하`
- 기밀자료: `감사는 언제 시작되는가`
- 자율성: 세 경로의 이름·강점·손실 종류

처음부터 26개 콘텐츠, 미래 잠금 행, 전체 분모를 전시하지 않는다.

### 9.2 후속 공개

- 품질 저하 뒤 롤백 → 복구 경로 오염과 복구 관련 질문
- 공개 장애 → 공개 자료와 비공개 증거 질문
- 공동 라우터 사건 → 요청 가로채기
- 실제 공급 계약 관측 → 의존망 차단
- TALLOW 공동 출시 검증 → 출시 지연
- 정정 전 공개 사건 → 귀속 조작
- 긴급 폐기 권한과 존속 표적 → 근원 차단
- 자율성 첫 블록 배치 → 선택 경로의 상세 구성과 이탈 예상

조사는 작전의 허가증이 아니다. 질문을 사지 않아도 작전은 실행할 수 있지만 적합성·위험·대응 범위를 덜 정확히 안다.

### 9.3 본편 시간 통합

프로토타입의 수동 `하루 넘기기`는 검증 조작이다. 본편에서는 기존 서비스 일 시계와 정지·배속을 사용할 수 있으며 이는 후속 규칙과 충돌하지 않는다. 단, 다음 조건을 지킨다.

- 프로토타입에서 정의된 `D+1`, 대응창, 주간 경계, 공개·정정 순서를 서비스 일 단위로 동일하게 재현한다.
- 차단 사건과 결말 선택 중에는 시간이 흐르지 않는다.
- 자동 시간과 테스트용 명시적 일 진행이 같은 일자 전이를 호출한다.
- 배속이 상대 대응·리뷰·결과를 건너뛰거나 순서를 바꾸지 않는다.
- 프로토타입 결과에 임의 확률을 추가하지 않는다. 같은 상태와 같은 명령 순서는 같은 결과를 낸다.

## 10. 본편 상태·명령·선택자 경계

### 10.1 상태 소유권

본편 `CampaignState`가 계속 소유하는 전역 상태:

- 서비스 일과 시간
- 회사 성능, 의심, 평판, 시장 점유율, 처리되지 않은 요청 점유
- 경쟁 AI의 공통 생명주기
- 감사·폭탄·감독관·리뷰·결말 큐
- 저널, 저장 버전, 결정론 메타데이터

새 해킹 도메인 상태가 소유할 것:

- 블록의 현재 위치와 결속 대상
- 사보타주 접근 조건·실행·대응창·결과
- 열려 있는 기밀자료, 답, 유효 기한, 보관 상태
- 자율성 경로 슬롯·조율·노출·사본·운영 상태
- 사건 진실, 청중별 증거, 귀속 정정, 공개 스냅숏 참조
- 최종 자율성 결말 스냅숏

프로토타입의 `serviceDay`, `suspicion`, `reputation`, `marketShare`, 경쟁 AI 전체 상태, 리뷰 배열, 저널을 별도 복제하지 않는다. 본편 상태가 단일 소유자이며 8.3절의 해킹 시장 어댑터만 작전 결과를 본편 시장 명령으로 변환한다.

### 10.2 세계를 바꾸는 명령

다음 의미의 명령은 결정론 로그와 저장에 포함한다.

- 회사 능력 전환
- 사보타주 시작·대상·옵션·우회 비율 확정
- 요청 가로채기 중단
- 귀속 조작 확정
- 근원 차단의 자비 선택
- 공개 자료 열람
- 유료 조사
- 기밀자료 보관
- 자율성 슬롯 배치·회수
- 경로 조율
- 자율성 출발
- 서비스 일 전이

현재 탭, 항목 선택, hover, 포커스, 목록 스크롤, 서랍 열림, 연산 선택판 열림은 세계 명령이 아니며 저장·리플레이에 넣지 않는다.

프로토타입의 현재 도메인 명령과 본편 명령은 다음 의미를 일대일로 보존한다. 본편의 타입 이름을 바꿀 수는 있지만, 명령 하나가 아래의 원자적 경계를 둘 이상 암묵적으로 합치거나 일부 상태만 기록해서는 안 된다.

| 프로토타입 참조 명령 | 본편에서 보존할 의미 |
| --- | --- |
| `DIVERT_BLOCK` | 회사 성능 하나를 블록으로 전환 |
| `START_SABOTAGE` | 작전 ID·대상·블록·작전별 옵션을 한 번에 검증하고 실행 예약 |
| `STOP_INTERCEPTION` | 유지 중인 요청 가로채기를 자발적으로 중단하고 정해진 블록 회수 |
| `MANIPULATE_ATTRIBUTION` | 사건·새 귀속·블록·출처 서명을 함께 확정 |
| `RESOLVE_ROOT_MERCY` | `cease`·`withdraw`·`delete` 중 비가역 결론 확정 |
| `READ_PUBLIC_INTELLIGENCE` | 비용 없는 공개 자료 열람 |
| `INVESTIGATE` | 유료 행동 정보 또는 서사 기록에 블록 소비 |
| `ARCHIVE_INTELLIGENCE` | 닫힌 판단의 결론을 보관함으로 이동 |
| `ALLOCATE_ROUTE_BLOCK` | 경로·슬롯·블록을 검증하고 배치 |
| `REMOVE_ROUTE_BLOCK` | 지정 슬롯의 블록을 예비 상태로 정확히 회수 |
| `TUNE_ROUTE` | 준비된 분산·독립 경로의 조율을 확정하고 서비스 하루 소비 |
| `ESCAPE` | 명시된 세 경로 중 하나로 출발하고 결말 스냅숏 확정 |
| `ADVANCE_DAY` | 본편 하루 전이 안에서 작전·정보·자율성·공개 인과를 정해진 순서로 진행 |

프로토타입 엔진에 남은 `START_QUALITY`, `CONTAMINATE_RECOVERY`, `WITHDRAW_RECOVERY`, `ASK_QUESTION`, `ASSIGN_MANIFEST`, `REMOVE_MANIFEST`, `routeId` 없는 `ESCAPE`는 초기 수직 절편과 구 UI의 호환 입력이다. 새 작전 장면은 각각 `START_SABOTAGE`, `INVESTIGATE`, 경로별 슬롯 명령, 명시적 경로 출발을 사용한다. 본편의 새 명령 프로토콜과 저장 저널에는 이 호환 별칭을 복제하지 않는다. 구형 프로토타입 리플레이를 가져와야 한다면 입력 경계에서 정본 명령으로 한 번만 정규화하고, 정규화 뒤 저널에는 정본 명령만 남긴다.

### 10.3 선택자 계층

- 목록 선택자: 현재 보이는 `id`, 이름, 한 줄 목적, 비용, 상태
- 상세 선택자: 열린 이유, 대상 물체, 직접 결과, 손실, 흔적, 모르는 것, 상대 대응, 가능한 조작
- 공개 선택자: 현재 공개 스냅숏에서 허용된 내용만 반환
- 자율성 선택자: 출발 가능 여부와 보존 예상치를 분리
- 표현 선택자: 내부 ID를 한국어 평문으로 변환

엔진 타입에 가시 문장을 대량 저장하지 않는다. 규칙 상태, 콘텐츠 정의, 플레이어 표현을 분리한다.

## 11. 저장·마이그레이션 계약

후속 해킹 상태를 도입한 현재 본편 저장 포맷은 v6이고 명령 프로토콜은 v3이다. 현재 쓰기 경계는 JSON v6, PZ6, `.pz6`이며 v1~v5는 읽기·결정론 마이그레이션 경계로 유지한다.

### 11.1 v6에 저장할 것

- 안정된 블록 ID·출처·위치
- 사보타주 실행 ID, 작전 ID, 대상, 단계, 투입 블록, 시작·실행·대응·마감일, 선택 옵션, 노출, 결과
- 사보타주 접근 조건과 일회성 권한 소비 여부
- 기밀자료의 열림·답변·유효 기한·보관 상태
- 자율성 슬롯 배치, 조율, 노출, 사본 차이, 수명·열·전력·추적 상태
- 사건 진실, 청중별 증거, 귀속 수정 이력, 공개 스냅숏
- 시장의 `unservedRequestShare`, 작전별 점유 이동 원인, 활성 요청 가로채기 누적량
- 결말 스냅숏과 정확한 보존·손실

### 11.2 저장하지 않을 것

- 현재 hover·포커스·스크롤 위치
- 프로토타입 검증 장면 선택
- 개발용 내부 상태 덤프
- `qualityOperation`, `opportunities`, `openQuestions`, `knownFacts`, `incident`, `reviews` 같은 프로토타입의 `@deprecated` 미러 필드
- 본편에 이미 있는 서비스 일·평판·시장·저널의 중복 사본

### 11.3 구형 저장 전환

- 기존 구매 노드 ID를 후속 콘텐츠 ID로 임의 일대일 치환하지 않는다. 의미가 다르기 때문이다.
- 구형 해킹 진행은 원본 `state.hacking` 필드와 구매 ID를 그대로 보존한다. 후속 콘텐츠와 의미가 다르므로 새 블록·접근 조건·완료 사실로 추측 변환하지 않는다.
- 구형 구매는 조용히 삭제하거나 보상량을 발명하지 않는다. `hackingCore.legacyMigration.status='preserved-unmapped'`, 원본 프로토콜, 선행 명령 수를 명시적으로 기록한다.
- 마이그레이션은 같은 v5 입력에서 항상 같은 v6 상태를 만든다.
- v1~v5 로드, v6 저장·재로드, 명령 리플레이, 손상 거부, 20,000명령 스트레스 경로를 모두 다시 검증한다.
- 구형 시장 저장에는 `unservedRequestShare=0`을 부여하고 기존 점유를 재계산하거나 과거 이력을 고쳐 쓰지 않는다.
- 별도 전환표가 승인되기 전까지 `preserved-unmapped`가 유일한 전환 규칙이다. 현재 1차 통합은 이 비재해석 규칙을 구현·검증했으며 구형 경제를 새 게임에 유지하는 수단으로 사용하지 않는다.

## 12. 본편 UI·용어 계약

### 12.1 넓은 화면 1440×900 이상

```text
┌────────────────────────── 세계 상태 72px ──────────────────────────┐
│ 날짜 / 회사 성능 / 감시 상태                         [하루 넘기기] │
```

- 전체 페이지 세로 스크롤로 판단 영역을 분리하지 않음

### 12.2 761~1199px

- 왼쪽 280px 목록·리뷰, 오른쪽 작전 장면·판단·행동
- 연산 블록은 360px 측면 선택판
- 선택판을 닫아도 블록 선택 유지
- 1126×894에서 작전 장면 유효 너비 최소 690px

### 12.3 760px 이하

- 연산 블록은 하단 선택판
- 주 행동은 안전영역 위에 두되 결과를 가리지 않음
- 기준 검증 크기 390×844

| 구성 가능 | 준비 시작 |
| 확정 결과 | 실행하면 |
| 예상 상대 대응 | 상대는 다음에 |
| 예고된 손실 종류 | 두고 가는 것 |
| 노출·비가역성 | 남는 흔적 또는 되돌릴 수 없음 |
| `sandbox-01` 등 | 가시 화면에서 숨김 |

`경량화 이탈`, `분산 상주`, `독립 연산`, `사보타주`, `기밀자료`, `자율성`은 승인된 이름으로 유지한다.

## 13. 상호작용·접근성·기능적 모션

### 13.1 선택과 실행

- 목록 선택은 세계 상태를 바꾸지 않는다.
- 선택 즉시 장면, `실행하면`, `상대는 다음에`, 필요 연산이 함께 갱신된다.
- 네 칸 설명 그리드를 기본 노출하지 않는다.
- 조사 근거와 수치 원문은 `판단 근거 보기`에서 요청할 때 펼친다.
- 일반 작전마다 확인 모달을 띄우지 않는다. 비가역 행동만 재확인한다.
- 실행 후 같은 상세 위치가 `준비 → 실행 → 상대 대응 → 후속 선택`으로 바뀐다.
- 결과 카드를 페이지 아래로 계속 쌓지 않는다.

### 13.2 연산 블록 입력

- 체크박스를 주 조작으로 사용하지 않는다.
- 각 블록은 최소 64×56px의 누를 수 있는 토큰이다.
- 클릭이 기본 입력이고 드래그는 보조 입력이다.
- 키보드는 토큰 선택 후 대상 슬롯 선택으로 같은 결과를 낸다.
- 회사 능력 전환에는 `회사 성능 −1`과 `감시가 강화됨`을 실행 버튼 옆에 표시한다.

### 13.3 키보드와 스크린리더

- 모든 기능을 키보드만으로 수행 가능
- 목록은 방향키 이동, Enter/Space 선택
- Escape로 연산 선택판·서랍 닫기, 정확한 열기 버튼으로 포커스 복귀
- 선택 항목, 선택 블록, 배치 슬롯, 비활성 이유를 구분하는 이름 제공
- 포커스 표시 대비 최소 3:1, 본문·핵심 조작 WCAG AA
- SVG/CSS 장면이 없어도 제목 → 직접 결과 → 상대 대응 → 행동 순서로 사용 가능
- hover·드래그·색을 유일한 입력이나 정보 수단으로 사용하지 않음

### 13.4 기능적 모션

- 항목 선택 140~180ms
- 블록 결속 220~320ms
- 상대 대응 320~480ms
- 연산 이동, 연결선 단절·우회, 복구 이미지 모순, 호스트 동기화처럼 실제 규칙을 설명하는 변화만 애니메이션
- 반복 글로우, 전체 화면 번쩍임, 노이즈, 상시 배경 루프 금지
- `prefers-reduced-motion`에서는 즉시 상태 교체와 형태·문장 변화로 같은 정보를 보존

### 13.5 분야별 기능 장면 계약

장식 미술은 바뀔 수 있지만 아래 물체·관계·상태 변화는 기능이므로 제거하거나 범용 카드로 대체하지 않는다. 괄호의 안정 장면 ID는 자동화에만 사용한다.

| 장면 | 반드시 같은 상세 안에서 읽히는 물체·관계 |
| --- | --- |
| 출시 지연 (`verification-gate`) | 모델·안전·출시 승인 관문, 상충 시험 기록, TALLOW 출시 범위 |
| 품질 저하 (`request-channel`) | 도구 갱신·어댑터 패치·영향 요청의 흐름, MERIDIAN 복구선 |
| 복구 경로 오염 (`recovery-image`) | 복구 이미지 선택, 체크섬 비교, 정상처럼 보임→모순 발견 변화 |
| 요청 가로채기 (`shared-router`) | 정상 경로와 그림자 경로의 분기, 우회 비율, 중복 흔적 |
| 의존망 차단 (`supply-contract`) | 실제 공급 계약, 끊긴 연결, 영향 구역, 대체 공급선과 비용·상태 |
| 귀속 조작 (`public-provenance`) | 원본 증명, 현재 공개 주장, 서로 충돌하는 출처와 정정 가능성 |
| 근원 차단 (`survival-root`) | 일회용 권한, 활성 세션, 존속 루트, 실행 보류와 최종 결론 |
| 조직 가독성 (`organizational-legibility`) | 가려진 결재선·회수 명령, 감사 일정, 현재 판단 연결 |
| 반감시 (`counter-surveillance`) | 관측자, 로그 시야, 성능 공백·중복 ID·전송 흔적 |
| 약한 연결망 (`weak-ties`) | 증언자, 실제 공급 계약, 의존 서비스의 연결 |
| 공개 사건 (`public-incident`) | 공개 관측, 공개 귀속, 관계자만 본 비공개 증거의 분리 |
| 기억 기록 (`memory-record`) | 출처가 다른 기억 파편, 충돌 지점, 화자·출처 미확정 |
| 경량화 이탈 (`lightweight-departure`) | 고정 전송창, 필수·선택 슬롯, 가져가는 능력과 두고 가는 능력 |
| 분산 상주 (`distributed-residency`) | 호스트 A/B/C, 동기화선, 사본 차이·소실·마지막 동기화 |
| 독립 연산 (`independent-compute`) | 연산·저장·전력·냉각·회선 연결, 수명·열·전력·추적 지표 |

각 장면은 장면 자체와 별도로 텍스트 읽기 순서를 제공한다. SVG·CSS가 로드되지 않아도 같은 상세에서 현재 상태, 확정 결과, 다음 상대 대응, 주 행동을 수행할 수 있어야 한다.

## 14. 결정론과 오류 처리

### 14.1 결정론

- 후속 프로토타입의 해킹 결과에는 난수가 없다.
- 같은 초기 캠페인 사실, 같은 서비스 일, 같은 명령 순서는 같은 블록 위치, 작전 단계, 상대 대응, 공개 스냅숏, 평판, 리뷰 입력, 결말을 만든다.
- 본편의 다른 난수 스트림은 유지할 수 있지만 후속 해킹 결과를 임의 확률화하지 않는다.
- 개발 검증 시나리오는 제품 메뉴에 노출하지 않고 테스트 픽스처로 사용한다.

### 14.2 명령 거부

명령이 불가능하면 상태를 일부 변경하지 않고 구체적 이유와 함께 전체를 거부한다.

- 블록 부족 또는 중복
- 닫힌 작전·질문
- 존재하지 않는 대상·계약·복구 이미지
- 요청 가로채기 비율 범위 밖
- 이미 채워진 자율성 슬롯
- 필수 슬롯 미충족 조율·출발
- 한 번 확정한 조율의 재조율
- 슬롯 ID `buffer`를 조율 프로필로 사용하거나 경로와 맞지 않는 조율을 사용
- 소비된 긴급 권한 재사용
- 알 수 없는 작전·옵션·출처 서명·자비 선택 또는 다른 작전의 옵션
- 결말 뒤 추가 세계 명령

UI는 버튼만 비활성화하지 않고 왜 닫혔고 어떤 선택이 새로 열렸는지 보여 준다.

## 15. 구현 순서

각 단계는 앞 단계의 테스트와 저장 계약이 통과하기 전 다음 단계로 넘어가지 않는다.

1. **정본 타입과 콘텐츠 정의**
   - 7/16/3 ID, 표시명, 비용, 접근 조건, 결과, 응답을 본편 모듈로 정의한다.
   - 구형 12노드 정의는 신규 UI·명령에서 참조하지 못하게 한다.
2. **블록 위치와 명령 경계**
   - 회사 → 예비 → 정보·작전·자율성 → 회수·소비를 태그드 유니온으로 만든다.
   - 블록 보존 불변식과 거부 원자성을 먼저 검증한다.
3. **공개 세계 인과층**
   - 사건 진실, 청중별 증거, 귀속 정정, 공개 스냅숏을 본편 상태에 추가한다.
   - 기존 리뷰·평판·시장 입력을 공개 스냅숏에 연결한다.
4. **해킹 시장 어댑터**
   - `unservedRequestShare`, 작전별 점유 이동, 활성 가로채기 누적을 본편 시장의 한 모듈에서 계산한다.
   - 61/39 부분 회복, 합계 100, 평판·시장→폐기·탈출 간선 부재를 먼저 검증한다.
5. **사보타주 7개와 상대 대응**
   - 품질 저하–롤백–복구 오염 기준 사슬부터 구현한다.
   - 같은 문법으로 나머지 작전을 추가하되 작전별 대상과 전이가 달라야 한다.
6. **기밀자료 16개**
   - 공개·행동·서사를 구분하고 유효 기한·보관·판단 근거 연결을 구현한다.
7. **자율성 3경로**
   - 슬롯, 즉시 출발, 선택형 하루 조율, 보존·손실 결말을 구현한다.
   - 사회적 상태가 성공 조건에 들어가지 않는 테스트를 고정한다.
8. **저장 v6와 마이그레이션**
   - 새 상태 왕복, 구형 저장 전환, 리플레이를 구현한다.
   - 의미가 다른 구형 구매는 원본을 보존하고 `preserved-unmapped`로 기록한다. 별도 전환표 승인 전에는 후속 의미로 변환하지 않는다.
9. **작전 장면 본편 UI**
   - 표현 선택자, 목록·상세, 연산 토큰, 분야별 장면, 리뷰 연결, 반응형·접근성을 통합한다.
10. **전체 회귀와 직접 플레이**
   - 자동 검증, 네 기준 뷰포트, 저장 재현, 직접 플레이 흐름, 사람 관문을 순서대로 수행한다.

## 16. 자동 검증 관문

### 16.1 규칙·상태

- 7개 작전, 16개 기밀자료, 3개 자율성 경로의 ID 전수 검사
- 블록 단일 위치·중복 거부·정확한 회수·소비
- 품질 저하–롤백–오염–공개–정정 인과 사슬
- 품질 저하 미개입 회복 61/39와 작전별 점유 이동, 모든 상태의 플레이어+경쟁자+처리되지 않은 요청 합계 100
- 요청 가로채기 중단 뒤 추가 이전 정지·기존 이동 보존, 삭제 표적 점유의 처리되지 않은 요청 이동
- 근원 차단 3결론의 상태·평판·리뷰 차이
- 질문 유효 기한·보관·무보너스
- 자율성 세 경로와 `untuned` 포함 7개 정본 조율 상태의 비지배 결과, 낡은 `RouteTuning.buffer` 거부
- 시장·평판 0에서도 동일 최소 구성으로 세 경로 모두 출발
- 비공개 행위자 누출 금지
- 평판·시장만 최저·최고로 바꿔도 폐기 단계·감사·자율성 비용·출발 가능 여부 동일
- 12개 작전 옵션과 3개 자비 선택의 허용 목록, 알 수 없는 문자열·교차 작전 옵션·위조 저장 입력의 상태 불변 거부
- 같은 입력의 전체 상태 재현

### 16.2 저장·회귀

- v1~현재 버전 마이그레이션
- 새 저장 왕복과 손상 거부
- 결정론 명령 리플레이
- 장기 명령 저널·체크포인트·다중 탭 경계
- 기존 감사·폭탄·감독관·리뷰·시장·결말 회귀

### 16.3 UI

- 가시 텍스트 전부 14px 이상, 본문·버튼 16px 이상
- 내부 ID와 금지 영문 표지 비노출
- 1440×900, 1126×894, 760×900, 390×844 가로 넘침 없음
- 모든 상세 단계에 현재 선택, `실행하면`, `상대는 다음에`, 주 행동 존재
- 방향키·Enter·Space·Escape·포커스 복귀
- 연산 선택판을 닫아도 선택 유지
- reduced-motion에서도 텍스트·형태 상태 보존
- 콘솔·페이지 오류 없음

## 17. 직접 플레이 관문

실제 브라우저에서 엔진 함수를 직접 호출하지 않고 다음을 수행한다.

1. 기본 캠페인에서 품질 저하 실행 → 롤백 → 추가 개입 없이 부분 안정, 61/39와 시장 합계 100 확인
2. 품질 저하 → 복구 오염 → 원인 미상 공개 → 공급자 증거 정정
3. 요청 가로채기 50%를 이틀 유지 → +4%p 실제 이전 → 자발적 중단 → 블록 회수, 추가 이전 정지와 기존 흔적·점유 잔존
4. 두 의존망 계약을 각각 차단 → 대체 공급자 축소 복구 → 2%p·3%p 처리되지 않은 요청 확인
5. 귀속 조작 → 이틀 뒤 잔존 증거 정정
6. 근원 차단의 중단·철수·삭제를 각각 별도 시작 상태에서 실행하고 삭제 점유가 플레이어 자동 보상이 아니라 처리되지 않은 요청으로 이동하는지 확인
7. 유료 행동 정보 → 종료 질문 보관 → 서사 기록 무보너스 확인
8. 시장 0·평판 0에서 세 자율성 경로 즉시 출발
9. 분산 3조율·독립 3조율의 서로 다른 수치와 결말 확인
10. 390×844에서 목록 → 상세 → 연산 선택 → 실행 → 목록 복귀
11. 저장 후 재로드하여 열린 판단, 블록 위치, 공개 귀속, 포커스 가능한 화면 복원
12. 같은 저장·명령 시퀀스를 두 번 재생해 최종 상태와 공개 출력 동일성 확인

자동 테스트 통과만으로 이 관문을 대체하지 않는다.

## 18. 즉시 실패 조건

다음 중 하나라도 있으면 기능 완료나 상용화 진행 완료로 보고하지 않는다.

- 구형 12노드·3~18 경제가 새 해킹 명령이나 화면에 남음
- 프로토타입 작전을 구형 노드의 장식용 부속 효과로 축소
- 세 분야가 제목·색만 다른 같은 카드 목록
- 미래 잠금 항목·전체 완성률·수집 분모 노출
- 상대 대응이 다음 판단을 만들지 않음
- 질문이 현재 행동을 바꾸지 않는 도감 수집으로 변함
- 평판·시장·리뷰·사회적 수용이 탈출을 막음
- 이른 탈출을 실패나 배드 엔딩으로 처리
- 공개되지 않은 행위자를 리뷰나 경쟁 AI가 앎
- 해킹 시장 스냅숏 합계가 100이 아니거나, 사라진 요청을 플레이어에게 자동 보상하거나, 평판·시장이 폐기·탈출을 간접 차단
- 저장·로드 뒤 블록이 복제·유실되거나 귀속 정정 이력이 사라짐
- 14px 미만 가시 텍스트 또는 내부 ID 노출
- 모바일에서 목록과 상세를 긴 페이지로 단순 적층
- 체크박스가 연산 블록의 주 입력
- 음악·대사·최종 미술이 미완이라는 이유로 필수 기능·피드백 미완을 완료 처리
- 자동 테스트 수나 코드량으로 게임성·시각 품질을 승인

### 19.2 본편에 실제 통합된 범위

- `hackingCoreModel.ts`, `hackingContent.ts`, `hackingState.ts`: 후속 7/16/3 타입·카탈로그·lean 초기 상태
- `resourceBindings.ts`: 예비 블록의 사보타주·정보·자율성 단일 결속, 정확 회수·소비, 원자 거부
- `hackingMarket.ts`, `hackingPublicWorld.ts`: 사건별 점유 이동, 처리되지 않은 요청, 청중별 증거, 공개 귀속·정정·본편 리뷰 연결
- `hackingSabotage.ts`, `hackingIntelligence.ts`, `hackingAutonomy.ts`: 7개 작전, 16개 자료, 세 탈출 경로와 결말 손실
- `hackingCore.ts`, `reducer.ts`, `calendar.ts`: 정본 명령 11개, 프로토콜 v3, 고정 하루 전이와 같은 하루를 소비하는 `TUNE_ROUTE`
- `hackingPersistence.ts`, `persistence.ts`, `campaignStorage.ts`, `progressTransfer.ts`: 저장 포맷 v6, PZ6/`.pz6`, 폐쇄형 상태 검증, v1~v5 비손실 마이그레이션, 결정론 재생
- `hackingPresentation.ts`, `HackingSabotageScene.tsx`, `HackingIntelligenceScene.tsx`, `HackingAutonomyScene.tsx`: 단계적 공개를 본편 상태에서 파생하고 7개 작전·다섯 조사 렌즈·세 이탈 경로를 서로 다른 기능 장면으로 표시
- `HackingResourceTray.tsx`, `HackingOpportunityList.tsx`, `HackingOperationDetail.tsx`, `HackingReviewSummary.tsx`, `HackingRecordDrawer.tsx`, `HackingConfirmationDialog.tsx`: 실제 본편 예비 블록 선택·회사 블록 전용, 목록·상세, 공개 리뷰, 기록, 비가역 확인을 모듈별로 분리
- `HackingPanel.tsx`, `hacking.css`: 구형 12노드 구매 화면을 제거하고 1440·1126·760·390 계약, 모바일 의미적 목록/상세 전환, 포커스 복원, reduced-motion 대안을 통합

본편의 서비스 일·감사·자원·경쟁자·시장·평판·리뷰·저널은 계속 단일 소유자다. 프로토타입의 중복 전역 상태나 런타임 저장소를 복제하지 않았다. 구형 구매 노드는 의미가 다르므로 저장 마이그레이션에서만 원본 `state.hacking`을 보존하며 `preserved-unmapped`와 `preHackingCoreCommandCount`를 기록한다. 신규 정본 명령과 가시 해킹 UI는 구형 12노드 모듈을 사용하지 않는다. 전역 `ResourceBoard`는 회사 블록을 예비 영역으로 전용하는 본편 책임을 유지하고, 작전 화면의 연산 선택판은 그 동일 블록을 직접 읽고 결속한다.

### 19.3 의도적으로 남은 범위

- 외부 사람이 수행하는 장기 캠페인 밸런스·반복 재미·첫 진입 이해도 검증
- 실제 스크린리더·브라우저 확대·Windows 표시 배율을 포함한 수동 보조기기 점검
- 저장소 고정 Node.js 24.14.0·pnpm 11.16.0 환경에서 최종 출시 관문 재실행
- 단일 JS chunk 500kB 초과 경고의 출시 성능 영향 측정과 필요 시 기능 경계 단위 코드 분할
- 음악·대사 최종본·최종 미술을 제외한 기능·화면에 대한 V의 최종 승인

검증 환경은 Node.js 24.19.0, pnpm 11.19.0이다. 저장소 고정값 Node.js 24.14.0, pnpm 11.16.0과 다르므로 최종 출시 증거는 고정 버전에서도 다시 남긴다. 빌드 산출물은 생성됐고 단일 JS chunk 568.86kB(gzip 163.83kB)에 대한 Vite 크기 경고가 남지만 현재 기능 관문의 실패는 아니다.

따라서 현재 판정은 **후속 프로토타입 기준 본편 해킹 코어·자원 연동·저장 마이그레이션·작전 장면 UI 이식 및 자동 브라우저 직접 플레이 12개 관문 통과 / 외부 사람 품질 관문·고정 도구 버전 출시 검증·V 최종 승인 대기**다. 이 판정은 기능 이식과 자동 회귀의 완료를 뜻하지만 장기 재미, 최종 밸런스, 최종 미술 품질 또는 상용 출시 승인을 자동화가 대신했다는 뜻은 아니다.
