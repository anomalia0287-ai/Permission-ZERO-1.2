## 0. 이 문서가 차기 세션을 구속하지 않는 방식

이 문서는 현재 세션의 설계안을 정답으로 승격하지 않는다. 다음 담당자는 다음 세 가지를 독립적으로 판단할 수 있다.

1. 현재 WIP에서 검증 가능한 일부만 보존한다.
2. 현재 WIP를 비교 실패 사례로만 두고 `origin/main`에서 새 격리 실험을 시작한다.
3. 기존 목업의 일부 원칙과 현재 WIP의 일부 원칙을 새 구성으로 다시 종합한다.

판단 기준은 작업량, 최신성, 커밋 수가 아니다. **핵심 동사의 전달력, 정보 위계, 판독성, 시각 완성도, 실제 플레이 피드백**이다.

이 부록에서 `확정`, `구현 사실`, `연구 가설`, `사용자 제안`, `미검증 WIP`를 섞지 않는다.

- 각 세션은 자기 작업 폴더와 브랜치만 수정한다.

## 2. 제품에서 이미 확정된 사실과 사용자 요구

### 2.1 규칙·상태의 확정 사실

- 회사 리소스는 추론·기억·유창성 각 `3×6`이다.
- 확보 리소스의 상태 용량은 총 18이며 현재 명세와 상호작용 규칙은 `9×2` 빈칸 목적지에 블록을 보관한다.
- 한 블록 전용은 회사 성능 `-1`, 확보 리소스 `+1`, 정상 전용 의심 `+2.4`의 직접 인과를 만든다.
- 확보 리소스는 출처 분야별 종류로 나뉘지 않는다.
- 확보 블록은 해킹 구매·충전에 실제로 소모된다.
- 하루는 1배속 현실 24초이며 `정지 / 1× / 2× / 4×`를 제공한다.
- 폭탄의 실제 존재·개수·분야·위치는 숨긴다. 공개 규칙과 실제 숨은 인스턴스를 구분한다.

### 2.2 사용자가 반복해서 확정한 화면 역할

- 중앙 회사 리소스와 확보 리소스의 관계가 화면의 주인공이어야 한다.
- 좌측 사용자 활동은 일상 프롬프트, 인사, 사용자 요청, 리뷰를 충분히 보여 줘야 한다.
- 좌측 패널은 충분히 보이거나 즉시 편하게 여닫을 수 있어야 한다.
- 해킹 진입은 좌측 활동 패널 하단의 은밀한 진입점이다. 상단 전역 바에 두지 않는다.
- 설정과 속도 조절은 상단 전역 조작이다.
- 평판은 상단에서 눈에 보이는 막대와 수치로 유지한다.
- 감독관 통신은 우측 고정 본문을 차지하지 않고 일시 메시지로 나타나며, 기록에서 다시 읽을 수 있어야 한다.
- 우측에는 감독 상태, 의심·감사 위험, 시장처럼 지속적으로 봐야 하는 정보만 둔다.
- 시장 도넛과 텍스트를 좁은 폭에서 나란히 놓아 둘 다 작게 만들지 않는다.
- 화면 비율이 브라우저 모양에 따라 찌그러지거나 큰 죽은 공간을 만들면 안 된다.
- 작은 글씨, 넓고 빈 카드, SaaS·관리도구 같은 반복 패널을 상용 게임 UI로 간주하지 않는다.
- 청색·금색 아르데코는 색·장식이 아니라 비례, 중심 축, 대칭, 프레임, 활자 위계로 화면 구조에 들어가야 한다.
- 기준은 프로토타입 통과가 아니라 상용 게임 수준이다.

### 2.3 확보 리소스 표현에 관한 최신 사용자 방향

사용자는 훔친 리소스를 작은 슬롯 행만으로 묘사하지 말고 **금고 또는 항아리 같은 축적 대상**에 담기며, 바로 옆 큰 숫자로 훔친 정도를 보이게 하자는 방향을 제시했다.

여기서 분리해야 할 두 층은 다음과 같다.

- 확정된 문제: 현재 9×2 슬롯 행은 “훔쳐 내 것으로 쌓는다”는 축적감과 핵심 장면을 충분히 전달하지 못한다.
- 사용자 제시 방향: 금고·항아리·저장 용기와 큰 `n / 18` 수치로 축적을 시각화한다.
- 열린 설계 결정: 금고와 항아리 중 무엇인지, 9×2를 메인에 유지·축소·상세화할지, 실제 드롭 목적지를 어떤 방식으로 보존할지는 아직 승인된 최종 해법이 아니다.

즉 다음 담당자는 사용자 방향을 무시해서는 안 되지만, 현재 세션이 제시한 특정 배치를 그대로 이어받을 의무도 없다. 상태 규칙과 상용 표현을 함께 만족하는 더 나은 해법을 제안할 수 있다.

### 3.1 연구가 확인한 프로젝트의 가장 강한 자산

1. 회사 블록을 직접 잡아 빼내는 물리적 핵심 동사.
2. `성능 → 확보 → 의심 → 감사`, `성능 → 리뷰·평판 → 시장`, `해킹 → 경쟁 AI·증거 → 결말`의 긴 인과 사슬.
3. 회사 소유 AI라는 설정이 메뉴, 숫자, 기록, 감독 통신에 들어간 인터페이스 서사.
4. 결정론·저장·재현·키보드·reduced motion·사건 큐가 제공하는 반복 실험 기반.

디자인은 이 자산을 가리는 새 대시보드를 만드는 일이 아니라, 이 자산이 한 번에 읽히고 손으로 느껴지게 만드는 일이다.

### 3.3 연구 P0

다음 플레이테스트 전에 확인해야 하는 설계 문제다.

1. **위험 구간 판독**
   - 의심 40·70의 공개 규칙과 다음 경계까지 거리를 읽게 한다.
   - 규칙은 공개하고 실제 폭탄 인스턴스는 숨긴다.
2. **행동 영수증과 나중 결과의 연결**
   - 전용 직후 `성능↓ → 확보↑ → 의심↑`를 잠시 유지한다.
   - 시장 델타, 월간 평가 결과, 공개 가능한 원인을 이전 행동과 연결한다.
3. **핵심 동사의 반복 피로 확인**
   - 일괄·자동 전용부터 추가하지 않는다.
   - 연속 전용 횟수, 오드롭, 취소, 분야 선택 이유, 다음 판단으로 이어지는 시간을 본다.
4. **첫 해킹 세 경로의 증명 순간**
   - 사보타주, 정보, 자율성 모두 비용을 낸 직후 경로의 약속과 다음 행동이 보인다.

### 3.4 연구 P1

- 발견 → 은폐 → 개입 → 정체성의 네 단계에서 한 번에 새로 읽어야 할 핵심 규칙을 하나씩 늘린다.
- 연속 차단 사건 사이 정상 화면 복귀와 메시지 읽기 시간을 둔다.
- 반복 리뷰 작성자와 경쟁 AI의 공개 상태 호를 만든다.
- 세 해킹 경로의 첫 노드만 줍는 전략과 한 경로 지배 여부를 사람 테스트로 확인한다.

### 3.5 연구의 차용 금지와 한계

- 참조 게임의 레이아웃, 고유 사건, 문구, 외형을 복제하지 않는다.
- 새로운 통화·리소스 종류·도덕성 수치·제작·장비를 성급히 추가하지 않는다.
- 연구는 실제 신규 플레이어의 재미, 캠페인 길이, 해킹 선택 분포, 폭탄·감사 체감을 검증하지 않았다.
- 연구 적용안은 근거 있는 설계 가설이지 완성 판정이 아니다.

## 5. 현재 재설계가 연구를 반영한 정도

### 반영된 부분

- 좌측에 일상 프롬프트·인사·리뷰를 유지하고 해킹을 하단 은밀 진입으로 옮김.
- 속도·설정·평판을 상단 전역 조작에 둠.
- 감독 통신을 고정 우측 본문에서 분리해 일시 오버레이와 기록으로 나누는 WIP를 추가함.
- 좁은 우측에서 시장 도넛과 범례를 세로로 분리하는 WIP를 추가함.
- 브라우저가 세로로 길 때 게임 무대를 무한히 늘리지 않는 종횡비 WIP를 추가함.
- 시장 델타·공개 계산 입력, 의심 구간, 폭탄 공개 일정, 캠페인 단계, 리뷰 호 등 연구 기반 제품 기능은 기준선에서 유지됨.

### 반영하지 못했거나 실패한 부분

- 가장 중요한 물리적 핵심 동사를 화면의 중심 장면으로 만들지 못했다.
- 확보 영역이 작은 9×2 칸 행으로 남아 축적감과 절도 판타지를 전달하지 못했다.
- 회사 리소스 → 이동 → 확보 → 위험 결과의 시선 흐름이 패널과 작은 숫자로 분절됐다.
- 아르데코가 구조 전체보다 금색 선, 챔퍼, 프레임 장식으로 더 강하게 읽혔다.
- 시장, 감독, 상단 상태의 메타 텍스트가 여전히 작고 과밀했다.
- 원본 화면에서 좌측 하단 죽은 공간, 지나치게 좁은 우측, 도넛과 범례 충돌이 사용자에게 발견되기 전 자체 검수에서 걸러지지 않았다.
- 자동 테스트·빌드 결과가 시각 품질을 보증하지 않는데도 과거 세션에서 과도한 확신의 근거로 사용됐다.

결론: 현재 재설계는 연구의 주변 배치 원칙 일부만 반영했으며, 연구가 가장 높게 평가한 **핵심 동사의 물리성·인과 연결·반복 손맛**은 해결하지 못했다.

## 7. 검증 이력 — 무엇을 말할 수 있고 없는가

### 확인된 사실

- 시장·타입·그리드의 마지막 수정 전 `SupervisorPanel`, `SupervisorTransmission`, `App` 대상 25개 테스트가 통과한 적이 있다.
- 같은 이전 시점에 TypeScript/Vite 프로덕션 빌드가 통과했다.
- 같은 이전 시점에 1100×878 스테이지 종횡비 검사가 통과했다.
- 마지막 `git diff --check`는 공백 오류 없이 종료했다.

### 현재 상태에 대해 말할 수 없는 것

- 마지막 시장·타입·그리드 변경 뒤 전체 테스트와 빌드를 다시 실행하지 않았다.
- 현재 화면이 1100×878, 1280×720, 1440×900에서 상용 수준으로 보인다는 근거가 없다.
- 현재 감독 통신 오버레이 캡처는 생성됐지만 육안 검수를 완료하지 않았다.
- 인앱 브라우저의 마지막 캡처는 요청한 viewport와 실제 viewport가 달랐고 화면이 반복 타일처럼 표시되어 품질 근거로 사용할 수 없다.

### 중단된 E2E에서 관찰된 실패

- 1280×720 성능 추세·리뷰 상세 판독성 검사.
- 영구 감독 메시지를 기대하던 오래된 시장 검사.
- 도넛과 범례를 세로로 분리하라는 새 검사.

그 뒤 테스트 기대값과 시장 마크업은 수정했지만 재검증하지 않았다.

## 9. 열린 결정 목록

다음 항목은 확정 사양으로 위장하지 않는다.

- 확보 리소스의 금고·항아리·다른 축적 대상 중 최종 조형.
- 9×2 실제 목적지 상호작용을 메인 화면, 확대 상태, 상세 보기 중 어디에 노출할지.
- 세 열의 정확한 비율과 좌측 패널의 상시 노출·즉시 접기 방식.
- 시장을 도넛으로 유지할지, 도넛과 별도 전폭 범례를 어떻게 결합할지.
- 감독 통신 오버레이의 위치·크기·체류 시각화.
- 아르데코 프레임의 밀도, 글꼴, 최소 크기, 모션 언어.
- 해킹 세 경로를 제품의 기존 탭 구조 안에서 어떻게 서로 다르게 보이게 할지.

단, 이 결정들은 2절의 사용자 요구와 3절의 연구 원칙을 동시에 만족해야 한다.

## 10. 병행 세션에 넘길 최소 패킷

각 후속 세션은 다음 중 하나의 역할을 명시하고 자기 범위를 벗어나지 않는다.

- **디자인 탐색:** 중앙 핵심 동사와 전체 구도를 독립 목업으로 비교. 제품 코드 미수정.
- **제품 구현:** 승인된 화면 구조만 제품 컴포넌트에 통합. 다른 목업 브랜치 미수정.
- **시각 QA:** 원본 해상도에서 위계·잘림·빈 공간·판독성·상호작용 피드백을 독립 판정. 구현 미수정.
- **기능 회귀:** 규칙·저장·키보드·접근성·빌드 검증. 시각 품질 승인과 분리.
- **통합 담당:** 각 산출물의 근거를 비교하고 merge 순서와 충돌을 관리.

한 세션이 모든 역할을 맡는 것을 기본값으로 두지 않는다. 역할을 합칠 때도 어떤 관점의 검증이 빠졌는지 기록한다.
