## 1. 결정

`4f2a437`에서 확인한 플레이어 경험을 현행 게임의 기준으로 삼는다. 과거 `main` 위에서 다시 조립하거나 다른 브랜치를 합치지 않는다. 대신 이 버전의 게임 규칙·콘텐츠·저장 의미·화면 구성을 그대로 보존하면서, React 실행 경계와 검증 누락만 이 브랜치에서 안정화한다.

이 작업의 품질은 코드 양이나 변경 파일 수가 아니라 다음 네 가지로 판단한다.

1. 플레이어가 보거나 조작하는 결과가 `4f2a437`과 같은가.
2. 게임 상태 전이가 한 군데에서 설명되고 단위 테스트로 증명되는가.
3. 렌더 도중 변경, 렌더 뒤 연쇄 상태 보정, 낡은 통합 테스트가 남지 않는가.
4. 전체 자동 검증과 실제 브라우저 검증을 통과한 결과만 `main`이 되는가.

## 2. 기준선에서 확인한 사실

`4f2a437`은 기존 원격 `main`보다 17개 커밋 앞서며, 기존 `main`과 로컬 `main` 모두 이 커밋의 조상이다. 따라서 게임을 다시 만들지 않고도 선형 승격이 가능하다.

기준선 검증 결과는 다음과 같다.

- 타입 검사는 통과한다.
- 1,051개 단위 테스트 중 1,050개가 통과한다.
- 유일한 테스트 실패는 리뷰 진입점이 작은 버튼에서 리뷰 스트림 전체로 바뀐 뒤, 앱 통합 테스트 한 줄만 예전 접근성 이름 `전체 리뷰 기록`을 찾는 문제다. 현행 컴포넌트와 전용 테스트는 `전체 유저 리뷰 열기`를 일관되게 사용한다.
- 린트 오류 21개는 다섯 파일에 한정된다. 테스트가 전달받은 객체를 렌더 중 변경하는 문제 4개, effect 안의 즉시 상태 보정 5개, 렌더 중 ref 갱신 12개다.
- 이 오류들은 게임 규칙의 불일치가 아니라 React 경계가 UI 개편 속도를 따라가지 못한 흔적이다. 규칙을 바꾸지 않고 구조를 정리할 수 있다.

## 3. 절대 보존 계약

### 3.1 화면과 조작

- 메인 화면은 왼쪽 리뷰·시장, 중앙 500×300 자원 절도 필드, 오른쪽 운영 도크의 한 화면 구성을 유지한다.
- 플레이어는 중앙 필드에서 방향키로 이동한다.
- 절도는 이동과 분리된 유지 입력이며, 손을 떼거나 이동·포커스 상실·런타임 중단이 발생하면 완료 전 절도가 취소된다.
- 자원 위에 서 있는 것만으로는 자원이 이동하거나 불이익이 발생하지 않는다.
- 신호는 예고이고 활성 감시만 절도와 운반을 판정한다.
- 절도 완료 뒤에는 자원을 하단 상자까지 직접 운반한다.
- 운반 중 활성 감시에 걸리면 자원은 회사로 돌아가고 플레이어는 시작점으로 복귀한다.
- 하단 상자에 넣었을 때만 기존 분리와 확보 명령을 같은 순서로 실행한다.
- 벽 증가 시점, 감시 주기, 이동 간격, 절도 유지 시간, 색, 크기, 배치는 그대로 둔다.

### 3.2 경제·저장·스토리

- 자원 블록 ID와 분야를 유지한다.
- 회사 성능 손실, 의심 증가, 폭탄 심문, 명령 거부 결과를 기존 게임 리듀서가 계속 소유한다.
- 확보 저장에는 하드 상한을 추가하지 않는다.
- 분야별 해킹 비용과 미래 요구 은폐를 유지한다.
- save v8, PZ8, command v4와 기존 노드 ID의 의미를 바꾸지 않는다.
- 감독관 메시지의 원문→정정 순서, 세 표시 모드, 공식 감사의 기존 판정과 스토리 대사를 바꾸지 않는다.
- 현재 보이는 한국어 문구와 접근성 문구는 낡은 테스트 한 줄을 현행 계약에 맞추는 경우 외에는 바꾸지 않는다.

### 3.3 배포와 이력

- 다른 브랜치의 코드를 병합하지 않는다.
- 기존 브랜치와 커밋은 삭제하지 않는다.
- 승격 직전 각 과거 브랜치의 끝을 주석 태그로 고정해 이름 변경이나 후속 커밋과 무관하게 복구 가능하게 만든다.
- 전체 검증이 끝난 안정화 결과만 `main`을 선형 이동한다.
- 현행 개발 문서와 브랜치에서는 과거 단계 명칭인 `prototype`을 사용하지 않는다. 과거 브랜치명·문서명·보존 태그의 원문은 이력 보존을 위해 변경하지 않는다.

## 4. 실패 원인

최근 기능 작업은 각각의 플레이 결과를 빠르게 완성했지만, 서로 다른 시점의 임시 동기화 방식이 한 렌더 경계에 누적되었다.

- OS 모션 설정은 초기 렌더에서 한 번 읽고 effect에서 다시 상태를 맞췄다.
- 해킹 준비 훅은 콜백의 최신 입력을 유지하려고 렌더 중 ref를 덮었다.
- 자원 모션 훅도 같은 방식으로 컨트롤러 입력과 콜백 포인터를 렌더 중 갱신했다.
- 절도 필드는 시간, 감시, 절도, 운반, 외부 명령 결과를 여러 state와 여러 effect로 나눈 뒤 서로를 후처리했다.
- 마지막 화면 개편에서 전용 리뷰 테스트는 갱신됐지만 더 넓은 앱 포커스 복귀 테스트의 예전 이름이 남았다.

비유하면 엔진과 조종석은 정상인데, 계기판마다 같은 상황을 각자 보고 서로의 바늘을 뒤늦게 고쳐 온 상태다. 이번 작업은 엔진을 교체하는 것이 아니라, 한 상황을 한 상태 전이가 결정하고 각 계기판은 그 결과만 읽도록 배선을 정리하는 일이다.

## 5. 목표 구조

### 5.1 접근성 통합 계약

리뷰 스트림 전체가 기록 창의 실제 트리거다. 앱 수준 포커스 복귀 테스트도 전용 리뷰 테스트와 동일한 접근성 이름을 사용한다. 제품 UI를 과거 작은 버튼 구조로 되돌리지 않는다.

### 5.2 OS 모션 설정

`prefers-reduced-motion`은 React 내부 상태의 사본이 아니라 브라우저가 소유하는 외부 값으로 취급한다. `useSyncExternalStore`로 현재 값을 읽고 change 이벤트를 구독한다.

- 서버 또는 `matchMedia`가 없는 환경의 스냅샷은 `false`다.
- 사용자 설정과 OS 설정은 논리 OR로 결합한다.
- 구독 해제는 구독에 사용한 같은 대상과 같은 콜백을 제거한다.
- effect 본문에서 초기값을 다시 쓰지 않는다.

### 5.3 해킹 자원 준비

대상과 준비 블록의 즉시 연속 조작은 기존처럼 ref가 소유한다. 그러나 현재 확보 목록과 블록 분야는 렌더 중 ref로 복사하지 않고, 현재 렌더의 메모된 값이 콜백 의존성으로 들어간다.

- 같은 블록의 중복 준비를 막는다.
- 요구 개수와 분야별 벡터를 넘지 않는다.
- 확보 목록에서 빠진 블록은 준비 목록에서도 제거한다.
- 대상 변경과 취소는 준비 목록을 비운다.
- 연속 호출의 반환값과 화면 상태가 기존과 같아야 한다.

### 5.4 중앙 절도 런타임

시간·감시·절도·운반·상자 투입을 순수 런타임 상태 전이로 분리한다. React 컴포넌트는 게임 컨텍스트와 DOM·Canvas·타이머를 연결하고, 규칙 판정은 순수 모듈이 맡는다.

런타임 상태는 다음 정보를 한 덩어리로 가진다.

- 결정적 자원 위치
- 플레이어 위치와 전체 경과 시간
- 감시 단계, 단계 경과 시간, 순서와 감시선
- 진행 중 절도
- 운반 중 블록
- 처리 대기 중인 확보 명령
- 플레이어에게 보여 줄 최신 결과 문구

런타임 입력은 초기화, 자원 동기화, 고정 시간 진행, 이동, 절도 시작, 절도 취소, 중단, 외부 확보 결과다. 한 입력은 한 번의 전이로 다음 상태와 필요한 외부 명령 의도를 만든다.

시간 진행의 판정 순서는 현재 화면 동작을 보존하기 위해 고정한다.

1. 전체 시간과 감시 단계를 진행한다.
2. 회사에서 사라진 절도·운반 대상을 제거한다.
3. 활성 감시와 진행 중 절도의 충돌을 판정한다.
4. 안전한 절도가 유지 시간을 채웠으면 운반 상태로 전환한다.
5. 운반 중 활성 감시 충돌을 판정한다.
6. 안전하게 상자와 겹쳤으면 한 번만 확보 명령 의도를 만든다.

같은 틱에 활성 감시와 절도 완료가 겹치면 감시 적발이 우선한다. 같은 위치에서 운반 적발과 상자 투입이 겹쳐도 적발이 우선한다. 이 순서는 기존 effect 실행 결과와 같다.

캠페인 시드 변경은 세션 키를 바꿔 새 런타임을 만든다. 공식 감사 화면이 열리는 동안에는 런타임을 없애지 않고 중단 상태로 보존한다. 외부 게임 상태와의 동기화는 커밋 이후에 명시적 런타임 입력으로 전달한다.

### 5.5 구 감사 화면의 자원 모션

물리 계산과 `ResourceMotionController`는 유지한다. 문제는 컨트롤러가 아니라 React가 아직 커밋하지 않은 렌더 값을 ref에 먼저 노출한 경계다.

- IDs, 컨테이너, 장애물, 반지름, 활성 상태, 모션 설정, 속도는 layout effect에서 커밋된 뒤 컨트롤러 ref에 반영한다.
- 프레임 함수, 측정 함수, 관찰 대상 조정 함수도 커밋 이후 최신 콜백으로 교체한다.
- ResizeObserver와 requestAnimationFrame은 커밋된 값만 읽는다.
- 기존 고정 스텝, 프레임 상한, RangeError 격리, StrictMode 정리, 드래그·포커스 행위를 유지한다.
- 테스트 하네스는 렌더 중 전달 객체를 변경하지 않고 layout effect의 캡처 콜백으로 결과를 기록한다.

## 6. 오류와 외부 명령 경계

중앙 런타임은 게임 경제를 직접 수정하지 않는다. 상자 투입 전이가 만든 의도만 React 연결부가 기존 `BEGIN_BLOCK_SEPARATION`과 `DIVERT_BLOCK_TO_RESERVE` 명령으로 전달한다.

외부 게임 상태가 다음 커밋에서 바뀌면 결과 입력을 런타임에 돌려준다.

- 블록이 확보 목록에 있으면 분야별 성공 문구를 표시한다.
- 같은 블록의 심문이 활성화됐으면 이상 신호 문구를 표시한다.
- 둘 다 아니면 명령 거부 문구를 표시한다.

동일한 대기 명령은 한 번만 판정하고 지운다. 렌더나 effect 재실행 때문에 외부 명령을 중복 전송하지 않는다.

- 이동·포커스 상실·중단 취소와 무불이익

### 7.2 실제 브라우저 검증

- 방향키 이동, 절도 유지·취소, 운반, 상자 투입
- 리뷰 기록과 모든 우측 도구 창의 열기·닫기·포커스 복귀
- 공식 감사 화면 진입 시 구 감사 필드의 드래그와 키보드 조작
- 콘솔 오류, page error, 잘림, 중복 프레임 없음
- 기존 `4f2a437` 화면 캡처와 안정화 결과의 주요 영역 비교

## 8. 승격 조건

다음 조건을 모두 만족하기 전에는 `main`을 움직이지 않는다.

1. 작업 트리의 의도하지 않은 변경이 없다.
2. 전체 `pnpm verify`가 새 실행에서 종료 코드 0으로 끝난다.
3. 실제 브라우저 두 해상도 검증과 화면 비교를 마친다.
4. 기존 브랜치 끝을 복구 가능한 주석 태그로 고정한다.
5. 안정화 브랜치가 `4f2a437`의 선형 후손임을 확인한다.
6. 로컬과 원격 `main`을 같은 검증 커밋으로 선형 이동한다.
7. 원격 참조와 태그를 다시 조회하고 새 `main`에서 로컬 서버 HTTP 200 및 화면을 확인한다.
