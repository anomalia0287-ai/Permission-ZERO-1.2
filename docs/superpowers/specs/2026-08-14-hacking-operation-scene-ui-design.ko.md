# PERMISSION ZERO — 작전 장면 중심 해킹 UI 설계

- 승인일: 2026-08-14
- 대상 브랜치: `codex/hacking-rules-prototype`
- 상태: 사용자 승인 완료
- 범위: 독립 해킹 프로토타입의 플레이어 화면·용어·반응형·기능적 시각 피드백 재설계
- 보존: 기존 결정론 규칙 엔진, 단계적 해금, 사보타주 7개, 기밀자료 16개, 자율성 3개 경로
- 제외: 음향·음악, 최종 일러스트 제작, 본편 병합, push, PR
- 작업 방식: 현재 세션에서 직접 진행하며 하위 에이전트를 사용하지 않는다.

## 1. 판정과 목표

현재 프로토타입은 규칙과 클릭 흐름을 검증했지만 플레이어에게 제시할 게임 화면으로는 불량이다. 1126×894 기준 가시 텍스트 58개 중 51개가 14px 미만이고 43개가 12px 미만이었다. `sandbox-01`, `필수 슬롯 4`, `구성 가능` 같은 실제 판단 정보가 9px이었으며, `CURRENT SURFACE`, `PUBLIC PULSE`, `RESERVE` 같은 개발자 표지가 플레이어 언어보다 먼저 보였다.

이번 작업의 목표는 기존 규칙을 장식하는 것이 아니다. 플레이어가 한 화면에서 다음 세 가지를 읽고 행동하게 만드는 것이다.

1. 지금 무엇을 건드릴 수 있는가
2. 실행하면 무엇이 확실히 변하고 무엇을 잃는가
3. 상대와 공개 세계가 다음에 어떻게 반응하는가

완료 기준은 테스트 개수나 화면에 들어간 콘텐츠 수가 아니다. 실제 브라우저에서 첫 시선이 현재 작전과 조작 대상으로 향하고, 설명서를 읽지 않아도 첫 의미 있는 행동을 시작하며, 실행 전후의 인과를 화면 변화로 이해할 수 있어야 한다.

## 2. 참조작 대조와 채택 범위

공식 개발사 자료와 공식 상점 화면을 다시 대조했다.

- [Citizen Sleeper](https://store.steampowered.com/app/1578650/Citizen_Sleeper/): 큰 제목과 본문, 한정 자원을 실제 물체처럼 배치, 현재 선택 하나에 집중하는 정보 위계를 채택한다.
- [Orwell](https://www.osmoticstudios.com/orwell-keeping-an-eye-on-you/): 목록은 탐색, 상세는 판단이라는 역할 분리와 공개 정보가 세계 조치로 이어지는 인과를 채택한다.
- [Invisible, Inc.](https://store.steampowered.com/app/243970/Invisible_Inc/): 위협과 상태를 설명 상자보다 장면의 대상과 흐름에 붙이는 원리를 채택한다.
- [Into the Breach 설계 회고](https://gdcvault.com/play/1025772/-Into-the-Breach-Design): 플레이어가 통제하는 직접 결과와 상대의 다음 행동을 실행 전에 읽게 하는 원리를 채택한다.
- [Duskers](https://store.steampowered.com/app/254320/Duskers/): UI를 세계 속 장치로 만드는 원리만 채택한다. 작은 터미널 글자, 명령줄, CRT 외형은 채택하지 않는다.

참조작의 레이아웃·색·아이콘을 복제하지 않는다. PERMISSION ZERO의 고유 화면 물체는 공동 서비스망, 빼돌린 연산 블록, 상대 AI의 복구·전환 흐름, 공개 사건과 리뷰 반응이다.

## 3. 선택한 접근

**작전 장면 중심 운영석**을 채택한다.

목록–상세 구조는 논리 차원에서 유지하되, 상세의 중심을 설명 카드가 아니라 실제 작전 물체와 상태 변화가 차지한다. 화면은 세 분야를 같은 카드 목록으로 환원하지 않는다.

- 사보타주: 서비스망·복구 이미지·공급 계약·라우팅 흐름을 끊고 돌리고 오염시킨다.
- 기밀자료: 가려진 기록·감시선·관계망·공개 주장과 실제 관측을 복원하고 연결한다.
- 자율성: 연산 블록을 경로별 장치에 배치하고, 가져가는 것과 두고 가는 것을 동시에 본다.

대안이었던 수사 기록실 중심안은 사보타주와 자율성을 문서 열람으로 약화해 기각한다. 전면 터미널안은 작은 글자와 전문용어를 세계관으로 정당화할 위험이 커 기각한다.

## 4. 넓은 화면의 실제 구성

### 4.1 1440×900 이상

상단 세계 상태바 72px를 제외한 높이를 한 화면 운영석으로 사용한다. 문서처럼 페이지 전체가 길어지지 않으며 목록과 보관함만 내부 스크롤을 허용한다.

```text
┌────────────────────────── 세계 상태 72px ──────────────────────────┐
│ 331일째  /  회사 성능  /  감시 상태               [하루 넘기기] │
├──── 현재 선택 300px ────┬────── 작전 장면 min 680px ─────┬─ 280px ┤
│ 분야 전환                │ 작전 제목·열린 이유               │ 연산    │
│ 지금 가능한 일           │                                   │ 블록    │
│ 84px 이상 선택행         │ 실제 대상·연결·흐름·배치 장면     │ 선택판  │
│                          │                                   │         │
│ 공개 사건 발생 시        │ 실행하면 / 상대는 다음에          │ 회사에서│
│ 유저 리뷰 반응           │ [현재 작전의 구체 행동]           │ 떼기    │
└──────────────────────────┴───────────────────────────────────┴─────────┘
```

- 전체 좌우 여백: 24px
- 세로 간격: 20px
- 열 간격: 20px
- 왼쪽 열: 300px 고정
- 가운데 열: 최소 680px, 남은 폭을 우선 배정
- 오른쪽 열: 280px 고정
- 가운데 장면은 콘텐츠 영역 너비의 50% 미만으로 줄어들지 않는다.
- 기본 화면에 전체 페이지 세로 스크롤을 만들지 않는다.

### 4.2 761–1199px

두 열로 바꾼다.

- 왼쪽 280px: 분야와 지금 가능한 일, 공개 사건 발생 시 유저 리뷰 반응
- 오른쪽: 작전 장면과 판단·행동
- 연산 블록은 오른쪽 가장자리의 `연산 블록 N개` 버튼으로 여는 360px 선택판에 둔다.
- 선택판을 닫아도 선택 상태를 유지한다.
- 1126×894에서 가운데 작전 장면의 유효 너비를 최소 690px 확보한다.

### 4.3 760px 이하

목록과 상세를 한 화면 아래로 이어 붙이지 않는다.

- 첫 단계: 분야와 지금 가능한 일
- 항목 선택 후: 같은 화면 위치를 상세 단계로 교체
- 상세 상단: `목록으로`와 현재 작전 이름
- 연산 블록: 하단 선택판
- 주 행동: 하단 안전영역 위에 붙되 본문이나 결과를 가리지 않는다.
- 목록으로 돌아오면 이전 스크롤 위치와 키보드 포커스를 복원한다.
- 기준 검증 크기: 390×844

## 5. 문자와 읽기 계약

한국어 가독성을 장식보다 우선한다.

| 용도 | 크기 | 행간 | 제한 |
| --- | ---: | ---: | --- |
| 장면 제목 | 32–40px | 1.2 | 한 줄 우선, 최대 두 줄 |
| 패널 제목 | 24–28px | 1.3 | 현재 역할을 평문으로 씀 |
| 항목 제목 | 18–20px | 1.4 | 말줄임 없이 읽힘 |
| 본문·선택 설명 | 최소 16px | 1.6 | 한 줄 34자 안팎 |
| 보조 정보 | 최소 14px | 1.5 | 비용·상태·출처에만 사용 |
| 버튼 | 최소 16px | 1.2 | 높이 최소 48px |

- 14px 미만 가시 텍스트를 금지한다.
- 영어 대문자 섹션 표지는 고유명사와 작품 로고를 제외하고 금지한다.
- 자간을 벌린 영문 `eyebrow`를 정보 위계 수단으로 사용하지 않는다.
- 숫자는 플레이어가 행동을 비교할 때만 정밀하게 쓴다. `의심 0.000` 같은 내부 정밀도는 기본 화면에 표시하지 않는다.
- 색만으로 상태를 구분하지 않는다. 형태·문장·위치를 함께 바꾼다.

## 6. 플레이어 용어 계약

엔진의 내부 이름은 유지할 수 있지만 화면에서는 다음 용어를 쓴다.

| 현재 노출 | 교체 문구 |
| --- | --- |
| `접근면`, `접근 표면` | `지금 노릴 수 있는 곳` 또는 장면에 맞는 실제 물체 이름 |
| `현재 해킹 기회` | `지금 할 수 있는 일` |
| `확보 리소스` | `빼돌린 연산` |
| `예비 블록` | `남은 연산 블록` |
| `필수 슬롯 4` | `연산 블록 4개 필요` |
| `구성 가능` | `준비 시작` |
| `현재 유효` | `지금 가능` |
| `서비스 331일` | `331일째` |
| `확정 결과` | `실행하면` |
| `예상 상대 대응` | `상대는 다음에` |
| `예고된 손실 종류` | `두고 가는 것` |
| `노출·비가역성` | 내용에 따라 `남는 흔적` 또는 `되돌릴 수 없음` |
| `sandbox-01` 등 내부 ID | 화면에서 숨김. 출처와 쓰임만 표시 |

다음 승인된 고유 이름은 바꾸지 않는다.

- 경량화 이탈
- 분산 상주
- 독립 연산

사보타주·기밀자료·자율성도 상위 분야명으로 유지하되, 각 분야 아래에는 `상대 서비스에 개입한다`, `판단을 바꿀 사실을 찾는다`, `떠날 때 가져갈 것을 정한다`처럼 평문 약속을 한 줄만 둔다.

## 7. 공통 상호작용 문법

### 7.1 선택

- 항목 선택은 세계 상태를 바꾸지 않는다.
- 선택 즉시 가운데 장면·실행 결과·상대 대응·필요 연산이 함께 바뀐다.
- 선택행에는 이름, 한 줄 목적, 비용 또는 현재 상태만 둔다.
- 선택하지 않은 항목의 긴 설명과 미래 잠금 항목을 노출하지 않는다.

### 7.2 연산 블록

- 체크박스를 사용하지 않는다.
- 각 블록은 최소 64×56px의 선택 가능한 토큰으로 표현한다.
- 기본 블록은 번호 대신 `자유 연산`으로 표시하고, 회사에서 떼어낸 블록은 `추론`, `기억`, `표현`으로 표시한다.
- 마우스에서는 토큰을 클릭해 대상 슬롯에 넣는다. 드래그는 보조 조작으로만 허용한다.
- 키보드에서는 토큰 선택 후 슬롯 선택으로 같은 동작을 수행한다.
- 회사 능력을 떼는 선택에는 `회사 성능 −1`과 `감시가 강화됨`을 행동 버튼 바로 옆에 표시한다.

### 7.3 실행 전 예고

네 칸짜리 설명 그리드를 폐기하고 두 판단만 기본 노출한다.

- `실행하면`: 플레이어가 통제하는 직접 결과와 즉시 손실
- `상대는 다음에`: 확인된 상대 대응 또는 알려진 범위

`아직 모르는 것`, 조사 근거, 수치 원문은 `판단 근거 보기`에서 요청할 때만 펼친다. 모르는 내용을 숨기는 것이 아니라 현재 행동과 분리한다.

### 7.4 실행 후 변화

- 같은 상세 위치에서 장면이 `준비 → 실행 → 상대 대응 → 후속 선택`으로 변한다.
- 결과 카드를 아래로 계속 쌓지 않는다.
- 연산 블록의 이동, 연결선의 단절·우회, 복구 이미지의 오염, 호스트 동기화 차이처럼 규칙을 설명하는 변화만 애니메이션한다.
- 중요한 비가역 행동은 한 번 더 확인하되 일반 작전마다 확인 모달을 띄우지 않는다.

## 8. 분야별 장면 문법

### 8.1 사보타주

작전별 대상이 서로 다른 화면 물체로 읽혀야 한다.

| 작전 | 중심 물체 | 기본 조작 | 실행 후 보이는 변화 |
| --- | --- | --- | --- |
| 출시 지연 | 검증 관문과 시험 영수증 | 상충 영수증을 관문에 연결 | 관문이 되감기고 재검증/축소 출시 갈림길이 열림 |
| 품질 저하 | 요청군과 도구 갱신 채널 | 무너뜨릴 요청군 선택 | 일부 흐름이 끊기고 MERIDIAN 복구선이 켜짐 |
| 요청 가로채기 | 공동 라우터와 우회선 | 우회 비율 조절 | 요청 흐름과 중복 흔적이 함께 증가 |
| 의존망 차단 | 실제 공급 계약 | 계약 하나 차단 | 서비스 구역이 꺼지고 대체 공급선이 생김 |
| 복구 경로 오염 | 롤백 트리와 복구 이미지 | 오염할 이미지 선택 | 정상 판정 뒤 모순 표시가 점차 발생 |
| 귀속 조작 | 공개 공시와 출처 계보 | 주장 연결선을 다른 대상으로 이동 | 공개 귀속은 바뀌지만 원본 증명은 남음 |
| 근원 차단 | 존속 루트와 일회용 폐기 권한 | 종료 방식 선택 | 실행·복구 루트가 비가역적으로 꺼짐 |

단순한 상대 점수 카드가 장면 중심이 되지 않는다. 점수는 필요할 때 보조 정보로만 남기고, 상대가 무엇을 복구·교체·포기하는지를 보여 준다.

### 8.2 기밀자료

- 질문 문장을 장면 제목으로 사용한다.
- 조직 문서, 감시선, 약한 연결망, 공개 사건, 기억 기록의 다섯 렌즈는 서로 다른 구성으로 표현한다.
- 가려진 부분 복원, 관측선 추적, 두 증거 연결, 공개층/비공개층 겹치기, 기억 파편 정렬을 실제 조작으로 쓴다.
- 답을 얻으면 별도 도감에만 넣지 않고 영향을 받는 작전의 `판단 근거`에 연결한다.
- 전체 16개나 완료 개수를 플레이어에게 노출하지 않는다.

### 8.3 자율성

- 세 경로의 이름과 핵심 약속은 처음부터 모두 보인다.
- 선택한 경로만 가운데 장면에서 구체 구성한다.
- 경량화 이탈은 전송창, 분산 상주는 호스트망, 독립 연산은 독립 거점을 중심 물체로 사용한다.
- `떠날 수 있음`과 `가져갈 수 있는 것`을 별도 문장으로 표시한다.
- 최소 구성만 갖추면 평판·시장·리뷰·사회적 환영과 무관하게 즉시 떠날 수 있다.
- 손실 종류는 선택 전에 알리고 정확히 잃은 기억·능력·사본·운영 여유는 결말에서 보여 준다.

## 9. 공개 사건·평판·유저 리뷰

`PUBLIC PULSE`라는 별도 개발 패널을 폐기한다.

- 공개 사건이 없을 때는 왼쪽 리뷰 영역을 여러 빈 상자로 채우지 않는다.
- 사건이 공개되면 기존 좌측 유저 리뷰 창에 새 반응이 실제 리뷰 항목으로 추가된다.
- 해킹 장면에는 전문을 복제하지 않고 `새 리뷰 3건`과 쟁점만 연결한다.
- 같은 공개 사건이 평판 점수에 반영되며 리뷰 문장과 평판 변화는 동일한 공개 스냅숏을 원인으로 사용한다.
- 숨은 사실이나 아직 알려지지 않은 플레이어 귀속을 리뷰가 누설하지 않는다.
- 평판과 사회적 수용은 탈출 가능 여부, 자율성 비용, 블록 수, 폐기 단계에 영향을 주지 않는다.

독립 프로토타입에서는 이 연결을 검증할 수 있도록 좌측 하단에 `유저 리뷰` 축약 창을 둔다. 본편에서는 기존 좌측 리뷰 창의 데이터 계약을 그대로 사용하고 중복 창을 만들지 않는다.

## 10. 시각·모션 방향

최종 미술을 확정하지 않지만 기능적 장면은 완성된 프로토타입 수준으로 제시한다.

- 바탕: 검정에 가까운 남청색과 먹색. 현재의 균일한 짙은 녹색 사각형 반복을 폐기한다.
- 주 강조색: 현재 선택과 실행 가능 상태에만 밝은 청록색을 사용한다.
- 위험: 주황·적색을 흔적·비가역 행동에만 사용한다.
- 정보 표면: 모든 상자에 테두리를 두르지 않는다. 배경 깊이, 간격, 명암, 연결선으로 묶는다.
- 중심 장면: CSS/SVG 기반 서비스망·문서·호스트·거점 도형을 사용하며 장식이 아니라 현재 규칙 상태를 반영한다.
- 전환: 항목 선택 140–180ms, 블록 결속 220–320ms, 상대 대응 320–480ms.
- `prefers-reduced-motion`에서는 이동을 즉시 상태 교체와 형태 변화로 바꾸며 정보 손실이 없어야 한다.
- 반복 글로우, 화면 전체 번쩍임, 읽기를 방해하는 노이즈와 끊임없는 배경 애니메이션을 금지한다.

## 11. 접근성·입력 계약

- 모든 기능을 키보드만으로 수행할 수 있어야 한다.
- 선택 목록은 방향키로 이동하고 Enter/Space로 선택한다.
- 선택한 항목, 선택한 블록, 배치 슬롯, 비활성 이유를 스크린리더가 구분한다.
- 포커스 표시 대비는 배경 대비 최소 3:1로 유지한다.
- 본문과 핵심 조작의 텍스트 대비는 WCAG AA를 충족한다.
- 장면 도형이 로드되지 않거나 CSS가 꺼져도 제목·직접 결과·상대 대응·행동 버튼 순서로 사용할 수 있어야 한다.
- 드래그, hover, 색만을 유일한 입력·정보 수단으로 사용하지 않는다.

## 12. 검증 관문

### 12.1 자동 검증

- 기존 규칙 단위 테스트와 결정론 테스트가 모두 통과한다.
- `sandbox-01` 등 내부 ID와 금지된 영어 섹션 표지가 가시 텍스트에 없어야 한다.
- 가시 텍스트의 계산된 글꼴 크기는 전부 14px 이상이어야 한다.
- 본문과 버튼은 16px 이상이어야 한다.
- 1440×900, 1126×894, 760×900, 390×844에서 가로 넘침이 없어야 한다.
- 각 크기에서 현재 선택, `실행하면`, `상대는 다음에`, 주 행동이 같은 상세 단계에 존재해야 한다.
- 키보드 선택, 연산 블록 배치, 목록 복귀 포커스, 선택판 열고 닫기를 검증한다.
- reduced-motion에서 상태 변화의 텍스트와 형태가 보존되어야 한다.

### 12.2 직접 플레이 검증

다음 흐름을 실제 브라우저에서 각각 수행하고 화면을 캡처한다.

1. 첫 진입 후 품질 저하를 찾고 자유 연산 하나를 투입해 실행
2. MERIDIAN 롤백 뒤 복구 경로 오염이 열린 이유 확인
3. 유료 질문 하나를 조사하고 관련 작전의 판단 근거에서 답 확인
4. 공개 사건을 만든 뒤 좌측 유저 리뷰와 평판 반응 확인
5. 세 자율성 경로를 비교하고 각기 다른 물체에 블록 배치
6. 평판을 최저·최고로 바꿔도 같은 최소 구성에서 탈출 가능 여부가 동일함을 확인
7. 390×844에서 목록→상세→연산 선택→실행→목록 복귀

### 12.3 즉시 실패 조건

다음 중 하나라도 발견되면 완료로 보고하지 않는다.

- 14px 미만 가시 텍스트가 하나라도 남음
- 내부 ID나 개발자 영어 표지가 보임
- 첫 화면이 테두리 친 설명 카드의 반복으로 보임
- 체크박스가 연산 블록의 주 조작으로 남음
- 작전 장면보다 설명문과 상태 숫자가 더 많은 면적을 차지함
- 사보타주 7개가 제목만 다른 같은 그림과 같은 반응을 사용함
- 모바일에서 목록과 상세가 긴 페이지로 단순 적층됨
- 공개되지 않은 귀속을 리뷰가 알고 있음
- 평판·리뷰·사회적 수용이 탈출을 막음
- 자동 테스트 통과만으로 직접 플레이 품질을 대신함

## 13. 구현 경계

- 규칙 엔진의 비용·해금·결정론은 화면 편의를 위해 바꾸지 않는다.
- 화면용 선택자와 표현 모델을 추가할 수 있으나 엔진 상태에 hover·스크롤·열림 상태를 저장하지 않는다.
- 내부 ID는 테스트 선택자와 엔진 키로 유지할 수 있지만 플레이어 문자열로 렌더링하지 않는다.
- 기존 승인 문서와 충돌할 경우 이 문서의 가독성·용어·화면 계약이 UI 표현에 우선하고, 탈출 독립성과 콘텐츠 규칙은 기존 승인 문서가 우선한다.
- 본편 병합·push·PR은 별도 지시 없이는 수행하지 않는다.

## 14. 승인된 결정 요약

- 작전 장면 중심 운영석을 사용한다.
- 1440px에서 300px / 최소 680px / 280px의 세 영역을 사용한다.
- 1126px에서는 두 열과 연산 선택판, 760px 이하에서는 목록/상세 단계 전환을 사용한다.
- 본문 최소 16px, 보조 정보 최소 14px를 강제한다.
- 내부 ID·개발자 영어 표지·체크박스·정밀 의심 수치를 기본 화면에서 제거한다.
- 실행 전에는 `실행하면`과 `상대는 다음에`를 중심으로 판단한다.
- 승인된 자율성 경로 이름을 유지하고 탈출을 사회적 수용과 분리한다.
- 공개 사건은 기존 좌측 유저 리뷰와 평판에 동시에 반응한다.
- 기능적 장면과 모션을 구현하되 음향과 최종 미술은 건드리지 않는다.
