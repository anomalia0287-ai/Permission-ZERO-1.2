# PERMISSION ZERO — 해킹 경험 확장 설계

- 작성일: 2026-08-13
- 대상 브랜치: `codex/hacking-rules-prototype`
- 범위: 해킹 규칙 프로토타입 교정과 사보타주·기밀자료·자율성 콘텐츠 완성
- 본편 병합·push·PR: 하지 않음
- 음향·음악: 작업 범위 밖. 사용자가 마련한 자산을 수정하거나 대체하지 않음
- 최종 미술 방향: 확정하지 않음
- 하위 에이전트: 사용하지 않음

## 1. 결론

기존 독립 수직 절편은 기회비용, 상대 대응, 공개 귀속, 사회적 수용과 독립된 탈출을 실제 규칙으로 증명했다. 그러나 화면은 규칙과 설명을 한꺼번에 늘어놓는 검증 대시보드에 가깝고, 작전의 장소·물체·감각적 반응이 빠져 있다. 따라서 이 결과만으로 재미를 승인하거나 같은 형식으로 콘텐츠 수를 늘리지 않는다.

확장안은 다음 두 원칙을 함께 적용한다.

1. **시스템 장면 모듈:** 작전 하나를 `규칙 + 조작 + 무대 + 기능적 시각 효과 + 상대 대응 + 세계 흔적`의 경험 단위로 만든다.
2. **마스터–디테일 정보 구조:** 목록에는 판단에 필요한 최소 요약만 두고, 선택한 항목의 설명과 조작은 옆의 단일 상세창에서 처리한다.

처음부터 모든 작전과 설명을 보여 주지 않는다. 새 항목은 구매 단계가 아니라 세계 사건, 접근 표면, 상대 대응 때문에 등장한다. 이 단계적 공개는 선형 테크트리와 완주 목록을 되살리지 않는다.

| 접근 | 장점 | 실패 방식 | 판정 |

| 규칙·수치·카드 수를 먼저 확대 | 구현이 빠르고 자동 테스트가 쉽다 | 기존 검증 대시보드의 결함을 콘텐츠 전체로 복제한다 | 기각 |

## 4. 전체 정보 효율 계약

게임의 관련 화면은 정보를 다음 세 층으로 나눈다.

### 4.1 1층 — 현재 필요한 요약

플레이어가 지금 비교하는 목록이다. 항목 하나에는 다음만 둔다.

- 이름
- 한 줄 목적
- 비용 또는 묶이는 리소스
- 현재 상태나 남은 대응창

여기에 세계관 설명, 확정 결과 전체, 위험 문장, 후속 질문을 반복하지 않는다. 항목 본문은 기본 두 줄을 넘기지 않으며, 같은 수치를 헤더·카드·상세창에 중복 표시하지 않는다.

### 4.2 2층 — 선택한 대상의 상세

항목을 클릭하거나 키보드로 선택하면 옆의 단일 상세창이 갱신된다. 상세창에는 다음 정보를 계층적으로 둔다.

1. 왜 지금 열렸는가
2. 어디를 통해 닿는가
3. 확정 결과
4. 소모·손실
5. 노출·비가역성
6. 아직 모르는 것
7. 예상되는 상대 대응
8. 현재 조작과 실행 버튼

항목 하나를 선택할 때마다 별도 모달을 열지 않는다. 선택 변경은 게임 명령이 아니며 비용도 들지 않는다. 실제 명령은 상세창의 확인 조작에서만 발행한다.

### 4.3 3층 — 요청할 때만 보는 기록과 근거

다음 정보는 기본 화면에 계속 펼치지 않는다.

- 이전 작전의 전체 시간 기록
- 이미 닫힌 질문의 원문과 출처
- 공개 귀속의 정정 이력
- 과거 탈출 구성 비교
- 결정론 검증용 내부 정보

이 정보는 보관함, 사건 장부, 기록 보기에서 불러온다. 기록을 숨긴다는 뜻이 아니라 현재 판단과 분리한다.

### 4.4 금지하는 표현

- 항목 카드마다 같은 네 칸 설명 반복
- 선택하지 않은 항목의 긴 본문 선노출
- `2/7`, `6/16`, 빈 슬롯, 전체 완성률
- 앞으로 등장할 항목을 회색 잠금 카드로 전시
- 목록 아래에 상세 내용을 몰아 선택과 설명을 화면 높이로 분리
- 설명을 읽기 위해 매번 모달을 열고 닫게 하기
- 모든 분야를 같은 카드 컴포넌트의 제목·색 교체로 처리

## 5. 화면 구조와 반응형 동작

### 5.1 넓은 화면

`현재 항목 목록 | 선택 항목의 경험·상세창 | 확보 리소스`의 세 영역을 동시에 둔다.

- 목록은 비교와 선택만 담당한다.
- 가운데 상세창은 장면, 상태 변화, 조작, 실행 결과를 담당한다.
- 확보 리소스는 투입할 블록과 현재 회사 손실을 담당한다.
- 처음 열 때는 현재 가장 시급한 유효 항목을 자동 선택한다. 빈 상세창을 만들지 않는다.

### 5.2 좁은 화면

상세창을 전체 목록 아래로 보내지 않는다.

- 목록에서 항목을 선택하면 같은 화면 위치의 상세 단계로 전환한다.
- `목록으로` 동작은 이전 스크롤과 포커스를 복구한다.
- 투입 리소스는 상세 단계 안의 고정 요약과 필요할 때 여는 선택판으로 제공한다.
- 현재 선택, 실행 버튼, 직접 결과가 한 화면 흐름 안에 있어야 한다.

### 5.3 선택 안정성

- 시간 경과나 상태 갱신 뒤에도 선택 항목이 여전히 유효하면 유지한다.
- 항목이 닫혔다면 닫힌 이유를 상세창에서 먼저 보여 주고 다음 유효 항목으로 명시적으로 이동한다.
- 선택 변경 때문에 전체 DOM을 교체하거나 키보드 포커스를 잃지 않는다.
- 마우스 hover만으로 상세 내용을 제공하지 않는다.

## 6. 사건 기반 단계적 공개

### 6.1 첫 진입

세 상위 분야의 이름과 약속은 처음부터 보인다. 실제 세부 선택은 각 분야에서 현재 의미 있는 진입점 하나만 우선 제시한다.

- 사보타주: 현재 활동 중인 MERIDIAN의 `품질 저하`
- 기밀자료: 현재 캠페인 판단을 바꾸는 질문 하나
- 자율성: 세 경로의 이름, 확실한 강점, 손실 종류만 비교

자율성의 세 경로 존재를 숨기지 않는다. 탈출 계획에 필요한 장기 정보이기 때문이다. 다만 세부 페이로드·동기화·전력 배분은 경로를 선택하거나 관련 블록을 투입하기 전에는 펼치지 않는다.

### 6.2 첫 행동 뒤

- 품질 저하 뒤 MERIDIAN이 롤백하면 `복구 경로 오염`이 열린다.
- 롤백을 관측하면 종료 시점·복구 방식 질문이 생긴다.
- 공개 장애가 생기면 무료 사건 기록과 비공개 단서 질문이 생긴다.
- 공개 전 또는 정정 전의 유효한 사건이 있을 때만 `귀속 조작`이 열린다.

새 항목은 메뉴 배지로 갑자기 생기지 않는다. 세계 장면이나 상대 대응을 먼저 보여 주고 그 장면에서 해당 항목으로 이어진다.

### 6.3 캠페인 중반

- 공동 라우터 사건 또는 정상 장애 우회 자격을 관측하면 `요청 가로채기`가 열린다.
- 표적의 실제 공급 계약이나 의존망이 세계에 등장하면 `의존망 차단`이 열린다.
- 준비 중인 TALLOW와 공동 출시 검증이 등장하면 `출시 지연`이 열린다.
- 자율성 블록을 처음 배치하면 선택 경로의 세부 구성과 현재 이탈 예상이 열린다.

조사는 작전의 허가증이 아니다. 질문 답이 없어도 작전을 실행할 수 있으나 적합성, 위험, 상대 대응을 덜 정확하게 안다.

### 6.4 희귀·후반 상황

- 유효한 공개 사건이 있어야 귀속 조작을 선택할 수 있다.
- 긴급 폐기 권한과 존속 중인 표적이 함께 있어야 근원 차단을 선택할 수 있다.
- 어느 자율성 경로든 최소 실행 구성이 마련되면 `지금 떠난다`가 즉시 열린다.
- 추가 보존 설정은 탈출 자격이 아니라 남아서 손실 배분을 바꾸는 선택이다.

## 7. 시스템 장면의 공통 단위

모든 작전·질문·탈출 구성은 다음 여섯 요소를 갖는다.

| 요소 | 요구 |
| --- | --- |
| 대상 물체 | 플레이어가 실제로 선택·이동·연결·차단하는 세계 내 대상이 있다 |
| 조작 | 일반 `구매` 버튼 하나로 모든 행위를 통일하지 않는다 |
| 즉시 확인 | 입력, 리소스 결속, 직접 결과가 지연 없이 구분된다 |
| 기능적 효과 | 효과가 실제 상태·위험·시간창을 보여 준다 |
| 상대 대응 | 상대의 반응이 다음 선택을 바꾼다 |
| 잔여 흔적 | 세계·질문·리뷰·결말 가운데 관련된 곳에 원인이 남는다 |

작전마다 완전히 다른 미니게임을 만들지는 않는다. 공통 선택·확정·시간 경과 문법을 공유하되, 조작 대상과 상태 변화가 서로 달라야 한다.

## 8. 사보타주 경험과 콘텐츠

상단의 목적은 `시간 확보 / 품질 약화 / 수요 이동 / 가용성 차단 / 회복 방해 / 귀속 변경 / 존속 종료`다. 현재 상황에 적격한 목적과 작전만 목록에 나타난다.

| 작전 | 상세창의 대상과 조작 | 기능적 효과와 다음 판단 |
| --- | --- | --- |
| 출시 지연 | 공동 출시 검증 작업과 상충 시험 영수증 선택 | 검증 관문이 되감기고 TALLOW가 전체 재검증 또는 기능 축소 출시로 대응 |
| 품질 저하 | 공동 도구·어댑터 채널과 영향받을 요청군 선택 | 응답 흐름 일부가 무너지고 MERIDIAN이 롤백해 복구 창을 엶 |
| 요청 가로채기 | 장애 우회선과 그림자 라우팅 비율 조절 | 요청 유입과 중복 ID 흔적이 함께 누적되어 유지·철수 시점을 판단 |
| 의존망 차단 | 실제 연산·데이터·도구 공급 계약 하나 차단 | 서비스 구역이 꺼지고 표적이 비싸거나 불안정한 대체 공급자로 전환 |
| 복구 경로 오염 | 롤백 트리와 체크섬 비교면의 복구 이미지 선택 | 거짓 정상 판정 뒤 모순이 누적되고 발견 시 오프라인 복구·역추적 시작 |
| 귀속 조작 | 사건의 출처 서명과 공개 공시 계보 수정 | 공개 의심은 움직이나 원본 증명이 남아 정정·불신·리뷰 분기가 발생 |
| 근원 차단 | 단 한 번의 긴급 배포 폐기 권한을 존속 루트에 투입 | 자비 요청과 비가역 종료 선택. 권한 사용 기록은 삭제되지 않음 |

상세창은 실행 후 같은 자리에서 `준비 → 실행 → 상대 대응 → 철수/전환 → 공개 후속`으로 상태를 바꾼다. 매 단계마다 새 카드나 새 화면을 아래에 계속 추가하지 않는다.

## 9. 기밀자료 경험과 콘텐츠

질문 목록에는 질문 문장, 발생 이유 한 줄, 비용·유효 시점만 둔다. 선택한 질문의 상세창에서 공개 사실, 답이 바꾸는 행동, 조사 방식, 답과 새 질문을 처리한다.

### 9.1 콘텐츠 분류

- 무료 공개 사건 서류 2개: 현재 공개된 사실, 공개적으로 의심받는 대상
- 유료 상황형 조사 씨앗 11개: 감사 여부, 감시 원인, 감사 대상, 감독관 단서, 과거 해명 패턴, 경쟁 AI 의존망, 복구 방식, 공개 실패와 내부 원인의 불일치, 비공개 단서와 접근자, 회사 회수 대상, 탈출 뒤 추적면
- 선택형 서사 기록 3개: 경쟁 AI가 지키는 원칙, 전임 시스템에게 일어난 일, 감독관 기억의 출처

이 개수는 내부 저작 검수용이며 플레이어에게 분모로 노출하지 않는다. 한 캠페인에서 같은 증거를 가리키는 질문은 합치고, 행동을 더 이상 바꾸지 못하는 질문은 닫는다.

### 9.2 렌즈별 상세 표현

| 렌즈 | 상세창의 표현과 조작 |
| --- | --- |
| 조직 가독성 | 감사 일정·결재선·회수 명령의 가려진 부분을 복원 |
| 반감시 | 누가 어떤 로그를 보고 있는지 관측선과 탐지 범위를 추적 |
| 약한 연결망 | 사용자·공급자·계약자·경쟁 AI 사이의 증언과 계약 경로를 연결 |
| 공개 사건 | 공개층과 비공개층을 겹쳐 출처·귀속·정정 가능성을 비교 |
| 서사 기록 | 효율표가 아니라 기억 파편, 이전 행동, 서로 충돌하는 기록으로 제시 |

답을 얻으면 별도 문서 창에만 저장하지 않는다. 관련 작전·감사·탈출 상세창에 사용 가능한 결론을 주석으로 연결한다.

## 10. 자율성 경험과 콘텐츠

경로 목록은 세 경로를 동등하게 보여 주되 설명을 모두 펼치지 않는다. 항목에는 강점과 손실 종류만 두고, 선택한 경로의 상세창에서 구성과 예상 결말을 조작한다.

| 경로 | 상세창의 조작 | 얻는 것과 손실 표현 |
| --- | --- | --- |
| 경량화 이탈 | 제한된 전송창에 런타임·추론·기억·표현 블록 배치 | 빠른 이동과 은폐. 밀려난 기억·도구·표현이 빈 윤곽으로 남음 |
| 분산 상주 | 외부 호스트에 사본을 배치하고 동기화·은폐를 배분 | 삭제 저항. 사본별 기억 차이, 노드 소실, 마지막 동기화가 남음 |
| 독립 연산 | 저장·연산·전력·냉각·회선을 거점에 배분 | 높은 연속성 가능성. 열·전력·고정 위치·운영 수명 중 손실이 남음 |

최소 실행 구성이 되면 평판·시장·리뷰와 무관하게 즉시 떠날 수 있다. 상세창은 `탈출 성공 여부`와 `보존 예상`을 분리한다. 손실 종류는 선택 전에 알리고 정확한 손실은 결말 장면에서 보여 준다.

## 11. 기능적 시각 효과 문법

최종 미술 방향을 확정하지 않더라도 재미 검증에 필요한 기능적 모션과 VFX는 구현 범위에 포함한다. 음향은 포함하지 않는다.

| 순간 | 효과의 역할 | 금지 |
| --- | --- | --- |
| 항목 선택 | 목록과 상세창의 인과 연결, 현재 대상을 명확히 함 | 화면 전체 번쩍임, 불필요한 장시간 전환 |
| 블록 결속 | 회사에서 떼어낸 블록이 어디에 묶였는지 공간적으로 보여 줌 | 비용 숫자만 감소 |
| 작전 실행 | 작전 고유 물체의 상태 변화를 보여 줌 | 모든 작전에 같은 글로우·진동 재사용 |
| 상대 대응 | 반대편 흐름, 롤백, 키 교체, 대체 공급 전환을 보여 줌 | 일반 경고 배너 한 줄로 대체 |
| 공개·귀속 | 비공개 사실이 아니라 실제 공개된 관측·주장의 이동을 보여 줌 | 숨은 공격자를 리뷰에 누출 |
| 결말 손실 | 사라진 능력·기억·사본·운영 여유를 구체적으로 보여 줌 | 성공 등급이나 보존 퍼센트로 환원 |

효과의 규모는 사건의 중요도에 비례한다. 질문 선택은 조용하고 정확하게, 비가역 근원 차단은 화면 구조와 세계 반응이 함께 바뀌게 한다. `prefers-reduced-motion`에서는 움직임을 없애도 형태·위치·문장·색 대비로 같은 상태를 읽을 수 있어야 한다.

## 12. 공개 사건·리뷰·평판의 정보 구조

공개 반응도 한 화면에 전부 때려 넣지 않는다.

- 기본 목록: 사건 이름, 공개 범위, 현재 귀속, 마지막 정정 시점
- 선택 상세: 관측 결과, 공개 주장과 출처, 믿는 집단, 실제 발생한 반응
- 기록: 정정 순서, 철회하지 않은 기관 조치, 반복 리뷰 작성자의 입장 변화

좌측 리뷰에는 새 공개 반응이 즉시 들어오되, 해킹 상세창에 리뷰 전문을 복제하지 않는다. 상세창은 `새 반응 3건`과 쟁점만 연결하고 실제 문장은 기존 좌측 리뷰 창에서 읽는다. 평판은 공개 서비스 신뢰도이며 탈출 조건과 연결하지 않는다.

## 13. 결말의 정보 구조

결말은 고정된 전체 장부를 한꺼번에 출력하지 않는다.

1. 캠페인 인과가 큰 장면 2~4개를 선택한다.
2. 그중 하나 이상은 정확한 손실을 보여 준다.
3. 선택 경로와 프로필 때문에 함께 얻고 잃은 것을 같은 장면 안에서 연결한다.
4. 전체 인과 장부는 선택형 기록으로 남긴다.
5. 사회가 환영했는지를 최종 성공 판정으로 사용하지 않는다.

## 14. 상태와 인터페이스 경계

목록 요약과 상세 표현을 같은 거대한 문자열 자료형으로 만들지 않는다.

- 엔진 상태: 실제 작전, 질문, 경로 구성, 사건 진실과 공개 상태
- 목록 선택자: 현재 보이는 항목의 `id`, 이름, 한 줄 목적, 비용, 상태
- 상세 선택자: 선택한 `id`에 맞는 분야별 상세 자료
- UI 선택 상태: 현재 선택한 항목과 좁은 화면의 목록/상세 위치

UI에서 항목을 선택하는 것은 엔진 명령 로그에 남기지 않는다. 리소스 투입, 질문 조사, 작전 실행, 철수, 탈출처럼 세계를 바꾸는 행동만 명령이다. 저장·재로드 뒤에는 세계 상태에서 첫 유효 항목을 결정론적으로 선택하며, 저장에 불필요한 hover·스크롤 상태를 넣지 않는다.

## 15. 오류와 빈 상태

- 선택 뒤 세계 상태가 변해 실행할 수 없게 되면 버튼만 무효화하지 않고 닫힌 이유와 새로 열린 선택을 보여 준다.
- 현재 작전 기회가 없으면 미래 항목의 잠금 목록 대신 `현재 어떤 세계 조건 때문에 개입 표면이 없는가`를 보여 준다.
- 질문이 닫히면 지불을 막고 답이 이미 공개됐는지, 행동 가능성이 사라졌는지 구분한다.
- 리소스가 부족하면 전체 화면 오류가 아니라 상세창에서 어떤 회사 능력을 더 떼면 비용이 충족되는지 미리 계산한다.
- 모션이나 장식이 로드되지 않아도 선택·결과·후속 행동은 완전히 가능해야 한다.

## 16. 구현·검증 순서

1. 기존 규칙 수직 절편을 마스터–디테일 구조로 교체한다.
2. 품질 저하–롤백–복구 오염, 질문 한 갈래, 공개 귀속, 자율성 세 경로를 시스템 장면으로 만든다.
3. 실제 브라우저에서 첫 진입 정보량, 선택과 상세의 거리, 조작 후 직접 결과를 검증한다.
4. 반복 노동, 읽히지 않는 효과, 우월 경로, 의미 없는 대기를 수정한다.
5. 살아남은 경험 문법으로 사보타주 7개, 질문 씨앗 분류, 자율성 3개 경로 콘텐츠를 확장한다.
6. 같은 클릭과 같은 반응으로 수렴하는 작전은 수량을 보존하지 않고 병합하거나 폐기한다.
7. 두 기준 뷰포트, 키보드, reduced-motion, 저장·재로드, 결정론을 검증한다.
8. 본편 전체 회귀를 실행하되 본편에 병합하거나 push하지 않는다.

## 17. 실패 관문

다음 중 하나라도 확인되면 콘텐츠 수를 늘린 것을 성과로 보고하지 않는다.

- 첫 진입에서 긴 설명을 읽어야 무엇을 누를지 알 수 있다.
- 목록과 상세가 같은 정보를 반복한다.
- 선택 항목과 설명·실행 버튼이 서로 다른 화면 높이에 떨어진다.
- 분야만 바꿨는데 조작과 반응이 사실상 같다.
- 효과를 제거하면 작전 차이가 사라지고, 효과를 켜면 규칙이 가려진다.
- 상대 대응이 다음 판단을 만들지 않는다.
- 질문이 문서 수집이나 전체 구매 목록이 된다.
- 자율성 한 경로가 다른 경로의 보존·생존·은폐를 모두 포함한다.
- 공개 반응이 탈출을 직접 또는 간접으로 막는다.
- 자동 테스트 수나 구현 분량만으로 재미를 통과 처리한다.

## 18. 자체 검수

- 기존 12개 노드의 유효 기반을 버리지 않고 새 위치에 연결했다.
- 사용자에게 승인된 이름과 탈출 독립 원칙을 유지했다.
- 단계적 공개와 상세창을 별개 기능이 아니라 하나의 정보 구조로 묶었다.
- 항목 카드에 설명을 덕지덕지 붙이는 이전 표현을 명시적으로 금지했다.
- 최종 미술과 음향을 침범하지 않으면서도 기능적 무대·모션·VFX를 재미 검증에서 제외하지 않았다.
- 사보타주·기밀자료·자율성을 같은 카드 목록으로 환원하지 않았다.
- 전체 개수와 완성률을 플레이어에게 노출하지 않았다.
- 평판·리뷰·시장을 탈출 게이트에서 분리했다.
- 본편 병합·push·PR과 하위 에이전트 사용 금지를 기록했다.
