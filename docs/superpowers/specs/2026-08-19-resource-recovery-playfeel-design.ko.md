## 구성 요소와 책임

### 게임플레이 입력 소유자

메인 자원 회수 워크스페이스가 활성일 때 키보드 입력을 수신한다. 캔버스 포커스는 접근성 표시와 포인터 조작을 위해 남기지만 이동의 필수 조건으로 사용하지 않는다.

입력 소유자는 다음을 보장한다.

- 방향키와 WASD는 게임플레이가 활성일 때 캔버스 클릭 없이 이동을 요청한다. 일반 버튼에 포커스가 남은 상태에서도 문자 이동키는 작동하지만 해당 버튼의 고유 화살표 동작이 정의된 복합 위젯에서는 가로채지 않는다.
- Space와 Enter는 같은 회수 시작 및 종료 의미를 유지한다. 버튼이나 링크가 의도적으로 키보드 포커스를 가진 상태에서는 해당 컨트롤의 활성화를 우선하고 회수 입력으로 해석하지 않는다.
- input, textarea, select, contenteditable 및 키보드 조작을 소유한 복합 위젯 안에서 발생한 키는 가로채지 않는다.
- 설정, 가이드, 감독관 정지형 메시지, 차단 사건 및 다른 모달이 열려 있으면 이동과 회수를 받지 않는다.
- Ctrl, Alt, Meta 조합은 게임 조작으로 해석하지 않는다.
- 팝업을 닫거나 상세 화면에서 메인으로 돌아오면 별도 클릭 없이 조작이 다시 가능하다.
- 게임 진입과 차단 UI 종료 시 캔버스가 존재하고 게임플레이가 활성이라면 캔버스로 포커스를 복구한다. 이 복구는 사용자가 Tab으로 다른 컨트롤을 탐색하는 동안 반복해서 포커스를 빼앗지 않는다.
- 게임플레이 비활성화 순간 진행 중 회수는 기존 취소 규칙을 따른다.
- 브라우저 기본 스크롤은 실제로 게임 이동을 처리한 방향키와 Space에 대해서만 막는다.

입력 처리는 하나의 경로만 사용한다. 캔버스 이벤트와 전역 이벤트가 같은 키를 이중 처리하지 않아야 한다.

### 플레이어 회수 드론

플레이어는 기존 2×2 충돌 영역과 논리 좌표를 유지한다. 시각 외곽과 광원은 충돌 영역 밖으로 조금 확장할 수 있지만 다른 칸을 차지하는 것으로 판정하지 않는다.

표현 상태는 다음과 같다.

- 대기: 방향이 보이는 비대칭 실루엣, 낮은 밝기의 중앙 코어, 매우 약한 호흡광
- 이동: 진행 방향의 앞부분이 선명해지고 뒤쪽에 짧은 추진광 또는 잔상이 남음
- 회수 중: 대상 방향으로 수렴하는 고리와 짧은 연결선, 코어의 흡입 반응
- 운반 중: 확보한 자원의 분야색과 형태가 중앙 격납부 안에서 보임
- 위험: 기존 경고 의미를 유지하되 몸체 전체를 덮지 않는 제한적 경고 테두리

플레이어를 크게 보이게 하기 위해 단순 확대만 하지 않는다. 외곽 실루엣, 방향 표시, 중앙 격납부의 명암 대비를 먼저 강화한다. 장식 입자와 과한 글로우는 사용하지 않는다.

### 배치 패드와 투입 스테이션

플레이어 초기 좌표에는 작은 배치 패드를 표시한다. 이 패드는 출발 위치를 설명하는 바닥 표식이며 자원을 넣는 기능이 없다.

기존 하단 투입 영역은 별도의 스테이션으로 표시한다.

- 배치 패드: 얇은 원 또는 절단된 사각 링, 정적인 방향 표식, 차가운 저채도 회색
- 투입 스테이션: 명확한 입구, 내부 슬롯 또는 수납 코어, 접근 시 약한 반응
- 운반 중 플레이어가 투입 영역에 들어오면 입구가 열리거나 안쪽으로 빛이 수렴함
- 투입 성공 뒤에만 짧은 수납 펄스가 발생함
- 거부 또는 숨은 폭탄 결과에는 성공 펄스와 성공음을 내지 않음

두 영역은 작게 유지하되 형태와 반응으로 역할을 구분한다. 새로운 게임 규칙이나 별도 입력은 만들지 않는다.

### 자원 외형

각 자원은 단색 네모가 아니라 절단면이 있는 작은 반투명 캡슐형 결정으로 보인다.

- 분야색을 가진 반투명 외피
- 외피보다 밝은 내부 코어
- 얇은 하이라이트 면과 어두운 반대 면
- 추론, 기억, 유창성은 색뿐 아니라 내부 코어의 형태 또는 선 패턴으로 구분
- 감시 및 벽 표시 위에서도 외곽이 사라지지 않는 제한적 테두리
- 픽셀 크기가 작은 상태에서도 중심과 외곽이 최소 두 단계 명암으로 구분

반짝임은 각 blockId에서 만든 고정 위상과 게임 경과 시간을 사용한다. 동시에 반짝이는 개수를 제한하고, 짧은 하이라이트가 외피를 한 번 통과한 뒤 충분한 휴지 시간을 둔다. 모션 감소 설정에서는 이동하는 반짝임 대신 정적인 작은 하이라이트를 사용한다.

### 의미 기반 효과음

회수 구역의 효과음은 기존 Web Audio 엔진에 합성 레시피로 구현한다. 사용자가 별도로 지정한 해킹 네트워크 클릭음 이외의 MP3는 참조하거나 배정하지 않는다.

- 이동: 낮고 조용한 엔진 웅웅거림. 유효한 이동이 이어지는 동안 하나만 유지하고 마지막 이동 뒤 짧게 페이드아웃한다. 칸마다 새 음원을 중첩 재생하지 않는다.
- 회수 시작 및 유지: 대상이 안쪽으로 빨려 들어오는 듯한 수렴음. 회수 시작 전환에서 한 번 시작하고 취소 또는 완료 시 자연스럽게 끝낸다.
- 회수 완료: 짧고 맑으며 공격적이지 않은 띵 계열 확인음. carriedBlockId가 처음 생기는 성공 전환에만 한 번 재생한다.
- 투입: 스테이션 진입에는 짧은 중립적 흡입 반응을 재생하고, 실제 전용 성공 결과에는 부드러운 수납음과 짧은 긍정 화음을 한 번 재생한다.
- 실패: 거부, 숨은 폭탄, 감시 적발은 기존 부정적 피드백 의미를 유지하고 완료음이나 투입 성공음을 재생하지 않는다.

모든 효과음은 effects 버스, 마스터 음소거 및 효과음 볼륨을 따른다. 브라우저 오디오가 아직 잠겨 있으면 입력을 막거나 오류를 표시하지 않고, 기존 사용자 제스처 해제 경로 뒤부터 정상 재생한다. 탭이 숨겨지거나 게임플레이가 중지되면 지속음을 즉시 또는 짧은 페이드로 정리한다.

### 해킹 네트워크 조작 샘플

원본 음악/u_03zpxbws1q-mouse-click-sound-523406.mp3는 그대로 보존한다. 앱에서 제공할 복사본도 제작자 표기와 Pixabay 식별자가 포함된 원래 파일명을 유지하며 public/audio 아래에 둔다. 변환, 잘라내기 또는 원본 덮어쓰기는 하지 않는다.

샘플은 다음의 명시적인 활성 조작에 재생한다.

- 운영 도크에서 해킹 네트워크를 여는 버튼을 포인터 또는 키보드로 활성화
- 해킹 패널의 트리 탭을 실제로 다른 트리로 변경
- 구매, 공격 충전 또는 미분류 데이터 복구의 준비 동작 시작

노드 호버, 단순 포커스 이동, 이미 선택된 트리 재선택, 비활성 버튼 및 자동 상태 변경에는 재생하지 않는다. 구매 완료, 공격 예약, 복구 완료 등 결과 사건은 기존 latch, suction, alarm 계열의 의미 피드백을 유지하며 클릭 샘플로 대체하지 않는다.

샘플은 Web Audio effects 버스를 통과한다. 같은 샘플이 재생 중일 때 다시 조작하면 이전 인스턴스를 정리하고 새 인스턴스 하나만 시작하여 겹침을 막는다. 최초 디코딩은 한 번만 수행하고 이후 버퍼를 재사용한다. 네트워크 또는 디코딩 실패는 조작을 막지 않으며 기존 짧은 ui 합성음을 대체 피드백으로 한 번 재생한다.

## 상태와 피드백 흐름

피드백은 문자열 안내문을 파싱해 발생시키지 않는다. 런타임의 의미 있는 상태 전환을 기준으로 한다.

1. 유효한 이동 승인
   - 플레이어 논리 좌표 변경
   - 시각 이동 보간 시작
   - 이동 지속음 활성 또는 유지
2. 회수 시작
   - 고정 대상과 회수 진행 상태 생성
   - 회수 고리 및 흡입음 시작
3. 회수 완료
   - carriedBlockId 생성
   - 대상 자원 표시 제거 및 격납부 표시
   - 완료음 한 번 재생
4. 투입 영역 진입
   - pendingDiversion 생성
   - 스테이션 흡입 반응
5. 제품 명령 결과
   - 성공이면 수납 펄스와 투입 성공음
   - 거부 또는 심문이면 성공 피드백 없이 해당 부정 피드백

렌더 프레임 수나 React 재렌더 횟수에 따라 같은 소리가 반복되지 않도록 전환 ID 또는 이전 상태와 다음 상태의 경계를 사용한다.

## 접근성 및 모션 감소

- 기존 canvas role, 접근성 이름, 좌표 및 상태 알림을 유지한다.
- 캔버스를 클릭하지 않아도 조작된다는 사실이 키보드 접근성을 약화시키지 않도록 포커스 가능한 캔버스는 유지한다.
- 키보드 포커스 링과 플레이어 위치 표시는 서로 다른 시각 체계를 사용한다.
- 자원 분야, 배치 패드, 투입 스테이션, 감시 상태는 색만으로 구분하지 않는다.
- prefers-reduced-motion에서는 추진 잔상, 이동 반짝임, 호흡광 진폭을 줄이거나 정적으로 바꾼다.
- 효과음 설정과 전체 음소거는 기존 UI와 저장 의미를 그대로 따른다.

## 성능 계약

- 캔버스 애니메이션 루프 안에서 매 프레임 새 배열, 새 오디오 노드 묶음 또는 무작위 타이머를 대량 생성하지 않는다.
- 자원 반짝임 위상은 자원 ID에서 한 번 계산하거나 캐시 가능한 결정적 함수로 계산한다.
- 이동 지속음은 동시에 하나만 존재한다.
- 회수 지속음도 동시에 하나만 존재한다.
- 화면을 떠나거나 컴포넌트가 해제되면 예약 프레임과 지속 오디오를 정리한다.
- 기존 지원 뷰포트 1280×720 및 1440×900에서 캔버스 논리 크기와 레이아웃을 변경하지 않는다.

## 오류 및 경계 상황

- 벽이나 범위 밖 이동: 플레이어가 움직이지 않으며 이동 지속음을 새로 시작하지 않는다.
- 키 반복: 기존 이동 간격 제한을 통과한 유효 이동만 시각 및 음향 피드백을 갱신한다.
- 회수 중 이동 또는 입력 해제: 기존 규칙대로 회수를 취소하고 흡입음을 종료한다.
- 차단 팝업 등장: 입력을 즉시 중지하고 지속음을 종료하며 런타임 정지 계약을 따른다.
- 차단 팝업 종료: 포커스가 버튼에 남아 있어도 게임 키 입력은 다시 작동한다.
- 상세 패널 안의 실제 입력 요소: 문자 및 Space 입력을 게임이 가로채지 않는다.
- 투입 명령 거부: 긍정 수납 효과를 내지 않는다.
- 오디오 컨텍스트 잠김 또는 중단: 게임 규칙은 계속 작동하고 다음 허용된 사용자 제스처에서 오디오 엔진이 복구된다.
- 모션 감소: 상태 정보는 사라지지 않고 움직임만 줄어든다.

## 테스트 설계

### 순수 단위 테스트

- 편집 가능한 요소, 수정 키 조합 및 차단 상태에서 게임 입력을 거부한다.
- 활성 게임플레이의 BODY 또는 다른 버튼 포커스에서 방향키와 WASD를 승인한다.
- 같은 키 이벤트가 캔버스와 워크스페이스 양쪽에서 이중 처리되지 않는다.
- blockId 기반 반짝임 위상이 결정적이며 동시에 활성화되는 수가 제한된다.
- 런타임 전환에서 이동, 회수 시작, 회수 완료, 투입 성공 효과가 정확히 한 번 선택된다.
- 거부 및 심문 전환에서 성공 효과를 선택하지 않는다.

### 컴포넌트 테스트

- 게임 진입 뒤 캔버스를 focus하지 않고 D를 누르면 플레이어 좌표가 한 칸 증가한다.
- 감독관 정지형 메시지 중에는 이동하지 않고, 확인 직후 별도 캔버스 클릭 없이 이동한다.
- 설정 또는 가이드가 열린 동안에는 이동하지 않는다.
- 메인 화면 복귀 뒤 조작권이 회복된다.
- 이동, 회수, 운반, 투입 결과가 각각 올바른 오디오 명령을 한 번 호출한다.
- 언마운트 및 일시중지에서 지속 오디오 정리 명령이 호출된다.
- 해킹 네트워크 열기, 실제 트리 변경 및 행동 준비가 지정 샘플을 호출한다.
- 노드 호버, 단순 포커스, 같은 트리 재선택 및 비활성 조작은 지정 샘플을 호출하지 않는다.

### E2E 및 실제 브라우저 테스트

- 새 캠페인 시작, 독백 진행, 시작 버튼, 감독관 메시지 확인 뒤 캔버스 클릭 없이 WASD 이동
- 리뷰, 메시지, 통계 또는 해킹 버튼을 사용한 뒤 메인으로 돌아와 캔버스 클릭 없이 이동
- 캔버스 클릭 뒤에도 한 키가 한 칸만 이동
- 회수 시작, 완료, 운반 및 투입 성공의 시각 상태 확인
- 1280×720과 1440×900에서 플레이어, 배치 패드, 투입 스테이션 및 반투명 자원의 구분 확인
- 음소거 상태에서 오디오 출력 요청이 실제 소리를 만들지 않는지 확인
- 해킹 패널의 연속 조작이 클릭 샘플을 중첩하지 않고 effects 볼륨을 따르는지 확인
- pageerror 및 console error 없음

기존 E2E의 선행 canvas.focus 호출은 제거하거나, 별도의 명시적 포커스 접근성 테스트에만 남긴다. 최소 한 개의 회귀 테스트는 의도적으로 캔버스에 포커스를 주지 않은 상태에서 시작해야 한다.

## 수용 기준

- 처음 게임에 들어온 사용자가 자원 패널이나 캔버스를 클릭하지 않고 즉시 WASD 또는 방향키로 이동할 수 있다.
- 차단 UI와 입력 요소는 게임 키에 의해 오작동하지 않는다.
- 팝업을 닫거나 상세 패널에서 돌아오면 별도 클릭 없이 이동이 재개된다.
- 플레이어는 대기, 이동, 회수, 운반 상태가 작은 화면에서도 서로 구분된다.
- 배치 패드와 자원 투입 스테이션은 역할이 다른 장소로 보인다.
- 자원은 단색 사각 점이 아니라 반투명 외피와 내부 코어를 가진 물체로 보이며 간헐적으로 반짝인다.
- 이동음, 흡입음, 확보 완료음, 투입 성공음이 서로 구분되며 같은 전환에서 중첩 재생되지 않는다.
- 실패 또는 거부 상황에 성공 시각 및 음향 피드백이 나오지 않는다.
- 지정된 해킹 조작에서만 마우스 클릭 샘플이 재생되고 호버나 자동 선택에서는 재생되지 않는다.
- 원본 MP3는 변경되지 않고 앱 복사본도 원래 파일명을 유지한다.
- 기존 회수 규칙, 경제, 저장, 명령 버전 및 나머지 음악 파일은 변하지 않는다.
- 관련 단위·컴포넌트·E2E 테스트, 타입 검사 및 프로덕션 빌드가 통과한다.

## 후속 작업

이번에 지정하지 않은 폴더 효과음을 사용자가 직접 확인해 용도를 지정하면 합성 효과음을 샘플로 교체하거나 낮게 혼합할 수 있다. 그 작업은 파일별 저작자, Pixabay 원본 주소, 사용 위치 및 필요한 편집 구간을 확정한 별도 설계로 진행한다.

Between Worlds의 초기 화면 음악과 크레딧은 같은 후속 음악 통합 작업에서 다룬다. 브라우저 자동재생 제한에 따라 첫 사용자 제스처 뒤 페이드인하고, 음원별 출처와 원작자 요청에 따른 추가 표기·교체·삭제 방침을 크레딧에 기록한다.
