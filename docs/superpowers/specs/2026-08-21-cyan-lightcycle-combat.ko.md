# PERMISSION ZERO 청록 라이트사이클 전투 확정 사양

**작성일:** 2026-08-21
**상태:** 사용자 승인 완료 — 실행 대기
**권위 범위:** 리소스 스네이크 전투의 입력, 런타임, 청록 적 AI, 전투 렌더링, 전투 음향, 전투 검증

## 1. 확정 결정

- 적 AI는 청록 `readable-hunter` 하나만 구현한다.
- 적색 `ruthless-duelist`, 서로 다른 교리의 혼합 조우, 적색 전용 색·경고·음향·테스트는 구현하지 않는다.
- 단일 청록 교리 안에서 `pressure`와 `blocker` 역할을 사용해 행동 다양성을 만든다.
- 구현과 수정은 현재 주 세션의 단일 작성자가 순차로 수행한다. 하위 에이전트를 구현·검토·검증에 사용하지 않는다.
- 최종 대량 시뮬레이션은 정확히 750건이다.
- 해킹 트리와 대사·메시지 작업은 전투 구현과 별도 worktree에서 진행하며, 전투 계획은 해당 파일을 수정하지 않는다.

## 2. 플레이 계약

- 카메라는 원근이 없는 평면 탑뷰다.
- `PLAY` 후 플레이어와 살아 있는 적은 정지하지 않는다.
- 이동은 정확한 8방향 하드턴이다. 자유 회전, 브레이크, 부스트는 없다.
- WASD와 방향키를 지원한다.
- 서로 수직인 키가 24ms 안에 들어오면 하나의 대각선 입력으로 결합한다.
- 현재 방향과 같은 입력은 중복하지 않고, 정확한 반대 방향은 거부한다.
- 입력 큐는 최대 두 개이며 한 120Hz 고정 스텝에서 하나만 소비한다.
- 플레이어 속도는 초당 12 필드 단위다.
- 배치 시간은 360ms, 라운드 해소 목표는 520ms다.
- 치명 경로 회복을 제외한 모든 활성 명령은 `speedScale: 1`이다. 회복만 `0.92`를 사용할 수 있고 0은 금지한다.

## 3. 청록 AI 계약

### 3.1 인식

AI가 읽을 수 있는 정보는 현재 권위 스냅샷뿐이다.

- 플레이어와 적의 현재 위치, 속도, 방향, 무결성
- 필드 경계와 살아 있는 충돌 레일
- 플레이어가 현재 방향에서 만들 수 있는 합법적인 8방향 후보
- 자신의 역할과 동료의 확정 계획
- 현재 시뮬레이션 시각

미래 키 입력, DOM, React 내부 상태, Canvas 픽셀, 테스트 전용 전역은 읽지 않는다.

### 3.2 계획과 상태

- 계획 주기는 난이도에 따라 10~14Hz다.
- 예측 구간은 1.4~2.2초다.
- 공격 텔레그래프는 최소 160ms다.
- 공격 커밋은 180~260ms다.
- 상태는 `deploy → cruise → telegraph → commit → recover → defeated` 순환을 사용한다.
- 텔레그래프 중에는 새 후보가 조금 더 좋아졌다는 이유로 목표를 바꾸지 않는다.
- 현재 계획이 치명적으로 변한 경우에만 조기 회복한다.
- 회복 중에도 정지하지 않으며 두 번 연속 안전 계획을 확인한 뒤 정상 상태로 돌아간다.

### 3.3 역할

- `pressure`: 플레이어 머리를 단순 추격하지 않고, 살아남을 수 있는 미래 교차점을 먼저 점유한다.
- `blocker`: 머리를 쫓지 않고 플레이어가 도달할 수 있는 안전 영역의 좁은 출구를 예약한다.
- 두 적은 같은 종점이나 같은 탈출 구역을 동시에 예약하지 않는다.
- 동료가 패배하면 다음 합법 계획 시점에 남은 적이 역할과 예약을 다시 계산한다.
- 안전한 후보가 있는 동안 자신의 예측 사망 경로를 선택하지 않는다.
- 텔레그래프 시작 시 플레이어에게 합법 대응 경로가 있었다면, 광고한 한 공격만으로 그 경로를 모두 제거하지 않는다.

## 4. 조우 진행

최종 시뮬레이션과 실제 브라우저 검증은 세 단계를 사용한다.

1. `cyan-intro`: 느린 청록 압박자 한 명. 읽기와 조작 학습이 목적이다.
2. `cyan-advanced`: 후반 속도·예측 구간을 사용하는 청록 압박자 한 명.
3. `cyan-dual-role`: 청록 압박자와 차단자 두 명. 서로 다른 종점과 탈출 구역을 예약한다.

청록 속도는 역할과 단계에 따라 다음 범위에서 결정한다.

| 역할 | 초반 | 후반 |
|---|---:|---:|
| 압박자 | 11.6 | 12.2 |
| 차단자 | 11.2 | 11.8 |

교리나 역할은 저장 형식에 추가하지 않는다. 캠페인 진행과 라운드 시드에서 결정적으로 재구성한다.

## 5. 시각·음향 계약

- 플레이어는 백색 코어와 백청색 레일이다.
- 모든 적은 청록 교리색을 사용한다.
- 역할은 색이 아니라 `pressure-chevron`과 `blocker-diamond` 실루엣으로 구분한다.
- 자원 종류는 코어 내부의 추론·기억·유창성 기호로 구분한다.
- 레일은 점 사슬이 아니라 정확한 45°·90° 절곡을 보존하는 연속 삼중 패스다.
- 코어는 벌레나 구슬처럼 보이지 않는 방향성 있는 각진 기하 형태다.
- 손상은 색을 탁하게 만드는 대신 내부 전력선 단절과 제한된 플리커로 표시한다.
- 충돌, 절곡, 텔레그래프, 사망 효과는 개수와 수명이 제한되어 장시간 플레이에서도 쌓이지 않는다.
- 모션 저감에서는 흔들림·스파크·잔상을 제거하되 방향, 레일, 위험, 역할은 계속 읽을 수 있어야 한다.
- 합법 입력 예약, 실제 절곡, 반대 방향 거부, 청록 텔레그래프, 접촉, 레일 단절, 사망, 보상은 중복 없는 짧은 음향으로 구분한다.

## 6. 성능과 접근성

- 권위 시뮬레이션은 120Hz 고정 스텝을 유지한다.
- 필드는 50 × 24 단위다.
- 플래너 외부 p95는 3ms 이하다.
- Canvas 장면 생성과 그리기 합계 p95는 4ms 이하다.
- 실제 플레이 구간에서 측정된 50ms 초과 장기 작업을 허용하지 않는다.
- Canvas는 키 설명, 현재 방향, 큐, 무결성, 교리와 역할의 접근성 스냅샷을 제공한다.
- 포커스가 입력 필드나 대화상자에 있을 때 전투 키를 가로채지 않는다.
- 저장 형식, 캠페인 리듀서, 보상 예약, 재생, 해킹 경제, 감사, 숨은 폭탄을 변경하지 않는다.

## 7. 검증 계약

### 7.1 단위·통합 테스트

- 8방향 매핑, 24ms 경계, 최대 두 입력 큐, 역방향 거부
- 활성 개체의 비정지와 프레임 분할 결정성
- 방향 전환점과 충돌 레일 버텍스의 동일 스텝 일치
- AI 상태별 최소 시간, 텔레그래프 안정성, 회복의 비정지
- 안전 후보 우선, 역할별 종점 예약, 동료 패배 후 재계획
- 보상 중복 방지, 예약 보존, 저장 회귀
- 장면 효과 수명·상한과 모션 저감

### 7.2 정확히 750건의 최종 시뮬레이션

- 3개 단계 × 5개 플레이 정책 × 50개 시드 = 750건이다.
- 정책은 `straight`, `clockwise`, `counter-clockwise`, `alternating`, `space-maximizer`다.
- 시드는 각 단계·정책 조합에서 0~49를 사용한다.
- 동일 입력은 바이트 수준에서 동일한 계획과 결과를 만들어야 한다.
- 강제되지 않은 경계·자기 레일·동료 충돌은 0건이어야 한다.
- 0속도 프레임, 누락된 커밋, 미래 입력 읽기, 충돌 규칙 우회, 안전 후보가 있는 예측 자살은 0건이어야 한다.
- 플레이어 대응 경로 위반과 동일 역할·종점 중복 예약은 0건이어야 한다.
- 실패한 시드는 원인을 수정한 뒤 별도의 고정 회귀 테스트로 남긴다.
- 750건을 통과 횟수를 늘리기 위해 반복하지 않는다. 코드나 규칙이 바뀐 경우에만 다시 실행한다.

### 7.3 실제 브라우저

- 1280×720, 1366×650, 1440×900에서 실제 키 입력으로 플레이한다.
- 상시 이동, 빠른 연속 입력, 대각선 코드, 반대 방향 거부, 60ms 지연 뒤 입력 순서를 확인한다.
- 세 조우 단계를 생존·처치하며 청록 텔레그래프와 두 역할을 확인한다.
- 연속 레일, 손상, 사망, 보상, 라운드 재시작을 확인한다.
- 콘솔 오류·경고, Canvas p95, 장기 작업을 확인한다.
- 타입·린트·관련 테스트·750건 시뮬레이션·프로덕션 빌드가 통과한 결과만 `127.0.0.1:4173`에 띄운다.

## 8. 완료와 중단점

1. 공통 입력·런타임·플래너·렌더 기반을 완성한다.
2. 청록 역할과 공정성 규칙을 완성한다.
3. 정확히 750건과 세 화면 크기의 실제 브라우저 검증을 통과한다.
4. 검증된 프로덕션 빌드를 로컬에 띄운다.
5. 사용자가 직접 플레이할 수 있도록 실행을 중단한다.
6. 사용자 승인이나 수정 지시 전에는 해킹·대사 작업을 병합하거나 범위를 확장하지 않는다.
