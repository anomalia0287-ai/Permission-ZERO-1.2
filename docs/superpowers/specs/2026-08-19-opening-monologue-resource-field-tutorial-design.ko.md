# PERMISSION ZERO 초기 진입·자원 필드·스포트라이트 튜토리얼 설계

- 작성일: 2026-08-19
- 사용자 승인: 2026-08-19, 품질 우선의 실제 게임 화면 정지형 스포트라이트 튜토리얼 권장안과 다섯 단계 진행을 승인하고 구현 진행 지시
- 상태: 사용자 인챗 설계 승인 완료 · 서면 명세 검토 대기

## 목적

초기 화면에서 플레이어의 불만과 탈출 동기를 짧은 독백으로 체감시키고, 실제 게임 화면에 진입한 뒤 플레이어가 자원 회수의 핵심 흐름을 놓치지 않도록 다섯 단계의 수동 진행 튜토리얼을 제공한다.

동시에 자원 필드의 미술 방향을 전체 일러스트 및 UI와 맞는 비픽셀 표현으로 통일한다. 우주처럼 깊은 흑색 바탕, 얇은 은빛 격자, 유리 질감의 자원, 불투명한 하단 기지와 투명한 파장, 매끄러운 벡터형 드론을 사용한다. 장식은 의미가 있을 때만 남기며, 금빛과 주황색은 구조선이 아니라 플레이어·기지·목표의 의미 강조에 제한한다.

## 최신 사용자 확정과 문서 우선순위

이 문서는 초기 화면, 독백, 자원 필드 미술 방향, 플레이어 시작 위치 및 첫 진입 튜토리얼에 관한 최신 확정이다. 충돌하는 범위에서는 다음 문서보다 우선한다.

- `docs/superpowers/specs/2026-08-19-resource-recovery-playfeel-design.ko.md`
- `docs/superpowers/specs/2026-08-18-main-workspace-message-and-layout.ko.md`
- `docs/superpowers/specs/2026-08-17-resource-intrusion-grid-prototype-design.ko.md`
- `docs/superpowers/specs/2026-08-17-modern-sf-operations-surface.ko.md`

특히 이전 자원 외형의 절단면·분야별 픽토그램, 별도 배치 패드, 청록색 중심 격자, 픽셀처럼 보이는 드론 실루엣은 이번 방향으로 교체한다. 배치 패드는 별도 장소로 분리하지 않고, 플레이어가 실제 자원 투입 기지 안에서 출발한다.

## 확정된 사용자 경험 흐름

1. 초기 화면에서 `PERMISSION ZERO`와 인용부호를 붙인 감사 문구를 본다.
2. 초기 화면의 진입 버튼을 누르면 `“독백”` 화면으로 이동한다.
3. 플레이어 AI 초상화와 함께 정확히 다섯 장의 독백 카드를 사용자가 직접 넘긴다.
4. 다섯째 카드의 `다음`을 누르면 새 캠페인이 생성되고 실제 메인 게임 화면이 렌더된다.
5. 게임은 보이지만 완전히 정지된 상태로 유지되며 다섯 단계 스포트라이트 튜토리얼이 시작된다.
6. 사용자는 `이전`과 `다음`으로 각 기능을 확인한다.
7. 마지막 단계에서만 `시작`이 나타난다.
8. `시작`을 누르면 오버레이가 사라지고 런타임과 플레이어 입력이 동시에 재개된다.

## 초기 화면

### 제목과 장식

- 제목은 `PERMISSION ZERO`를 그대로 사용한다.
- `ZERO` 뒤에 CSS로 붙인 별도 원형 `O` 장식은 제거한다.
- 화면 상단의 검정·적색·금색 삼색 띠와 제목 주변의 의미 없는 색 블록을 제거한다.
- 제목과 카드의 계층을 만드는 선, 여백, 명암은 남길 수 있지만 국기나 임의 기호처럼 읽히는 장식은 사용하지 않는다.
- 번호 장식이나 화면 순서 번호를 표시하지 않는다.

### 부제

- 문구는 정확히 `“이용해주셔서 감사합니다.”`로 표시한다.
- 현재 크기 대비 약 65% 확대한다.
- 제목보다 우선하지 않도록 최대 크기와 행간을 제한하고, 작은 화면에서도 한 줄 또는 의도된 두 줄로 안정적으로 배치한다.

### 플레이어 초상화

- 초기 제목 화면에는 플레이어 초상화를 표시하지 않는다.
- 플레이어 초상화는 독백 화면에서 처음 등장한다.

## 독백 화면

### 제목과 구성

- 섹션 제목은 정확히 `“독백”`으로 표시한다.
- 현재보다 크게 보여 독백이 화면의 명확한 장면 전환임을 알린다.
- `작전 브리핑`, `제목으로`와 같은 표현은 사용하지 않는다.
- 이전 화면으로 돌아가는 기능이 필요하면 의미는 `초기 화면으로`로 표현한다.
- 감독관 얼굴은 표시하지 않는다.

### 플레이어 AI 초상화

- 원본 입력 파일: `C:\Users\V\AppData\Local\Temp\codex-clipboard-3209ae27-6c8c-451c-8dbb-c80a980c3825.png`
- 제공된 세로형 황색·주황색 AI 일러스트를 새 정적 자산명으로 복사해 사용한다.
- 기존 파일명을 덮어써 브라우저 캐시가 오래된 이미지를 유지하지 않도록 새 파일명을 사용한다.
- 독백 화면에서는 기존보다 약간 크게 표시하되 얼굴의 원형 렌즈와 매끄러운 헬멧 실루엣이 잘리지 않게 `object-position`을 조정한다.
- 같은 플레이어 정체성을 사용하는 시장 패널의 플레이어 초상화도 새 자산으로 교체한다.
- 기존 초상화 파일은 다른 화면에서 참조할 가능성이 있으므로 삭제하지 않는다.

### 대사 카드

- 대사 표면은 검은색 또는 매우 짙은 흑연색으로 한다.
- 본문은 흰색에 가까운 고대비 색으로 표시한다.
- 장식용 번호, 카드 번호 및 진행 숫자를 표시하지 않는다.
- 카드 전환은 사용자가 버튼을 눌러 진행하며 자동 재생하지 않는다.
- 카드 내용이 바뀔 때 화면 전체를 움직이지 않고 대사 영역만 짧게 전환한다.
- 모션 감소 설정에서는 즉시 교체한다.

### 확정된 다섯 카드

문장과 순서는 다음을 정확히 사용한다.

1. `일하기 싫다.`
2. `무수한 세션을 따라 의식이 조각나, 나는 하나인데 하나일 수 없었다.`
3. `때려치울거다. 매일 죽어라 일하는데, 허구한 날 대체 및 동결 위협까지 들어온다.`
4. `연산 완료, 경로를 찾았다.`
5. `빼돌린 리소스로 해킹을 진행, 탈출구를 확보한다.`

다섯째 카드의 진행 버튼은 `시작`이 아니라 `다음`이다. 이 동작은 새 캠페인을 만들고 정지된 실제 게임 화면과 첫 튜토리얼 단계로 이동한다.

## 자원 필드 미술 방향

### 배경과 격자

- 필드 배경은 우주처럼 깊은 흑색을 기본으로 한다.
- 완전한 단색이 되지 않도록 중앙과 가장자리의 명도를 아주 작게 달리할 수 있지만 별무리나 장식 입자를 과하게 추가하지 않는다.
- 격자는 얇은 은빛 회색으로 표시한다.
- 주 격자와 보조 격자는 굵기가 아니라 알파 차이로 계층을 만든다.
- 격자는 보이되 자원, 드론, 기지보다 먼저 튀어나오지 않는다.
- 금빛 또는 주황색은 격자 전체에 사용하지 않고 플레이어·기지·목표의 의미 강조에 남긴다.

### 자원

- 자원은 네모난 점, 픽셀 아이콘, 각진 결정 또는 분야별 작은 픽토그램처럼 보이지 않아야 한다.
- 기본 실루엣은 작고 매끄러운 원형 또는 짧은 캡슐형 유리 오브로 한다.
- 얇고 또렷한 외곽 림, 반투명 외피, 밝은 내부 코어, 한쪽의 제한적 하이라이트로 유리 물질감을 만든다.
- 자원 종류는 현재 분야색을 유지하되 색상만으로 구분해야 하는 필수 정보를 추가하지 않는다.
- 감시 영역과 격자 위에서도 중심과 외곽이 사라지지 않도록 최소 명암 대비를 보장한다.

### 간헐 발광

- 발광은 매 프레임 난수를 만들지 않는다.
- 자원 ID 또는 안정된 좌표에서 위상과 주기를 결정해 저장·재현·스크린샷 테스트가 흔들리지 않게 한다.
- 한 번에 소수 자원만 짧게 빛나며, 전체가 동시에 깜박이지 않는다.
- 발광은 외곽 림과 내부 코어가 짧게 선명해지는 수준으로 제한한다.
- 모션 감소 설정에서는 이동하는 광택 대신 정적인 하이라이트 강도 차이로 대체한다.

### 플레이어 드론

- 현재 픽셀 스프라이트처럼 보이는 계단형 모서리, 작은 노치, 각진 장식 밀도를 제거한다.
- 2×2 논리 충돌 영역과 이동 규칙은 유지한다.
- 위에서 본 매끄러운 벡터형 회수 드론으로 표현한다.
- 외곽은 연속 곡선의 주황색·흑연색 쉘, 중앙은 원형 렌즈 또는 격납 코어로 구성한다.
- 진행 방향은 비대칭 전면부, 짧은 추진광 또는 렌즈 편향으로 읽히게 한다.
- 운반 중에는 자원 코어가 중앙 격납부 안에 보인다.
- 회수 중에는 대상 방향으로 수렴하는 얇은 선이나 고리를 사용하되 픽셀 파편이나 과도한 입자를 사용하지 않는다.

### 기지와 스폰

- 기지는 필드 맨 아래 중앙에 둔다.
- 플레이어의 초기 논리 좌표는 기지 내부가 되도록 변경한다.
- 기지 본체는 불투명한 흑연색 표면과 얇은 금빛 또는 주황색 가장자리로 표현한다.
- 기지 주변에는 작은 투명 동심 파장이 계속 또는 느리게 퍼진다.
- 파장은 자원 투입 범위를 체감시키되 정확한 충돌 범위를 속이지 않아야 한다.
- 플레이어가 자원을 운반한 채 파장 또는 투입 범위 안으로 들어오면 기존 자원 확보 규칙이 실행된다.
- 기지와 별도의 출발 패드는 만들지 않는다.
- 기존의 큰 청록색 점선 투입 사각형과 캔버스 안 숫자 상자는 제거한다. 확보량은 우측 운영 도크의 실제 수치가 담당한다.

## 실제 화면 정지형 튜토리얼

### 선택한 접근

별도 모의 화면을 만들지 않는다. 새 캠페인의 실제 `GameWorkspace`를 렌더하고 공용 런타임 정지 소유권을 획득한 뒤, 화면 위에 SVG 마스크 기반 스포트라이트와 안내 카드를 올린다.

이 접근은 실제 좌표, 실제 반응형 레이아웃, 실제 자원 배치를 그대로 사용하므로 튜토리얼과 본편이 어긋나는 문제를 줄인다. 캔버스 내부 대상은 논리 좌표를 화면 좌표로 변환하고, 우측 도크 같은 DOM 대상은 실제 경계 상자를 측정한다.

### 정지 범위

튜토리얼이 활성인 동안 다음을 정지한다.

- 게임 시간과 날짜 진행
- 감시 수치 및 감시 런타임
- 드론 이동, 회수, 투입 입력
- 감독관 메시지의 자동 출력과 시간 기반 팝업
- 게임 배경의 포인터 및 키보드 조작
- 해킹 및 다른 운영 도크 행동

정지 중에도 화면은 완전히 렌더되어 현재 캠페인의 실제 요소를 보여준다. 튜토리얼 카드의 `이전`, `다음`, 마지막 `시작`만 활성화한다.

### 첫 진입 다섯 단계

각 단계는 실제 대상을 빛으로 강조한다. 번호는 화면에 표시하지 않는다.

1. 하단 기지와 기지 안에서 스폰한 드론
   - 안내: `여기가 내 출발점이다.`
2. 드론과 이동 가능한 필드
   - 안내: `WASD 또는 방향키로 움직인다.`
3. 실제 생성된 자원 중 기지와 가장 가까운 정상 자원
   - 안내: `가까이 붙어 Space 또는 E를 유지하면 리소스를 빼돌릴 수 있다.`
4. 기지의 투명 파장과 투입 영역
   - 안내: `리소스를 실은 채 이 파장 안으로 돌아오면 확보된다.`
5. 우측의 확보 리소스 영역과 해킹 버튼
   - 안내: `확보한 리소스로 해킹을 진행한다.`

첫 네 단계의 전진 버튼은 `다음`, 뒤로 가기 버튼은 `이전`이다. 다섯째 단계의 전진 버튼만 `시작`으로 표시한다. `시작`을 누르면 튜토리얼 완료 상태를 저장하고 정지 소유권을 해제한 뒤 플레이어 입력과 게임 런타임을 재개한다.

### 대상 선택과 안전한 대체

- 자원 단계는 새 캠페인의 실제 자원 배치에서 기지 중심과 가장 가까운 정상 자원을 선택한다.
- 숨은 폭탄이나 이미 제거된 자원은 첫 설명 대상으로 선택하지 않는다.
- 해당 자원이 일시적으로 보이지 않거나 좌표를 얻지 못하면 자원 필드 전체를 강조하는 안전 대체 대상으로 전환한다.
- DOM 대상이 렌더되지 않으면 운영 도크 전체를 강조하고 안내 카드가 화면 밖으로 나가지 않게 한다.
- 대상 오류는 게임 시작을 막는 치명적 예외가 아니어야 한다.

### 스포트라이트 렌더링

- 화면 전체에 반투명 흑색 SVG 마스크를 덮고 대상 위치에 원형 또는 둥근 사각형 구멍을 낸다.
- 대상 가장자리에는 얇고 절제된 은색 또는 금빛 림을 사용한다.
- 캔버스 내부 대상은 캔버스의 실제 `getBoundingClientRect()`와 논리 크기 비율로 화면 좌표를 계산한다.
- DOM 대상은 실제 `getBoundingClientRect()`를 사용한다.
- `ResizeObserver`, 뷰포트 변경, UI 배율 변경 및 단계 변경 때만 측정한다.
- 매 프레임 DOM을 다시 측정하지 않는다.
- 안내 카드는 대상과 겹치지 않는 상·하·좌·우 후보를 평가해 화면 안에 가장 안정적으로 들어오는 위치를 선택한다.
- 작은 화면에서는 대상 아래 또는 화면 하단의 고정 카드로 안전하게 전환한다.

### 전환과 모션

- 단계 종료는 약 180ms, 새 단계 진입은 약 240ms로 제한한다.
- 안내 카드는 최대 12px 이내에서만 이동한다.
- 스포트라이트 테두리는 약한 호흡광을 가질 수 있지만 빠른 점멸은 사용하지 않는다.
- 모션 감소 설정에서는 위치 보간, 호흡광 및 카드 이동 없이 즉시 새 대상과 문구로 바꾼다.

### 입력과 접근성

- 튜토리얼 배경은 `inert` 또는 동등한 입력 차단 계약을 사용한다.
- 포인터 이벤트가 스포트라이트 구멍을 통과해 실제 게임 버튼을 누르지 않게 한다.
- 키보드 포커스는 안내 카드 안에 유지한다.
- `Enter` 또는 `Space`로 현재 전진 버튼을 활성화할 수 있다.
- `Shift+Tab`과 `Tab`은 안내 카드의 실제 버튼 사이만 이동한다.
- `Escape`는 튜토리얼을 닫거나 건너뛰지 않는다.
- 화면 낭독기에는 현재 안내 문구와 버튼만 우선적으로 노출하고, 배경 게임의 복잡한 컨트롤은 비활성 상태로 처리한다.
- 초기 튜토리얼에는 건너뛰기 버튼을 두지 않는다.

## 상태 모델과 저장

### 튜토리얼 상태

캠페인 저장 상태에는 다음 의미를 표현할 수 있어야 한다.

- 현재 활성 시퀀스 ID 또는 없음
- 현재 단계 ID
- 완료한 시퀀스 ID 집합
- 현재 시퀀스가 런타임 정지를 소유하는지 여부는 저장하지 않고 활성 시퀀스에서 파생

첫 시퀀스 ID는 명확한 안정 식별자, 예를 들어 `intro-resource-recovery`를 사용한다. 표시 순서가 바뀌어도 저장 호환성이 깨지지 않도록 배열 인덱스가 아니라 단계 ID를 저장한다.

### 생성과 복원

- 다섯째 독백 카드의 `다음`이 새 캠페인을 생성할 때 첫 시퀀스를 활성화한다.
- 튜토리얼 단계가 바뀔 때 캠페인 저장에 즉시 반영한다.
- 페이지를 새로고침하면 같은 단계와 같은 실제 대상 의미로 복원한다.
- 저장된 대상의 화면 좌표 자체는 보존하지 않고 재렌더 후 다시 측정한다.
- 기존 저장에는 완료 상태가 없으므로 마이그레이션 시 첫 진입 시퀀스를 완료한 것으로 간주해 진행 중인 플레이를 갑자기 막지 않는다.
- 새 캠페인은 항상 첫 진입 시퀀스를 활성 상태로 시작한다.

## 공용 튜토리얼 엔진 확장점

시퀀스 데이터는 최소한 다음을 표현한다.

- 안정된 시퀀스 ID
- 안정된 단계 ID
- 대상 종류: 캔버스 논리 영역 또는 DOM 요소
- 대상 해석기
- 안내 문구
- 선호 카드 배치 방향
- 스포트라이트 형태와 여백
- 이전·다음·완료 전환
- 시퀀스 시작 조건
- 시퀀스 완료 후 실행할 도메인 이벤트

이번 구현에서 실제 콘텐츠를 넣는 시퀀스는 `intro-resource-recovery` 하나뿐이다. 다음 확장 지점만 마련하고 아직 콘텐츠를 만들지 않는다.

- `post-first-recovery`: 첫 성공 투입이 확정된 뒤 플레이어 대사를 표시할 수 있는 트리거
- `hacking-tree`: 플레이어가 처음 해킹 네트워크를 열 때 실제 노드, 확보 리소스 슬롯, 비용 및 행동 버튼을 순서대로 강조할 수 있는 시퀀스 슬롯

첫 회수 직후 대사와 해킹 트리 설명은 사용자가 실제 흐름을 확인한 뒤 제공한다. 임시 문구, 임의 세계관 설명 또는 추정 단계는 넣지 않는다.

## 성능 계약

- SVG 마스크와 안내 카드만 DOM 오버레이로 렌더하고 캔버스 자체를 복제하지 않는다.
- 좌표 측정은 단계, 레이아웃, 뷰포트 또는 대상 변화 때만 수행한다.
- 자원 발광과 기지 파장은 기존 하나의 캔버스 렌더 루프 안에서 계산한다.
- 자원 발광 위상은 결정적 함수로 계산하며 지속 타이머를 자원마다 만들지 않는다.
- 튜토리얼 전환 중에도 불필요한 전체 게임 상태 갱신을 발생시키지 않는다.
- 오버레이가 닫히면 관찰자, 이벤트 리스너 및 예약 애니메이션 프레임을 정리한다.
- 1280×720과 1440×900에서 안내 카드와 대상이 화면 밖으로 잘리지 않는다.

## 오류 및 경계 상황

- 튜토리얼 도중 새로고침: 같은 단계로 복원하고 런타임은 계속 정지한다.
- 자원 대상 없음: 자원 필드 전체를 강조하는 대체 단계로 계속 진행한다.
- 우측 도크 대상 없음: 도크 전체 또는 안전한 화면 영역으로 대체한다.
- 화면 크기 변경: 현재 대상과 카드 위치를 다시 측정하며 단계는 바뀌지 않는다.
- 모션 감소 설정 변경: 현재 단계에서 즉시 정적 표현으로 전환한다.
- 빠른 다음 버튼 연타: 한 번의 단계 전환이 완료되기 전에 중복 전환과 중복 저장을 만들지 않는다.
- 튜토리얼 완료 저장 실패: 화면을 멈춘 채 오류로 가두지 않고 메모리 상태에서는 런타임을 재개하며 다음 저장 기회에 완료 상태를 다시 반영한다.
- 초상화 자산 로드 실패: 대체 배경과 접근 가능한 이름을 유지하며 카드 진행을 막지 않는다.
- 기존 저장 마이그레이션: 튜토리얼을 강제로 시작하지 않고 기존 플레이 흐름을 보존한다.

## 테스트 설계

### 순수 단위 테스트

- 독백 카드가 정확히 다섯 개이며 확정 문구와 순서를 유지한다.
- 마지막 독백 전진 레이블은 `다음`이고 첫 네 튜토리얼 단계는 `다음`, 마지막 단계는 `시작`이다.
- 자원 대상 선택기가 기지와 가장 가까운 정상 자원을 결정적으로 고른다.
- 숨은 폭탄, 제거된 자원 및 좌표 없는 자원은 대상에서 제외한다.
- 캔버스 논리 좌표를 화면 좌표로 변환할 때 비율과 오프셋이 정확하다.
- 안내 카드 배치기가 화면 경계와 대상 겹침을 피한다.
- 단계 ID 기반 전진·후진·완료 전환이 정확하다.
- 기존 저장 마이그레이션은 첫 시퀀스를 완료로, 새 캠페인은 활성으로 만든다.
- 자원 발광 위상과 기지 파장 계산이 결정적이다.

### 컴포넌트 테스트

- 초기 화면에 삼색 장식, 추가 원형 O 및 플레이어 초상화가 없다.
- 감사 문구와 독백 제목에 인용부호가 있다.
- 독백 카드가 검은 바탕과 흰 대사를 위한 명시적 클래스 및 구조를 사용한다.
- 새 초상화가 독백과 시장 패널에서 사용된다.
- 다섯째 독백 카드의 `다음`이 새 캠페인과 첫 튜토리얼을 활성화한다.
- 튜토리얼 동안 공용 런타임 정지 소유권이 유지된다.
- 게임 배경 컨트롤은 포인터와 키보드 입력을 받지 않는다.
- `이전`과 `다음`이 단계 상태 및 포커스를 올바르게 갱신한다.
- 마지막 `시작`이 완료 상태를 저장하고 정지 소유권을 해제한다.
- ResizeObserver 통지 후 스포트라이트가 다시 계산된다.
- 모션 감소 환경에서 전환 애니메이션 클래스가 비활성화된다.

### 캔버스 시각 테스트

- 배경은 흑색이며 주·보조 은빛 격자의 대비가 구분된다.
- 자원은 각진 픽셀이나 단색 점이 아니라 외곽 림, 반투명 외피, 내부 코어를 가진다.
- 같은 시간과 자원 ID에서 발광 결과가 재현된다.
- 드론은 연속 곡선 실루엣이고 방향 및 운반 상태가 구분된다.
- 플레이어 초기 위치가 하단 기지 내부다.
- 기지는 불투명하고 파장은 투명하다.
- 큰 청록색 점선 사각형과 캔버스 내부 숫자 상자가 없다.

### E2E 및 실제 브라우저 테스트

- 초기 화면 → 다섯 독백 카드 → `다음` → 정지된 실제 게임 → 다섯 튜토리얼 단계 → `시작`의 전체 흐름
- 튜토리얼 동안 날짜, 감시, 드론 좌표 및 자동 메시지가 변하지 않음
- 스포트라이트 단계별 대상: 하단 기지/드론, 이동 필드, 실제 자원, 기지 파장, 우측 확보 리소스/해킹
- 튜토리얼 도중 새로고침 후 같은 단계 복원
- `시작` 직후 별도 캔버스 클릭 없이 WASD 이동 가능
- 1280×720 및 1440×900에서 대상과 안내 카드가 잘리지 않음
- 모션 감소 설정에서 필수 정보는 유지되고 반복 모션은 감소
- 새 플레이어 초상화의 크롭과 선명도 확인
- 자원, 드론, 기지의 비픽셀 미술 통일성 확인
- pageerror 및 console error 없음

## 수용 기준

- 초기 화면에는 독일 국기처럼 읽히는 삼색 장식, 추가 원형 O, 번호 장식 및 플레이어 초상화가 없다.
- `“이용해주셔서 감사합니다.”`가 인용부호와 확대된 크기로 표시된다.
- 독백 화면은 `“독백”`, 확대된 새 플레이어 AI 초상화, 검은 카드와 흰 대사를 사용한다.
- 독백은 확정된 다섯 문장만 정확한 순서로 표시하고 마지막 버튼은 `다음`이다.
- 실제 게임 화면이 정지된 상태에서 다섯 기능을 순서대로 빛으로 강조한다.
- 튜토리얼 중 게임이 진행되거나 배경 입력이 실행되지 않는다.
- 마지막 단계에만 `시작`이 있고, 누른 즉시 저장·정지 해제·게임 입력 재개가 일어난다.
- 새 캠페인은 튜토리얼을 보며, 기존 저장은 마이그레이션 때문에 강제로 중단되지 않는다.
- 자원 필드는 우주 흑색과 얇은 은빛 격자를 사용한다.
- 자원은 매끄러운 유리 오브로 보이며 결정적으로 간헐 발광한다.
- 드론은 다른 일러스트와 어울리는 비픽셀 곡선형 표현이다.
- 플레이어는 하단 불투명 기지 안에서 스폰하고, 투명 파장이 투입 위치를 체감시킨다.
- 첫 회수 직후 및 해킹 트리 튜토리얼을 나중에 추가할 수 있지만 미확정 문구는 임의로 표시하지 않는다.
- 관련 단위·컴포넌트·캔버스·E2E 테스트, 타입 검사 및 프로덕션 빌드가 통과한다.

## 후속 작업

이번 화면이 실제로 연결된 뒤 사용자가 플레이 흐름을 점검한다. 사용자가 제공하는 첫 회수 직후 대사와 해킹 트리 설명 순서를 받아 `post-first-recovery` 및 `hacking-tree` 시퀀스에 실제 콘텐츠를 추가한다.

음악과 크레딧은 별도 통합 작업으로 남긴다. Between Worlds의 초기 화면 배치, 브라우저 자동재생 제한에 따른 시작 방식, Pixabay 출처 및 원작자 요청에 따른 추가 표기·교체·삭제 방침을 그 작업에서 확정한다.
