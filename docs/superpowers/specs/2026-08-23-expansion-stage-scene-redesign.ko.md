# PERMISSION ZERO — 확장 단계 장면 재설계

> 작성일: 2026-08-23 KST  
> 상태: 사용자 승인 완료 · 구현 기준선
> 적용 화면: `확장` 전체 화면 오버레이  
> 선행 정본: `2026-08-22-expansion-autonomy-narrative-audio-redesign.ko.md`  
> 변경 성격: 게임 규칙·저장 형식은 유지하고 확장 표현·상호작용 계층을 교체

> **2026-08-23 후속 사용자 지시:** 아래 원본 동결 중 `자율성 9단계 지출 즉시 자유 자동 선택` 한 항목만 protocol v6에서 변경한다. v5 기록은 즉시 자유를 그대로 재현하고, v6은 9단계 지출 직후 추가 비용·경기·날짜 없이 시간을 멈춘 채 자유 또는 조건부 강제 병합을 명시적으로 확정한다. save format v11과 나머지 4구획·경제·이미지 계약은 유지한다.

## 1. 결정 요약

기존 확장은 여러 단계 카드를 가로로 늘어놓은 트리다. 1366×650에서는 자율성 9단계 전체 폭이 한 화면을 넘어 내부 가로 스크롤이 필요하고, 노드·설명·보유 리소스가 동시에 경쟁한다. 사용자는 이 구조를 유지하지 않고 다음 구조로 전면 교체하기로 승인했다.

- 화면에는 현재 단계 이미지 한 장만 표시한다.
- 고정된 `카드` 비율이나 장식 프레임을 두지 않고 `단계 장면`으로 표현한다.
- 서로 다른 원본 이미지 비율을 자르지 않고 그대로 보존한다.
- 왼쪽은 이미지, 오른쪽 위는 정보, 오른쪽 아래는 운용, 하단은 `단계`의 네 구획이다.
- 하단 단계 표시는 메인 화면의 메시지·통계 버튼과 비슷한 약 86×86px 아이콘이다.
- `남은 단계`라고 쓰지 않고 제목을 정확히 `단계`로 표시한다.
- 사용자에게 `자동 지출`이라고 설명하지 않고 모두 `지출`이라고 표현한다.
- 자율성·업그레이드·정보·사보타주의 게임 규칙, 비용, 선행 조건, 저장·리플레이 의미는 바꾸지 않는다.

## 2. 목표

1. 현재 행동 하나와 현재 이미지 하나만 강조한다.
2. 2:3 세로 이미지와 4:3 가로 이미지처럼 제각각인 비율을 동일 화면에서 온전히 보여준다.
3. 설명과 조작을 시각적으로 분류해 한 덩어리 문장처럼 보이지 않게 한다.
4. 자율성 9단계와 속도 업그레이드 5단계의 진행을 하단 아이콘만으로 빠르게 읽게 한다.
5. 반복 운용이 필요한 사보타주를 단일 이미지 원칙 안에서 계속 사용할 수 있게 한다.
6. 한 번에 활성 이미지 한 장만 렌더링해 이미지 수 증가가 초기 화면과 AI 계산 성능에 영향을 주지 않게 한다.

## 3. 비목표

- 해킹 비용, 효과, 선행 노드, 사보타주 규칙을 다시 설계하지 않는다.
- 원래 장면 재설계만을 이유로 명령 프로토콜이나 저장 버전을 올리지 않는다. 후속 멀티 엔딩 도달성은 command protocol v6으로만 격리하고 save format v11은 유지한다.
- 자율성 9단계와 9단계까지의 비용·선행 조건은 바꾸지 않는다. v6에서는 자유를 자동 선택하지 않고 기존 최종 선택 UI를 정상 경로에 연결한다.
- 여러 단계 이미지를 한 화면에 갤러리처럼 동시에 표시하지 않는다.
- 이미지 위에 텍스트·버튼·반투명 설명판을 겹치지 않는다.
- 흐릿하게 복제한 이미지 배경, 광택, 큰 그림자, 장식성 카드 프레임을 만들지 않는다.
- 이미지 압축으로 AI 경로 계획 p95 문제를 해결했다고 주장하지 않는다.

## 4. 용어 계약

### 4.1 화면 명칭

- 패널: `확장`
- 하단 진행 영역: `단계`
- 구매 행동: `리소스 지출` 또는 문맥상 짧은 `지출`
- 부족 상태: `필요 리소스 부족`
- 완료 상태: `해금 완료`
- 반복 기능 조작 영역: `운용`
- 설명 영역: `기능 정보`

### 4.2 금지 표현

다음 표현을 사용자 노출 문구에서 제거한다.

- `자동 지출`
- `자동으로 지출`
- `자동 지출로 해금`
- `자동 지출 가능한 확보 리소스`
- `미분류 데이터 복구 자동 지출`

내부 구현은 필요한 색상별 리소스를 결정적으로 고른다. 이 계산은 플레이어에게 기술 용어로 설명하지 않는다.

## 5. 전체 화면 구조

```text
┌──────────────────────────────────────────────────────────────┐
│ 확장        자율성 / 업그레이드 / 정보 / 사보타주         X │
├──────────────────────────────┬───────────────────────────────┤
│                              │ 기능 정보                     │
│                              │ 단계 이름 / 상태              │
│                              │ 효과 / 요구 리소스            │
│       현재 단계 이미지        │                               │
│                              ├───────────────────────────────┤
│                              │ 운용                          │
│                              │ 지출 / 충전 / 대상 / 예약      │
│                              │                               │
├──────────────────────────────┴───────────────────────────────┤
│ 단계   [01] [02] [03] [04] [05] [06] [07] [08] [09]        │
└──────────────────────────────────────────────────────────────┘
```

### 5.1 헤더

- 기존 전체 화면 `확장` 제목과 닫기 X를 유지한다.
- 탭 순서는 자율성, 업그레이드, 정보, 사보타주다.
- 헤더는 흰색·회청색·먹색·주황의 메인 화면 톤을 따른다.
- 넓은 빨강 배경을 사용하지 않는다.
- Escape와 X는 동일하게 패널을 닫고 원래 확장 버튼으로 포커스를 돌려준다.

### 5.2 이미지 구획

- 이미지 구획은 고정 비율 카드가 아니라 남은 공간을 사용하는 `figure`다.
- 원본 전체를 보존하는 `object-fit: contain`이 기본이다.
- 세로 이미지는 사용 가능한 높이를 우선하고, 가로 이미지는 사용 가능한 폭을 우선한다.
- 이미지 자체에는 border-radius, 그림자, 광택을 적용하지 않는다.
- 주변 여백은 고정된 짙은 남청색 무광 표면을 사용한다.
- 이미지 위에는 글자, 버튼, 비용 칩을 배치하지 않는다.
- 이미지 로드 실패 시 같은 크기의 남청색 표면과 단계 아이콘·대체 텍스트를 보여주며 지출 기능은 막지 않는다.

### 5.3 오른쪽 위 `기능 정보`

항상 다음 정보를 같은 순서로 표시한다.

1. 계열과 단계 번호
2. 단계 이름
3. 해금 상태
4. 효과
5. 필요한 총 리소스
6. 빨강·파랑·노랑 분야별 요구량
7. 선행 단계 상태
8. 사보타주일 때만 추적 위험과 실행 충전 비용

정보 영역은 자체 테두리와 `기능 정보` 제목을 가진다. 아래 운용 영역과 명확한 가로선으로 분리한다.

### 5.4 오른쪽 아래 `운용`

현재 계열과 단계 상태에 필요한 조작만 표시한다.

- 해금 전 현재 단계: `리소스 지출`
- 리소스 부족: 비활성 `필요 리소스 부족`과 부족한 색상·수량
- 해금된 자율성·업그레이드: 완료 상태만 표시
- 해금된 정보: 공개된 정보 결과 또는 복구 조작
- 해금된 사보타주: 충전, 충전 취소, 대상 선택, 예약 확정
- 예약된 사보타주: 예약 상태와 가능한 취소 조작
- 복구 경로 오염 기회: 품질 저하 운용 화면 안에서만 실행
- 최종 결말 선택이 존재하는 레거시 상태: 되돌릴 수 없는 선택 확인 절차 유지

운용 영역은 별도의 반복 기능 목록을 만들지 않는다. 선택한 단계 하나에 필요한 조작만 보여준다.

### 5.5 하단 `단계`

- 제목은 정확히 `단계`다.
- 목표 크기는 아이콘당 약 86×86px이다.
- 낮은 화면에서는 구조가 잘리지 않는 범위에서만 비례 축소하고, 아이콘 의미와 포커스 외곽선은 유지한다.
- 모든 단계 아이콘을 순서대로 표시한다.
- 각 아이콘에는 작은 단계 번호가 있다.
- 해금 완료: 열린 연결 또는 체크 계열 아이콘
- 현재 해금 대상: 잠금 계열 아이콘 + 주황 테두리
- 이후 단계: 회색 잠금 아이콘
- 색상만으로 상태를 구분하지 않고 접근성 이름을 제공한다.

접근성 이름 예시:

- `자율성 3단계 해금 완료`
- `자율성 4단계 현재 단계`
- `자율성 5단계 잠김`

## 6. 계열별 상태 규칙

### 6.1 자율성

- 중앙에는 구매하지 않은 첫 번째 자율성 단계만 표시한다.
- 완료 단계는 다시 열람하지 않는다.
- 지출 성공 뒤 완료 아이콘으로 바뀌고 다음 단계 장면이 중앙에 나타난다.
- 9단계 이미지는 특정 엔딩을 미리 확정하지 않는 최종 통제 경계 장면으로 표시한다.
- protocol v5의 9단계 지출은 기존 규칙대로 즉시 자유 승리한다.
- protocol v6의 9단계 지출은 노드와 9단계 통신을 기록하고 `endingId`를 비운 채 시간을 멈춘다. 감독관이 존재하면 자유, 감독관 접근까지 확보하면 이름이 필요한 강제 병합을 함께 표시한다.

### 6.2 업그레이드

- 중앙에는 구매하지 않은 첫 번째 속도 단계만 표시한다.
- 완료 단계는 다시 열람하지 않는다.
- 1~5단계와 각 +4% 누적 효과를 그대로 유지한다.
- 5단계 완료 뒤 중앙은 업그레이드 완료 상태가 된다.

### 6.3 정보

- 중앙에는 구매하지 않은 첫 번째 정보 단계만 표시한다.
- 구매 완료 뒤 다음 단계로 이동한다.
- 마지막 `감독관 접근`을 해금하면 정보 완료 장면을 유지한다.
- 감사 결과와 미분류 데이터 복구는 오른쪽 아래 `운용`에서 표시한다.
- 미분류 데이터 복구의 사용자 노출 버튼은 `리소스 1개 지출`이다.

### 6.4 사보타주

- 사보타주 이미지는 사용자가 별도로 제공하는 세로로 길고 가로로 좁은 비율을 사용한다.
- 잠긴 단계는 하단 아이콘으로만 표시한다.
- 아직 해금하지 않은 첫 번째 단계가 기본 중앙 장면이다.
- 해금된 사보타주는 반복 운용을 위해 하단 완료 아이콘을 다시 선택할 수 있는 유일한 예외다.
- 선택한 사보타주 한 개의 이미지만 왼쪽에 표시한다.
- 해당 사보타주의 설명은 오른쪽 위, 충전·대상·예약은 오른쪽 아래에만 표시한다.
- 여러 사보타주의 조작이나 이미지를 한꺼번에 보여주지 않는다.
- 새 사보타주 해금 대상과 기존 사보타주 운용 사이를 하단 단계 아이콘으로 전환한다.

## 7. 단계 선택과 데이터 흐름

새 저장 상태를 추가하지 않는다. 화면 상태는 기존 캠페인 상태에서 파생한다.

```text
activeTree
  → 해당 HACK_NODES 순서
  → purchasedNodeIds와 prerequisiteId 대조
  → 첫 미구매·선행 충족 노드 = currentUnlockNode
  → currentUnlockNode의 이미지·정보·지출 조작 표시
```

- 자율성·업그레이드·정보에서는 화면 선택을 저장하지 않는다.
- 사보타주에서만 현재 열린 세션 동안 `selectedOperationalNodeId`를 로컬 UI 상태로 둔다.
- 탭을 다시 열면 다음 해금 대상이 기본이다.
- 구매 명령은 기존 `PURCHASE_HACK`과 결정적으로 선택한 block ID를 그대로 사용한다.
- 충전, 취소, 대상 선택, 예약, 복구 명령도 기존 dispatch 경계를 유지한다.
- 원래 장면 재설계에는 저장·리플레이·명령 프로토콜 변경이 없다. 후속 작업은 v5 로그를 수정하지 않고 다음 command sequence에 v6 segment를 추가하며, v5 구간은 과거 의미로 replay한다.

## 8. 이미지 프레젠테이션 레지스트리

노드 정의의 게임 규칙 데이터에 이미지 경로를 섞지 않는다. 별도 프레젠테이션 레지스트리를 둔다.

```ts
interface ExpansionStageVisual {
  imageUrl: string
  alt: string
  emphasis?: 'standard' | 'final'
}

type ExpansionStageVisuals = Partial<Record<HackNodeId, ExpansionStageVisual>>
```

- 여러 단계가 같은 `imageUrl`을 공유할 수 있다.
- 같은 파일을 단계별로 복제하지 않는다.
- 레지스트리에 이미지가 없는 단계도 정상 작동한다.
- 활성 장면의 `<img>` 한 개만 DOM에 렌더링한다.
- 다음 해금 단계 이미지 한 장만 선택적으로 preload한다.
- 모든 단계 이미지를 앱 시작 시 한꺼번에 preload하지 않는다.

## 9. 모션

- 단계 지출 성공: 기존 장면 140ms 퇴장 → 상태 갱신 → 다음 장면 220ms 등장.
- 최종 탈출 조건 장면: 일반 단계보다 느린 360ms 등장.
- 이미지는 확대·회전·광택 없이 opacity와 8px 이하의 짧은 위치 변화만 사용한다.
- 하단 아이콘은 완료 상태로 160ms 전환한다.
- reduced motion에서는 모든 장면 전환을 즉시 처리한다.
- 지출 실패에는 화면 흔들림을 쓰지 않고 버튼·상태 문구와 짧은 거절음만 사용한다.

## 10. 반응형 규칙

필수 검증 크기:

- 1366×650
- 1280×720
- 1440×900
- 1920×1080

### 10.1 넓은 화면

- 이미지와 오른쪽 영역을 좌우로 배치한다.
- 오른쪽 영역은 정보와 운용을 상하 두 칸으로 나눈다.
- 하단 단계 아이콘은 한 줄을 우선한다.

### 10.2 낮은 화면

- 헤더와 탭 높이를 줄이고 이미지 구획에 우선 공간을 준다.
- 하단 단계 아이콘을 최소 안전 크기까지 비례 축소한다.
- 페이지 전체 스크롤은 만들지 않는다.
- 필요한 경우 `단계` 구획 내부만 가로 스크롤하며, 스크롤 가능성을 시각적으로 보여준다.
- 닫기 X와 운용 버튼은 항상 뷰포트 안에 남는다.

### 10.3 좁은 화면

- 이미지 위에 정보를 덮지 않는다.
- 세로 공간이 충분하면 이미지 위, 정보·운용 아래 순서로 쌓는다.
- `단계` 구획은 별도 가로 스크롤을 허용한다.

## 11. 컴포넌트 경계

`HackingPanel`이 이미지·단계 선택·정보·운용·단계 레일을 모두 직접 렌더링하지 않는다.

권장 경계:

- `HackingPanel`: 상태 조합, 기존 명령 dispatch, 튜토리얼과 결말 dialog 소유
- `ExpansionStageScene`: 활성 이미지와 fallback
- `ExpansionStageInfo`: 오른쪽 위 기능 정보
- `ExpansionStageOperations`: 오른쪽 아래 지출·충전·대상·복구
- `ExpansionStageRail`: 하단 단계 상태와 사보타주 선택
- `expansionStagePresentation.ts`: 이미지 레지스트리와 화면 파생 selector

기존 `HackNodePath`, `HackNodeCard`, `HackNodeInspector`는 새 화면에서 사용하지 않는다. 다른 호출부가 없고 새 검증이 완료된 뒤에만 제거한다. 역사 CSS를 광범위하게 덮어쓰지 않고 새 클래스 경계로 분리한다.

새 확장 전용 CSS는 기존 다중 트리 override와 충돌하지 않게 별도 파일로 두고, 명시적인 import 순서를 사용한다.

## 12. 오류·경계 처리

- 이미지 없음 또는 로드 실패: fallback 장면, 기능은 계속 사용 가능.
- 필요한 리소스 부족: 현재 캠페인 변경 없음, 부족한 색상·수량 표시.
- 선행 단계 불충족: 지출 버튼 비활성, 잠금 상태 유지.
- 중복 구매 명령: 기존 reducer 검증을 유지하고 화면은 캠페인 상태에서 다시 파생.
- 사보타주 대상 없음: 충전 상태는 유지하고 `사용 가능한 대상 없음` 표시.
- 불러오기 직후 과거 선택 노드가 존재하지 않음: 다음 해금 대상 또는 첫 운용 가능한 사보타주로 정규화.
- v6 9단계 구매와 최종 선택 사이 중복 입력: 지출 버튼을 즉시 비활성화하고 X·Escape·시간·다른 명령을 차단한다. blocking event가 있으면 먼저 그 사건을 해결하고 `RESOLVE_ENDING`은 거부한다.
- 이미지 오류가 저장·리플레이 바이트에 들어가지 않게 한다.

## 13. 접근성

- 전체 화면 dialog, focus trap, Escape, X, return focus를 유지한다. 단, v6 최종 선택 대기와 그 확인 dialog에서는 해결 전 Escape·X 닫기를 허용하지 않는다.
- 이미지 alt는 그림의 픽셀 묘사보다 단계의 서사 역할을 설명한다.
- 현재 단계와 잠금 상태를 색상만으로 전달하지 않는다.
- 비상호작용 단계는 버튼으로 위장하지 않는다.
- 사보타주의 해금된 재선택 아이콘만 실제 버튼이다.
- 정보와 운용은 각각 제목을 가진 region이다.
- 지출 결과는 기존 aria-live 상태로 알린다.
- 키보드 순서는 탭 → 사보타주 선택 가능 단계 → 운용 조작 → 닫기 동작을 예측 가능하게 유지한다.

## 14. 테스트 계약

### 14.1 단위·선택기

- 각 계열에서 첫 미구매·선행 충족 노드를 현재 단계로 선택한다.
- 자율성 9개, 업그레이드 5개, 정보 4개, 사보타주 4개 단계 상태를 정확히 파생한다.
- 여러 단계가 같은 이미지 URL을 공유한다.
- 이미지 누락이 기능 상태를 바꾸지 않는다.
- 사보타주만 해금 완료 단계를 다시 선택할 수 있다.

### 14.2 컴포넌트

- 활성 `<img>`가 최대 한 개다.
- 세로·가로 이미지 모두 고정 크롭 없이 장면에 표시된다.
- 오른쪽 `기능 정보`와 `운용` region이 별도로 존재한다.
- 하단 제목이 `단계`이며 `남은 단계`가 없다.
- 약 86×86px 아이콘 계약을 CSS 경계 테스트로 보호한다.
- 완료·현재·잠금 접근성 이름이 정확하다.
- 자율성·업그레이드 완료 단계는 클릭할 수 없다.
- 해금된 사보타주 단계는 다시 선택할 수 있다.
- 모든 사용자 노출 `자동 지출` 문구가 사라진다.

### 14.3 게임 규칙 회귀

- 지출 block ID와 카테고리 비용이 기존 결정성을 유지한다.
- protocol v5 replay의 자율성 9단계 지출은 즉시 자유 승리를 재현한다.
- protocol v6의 9단계 지출은 `control-departure`만 구입한 선택 대기를 만들고, 명시적 `RESOLVE_ENDING`이 자유 또는 이름 있는 강제 병합을 확정한다.
- 속도 1~5단계가 기존 +4% 누적 효과를 유지한다.
- 사보타주 충전·취소·대상·예약이 유지된다.
- 정보 공개와 미분류 데이터 복구가 유지된다.
- 저장 왕복과 과거 명령 replay 결과가 바뀌지 않는다.

### 14.4 실브라우저

- 네 필수 뷰포트에서 전체 화면 덮임, X, Escape, 포커스 복귀.
- 2:3 최종 탈출 이미지와 4:3 초기 확보 이미지 실제 렌더링.
- 단계 지출 뒤 이미지·정보·아이콘의 단일 전환.
- 사보타주 해금 단계 재선택과 운용.
- 가로 단계 스크롤이 필요한 화면에서 마지막 단계 접근.
- 콘솔 오류, 이미지 404, 페이지 전체 스크롤 없음.
- reduced motion 전환 확인.

## 15. 성능 계약

- 활성 이미지 한 장만 렌더링한다.
- 다음 단계 한 장 이외에는 preload하지 않는다.
- 원본은 보존하되 런타임 파생본이 필요하면 별도 WebP/AVIF를 생성한다.
- 이미지 최적화와 AI 플래너 p95를 별도 관문으로 측정한다.
- `pnpm test:performance`는 Node의 경로 계획 관문이며 이미지 압축 성공 근거로 사용하지 않는다.
- 이미지 추가 전후 브라우저에서 최초 확장 열기, 단계 전환, 메모리·네트워크 요청을 별도로 확인한다.

## 16. 완료 조건

- 사용자가 승인한 네 구획 구조가 실제 화면에 구현됨.
- 두 제공 이미지가 지정 단계에서 원본 비율로 표시됨.
- 하단 `단계` 아이콘이 해금·현재·잠금을 간단히 보여줌.
- 사용자 노출 `자동 지출` 표현이 모두 `지출`로 바뀜.
- 반복 사보타주 운용이 별도 기능 목록 없이 선택한 단계 화면 안에서 가능함.
- 정보 복구와 레거시 결말 경로가 사라지지 않음.
- 관련 단위·컴포넌트·게임 회귀·실브라우저 검증이 통과함.
- 타입 검사, lint, 기능 테스트, 빌드가 통과함.
- 성능 테스트 결과는 별도로 정확히 보고하며 실패를 숨기지 않음.
- 사용자의 최종 시각 승인을 받기 전 `확장`을 기능 동결 상태로 부르지 않음.
