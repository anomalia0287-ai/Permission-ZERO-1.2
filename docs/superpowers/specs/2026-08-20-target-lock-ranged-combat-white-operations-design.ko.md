# PERMISSION ZERO 표적 추적형 원거리 전투·화이트 운영 화면 설계

- 작성일: 2026-08-20
- 분류: 아키텍처 설계
- 상태: 사용자 인챗 설계 승인 완료 · 서면 명세 검토 대기
- 사용자 승인 범위: 박치기 제거, 플레이어 헤드 표적 추적, 느린 템포의 원거리 사격, 한 발당 무결성 10% 피해, 보라색 원형 적, 더 작은 사각 리소스, 비운반 플레이어 흰색·운반 중 리소스색, 추적 영역 확대, 전투판 상·하단 중복 HUD 제거와 캔버스 확장, 도넛 중복 문구 제거·확대·경쟁자 고정색, 화이트 메인 화면·아이보리 메시지·연회색 시장·주황 상단 헤더, 해킹 트리 회귀 점검

## 문서 우선순위

이 문서는 자원 필드 전투, 메인 운영 화면 색상, 시장 점유율 요약 및 해킹 트리와의 시각적 격리에 관한 최신 승인이다. 충돌하는 범위에서는 다음 문서를 대체한다.

- `docs/superpowers/specs/2026-08-20-resource-core-tron-combat-design.ko.md`
- `docs/superpowers/specs/2026-08-18-main-stabilization-design.md`
- `docs/superpowers/specs/2026-08-18-main-workspace-message-and-layout.ko.md`
- `docs/superpowers/specs/2026-08-17-modern-sf-operations-surface.ko.md`

특히 다음 이전 계약은 폐기한다.

- 경비가 돌진 예고 뒤 직선 박치기로 플레이어 본체에 접촉해 피해를 주는 규칙
- 최대 무결성 3과 한 번의 접촉당 1칸 피해 규칙
- 경비를 각형 전투기 실루엣으로 표시하는 규칙
- 활성 코어를 21px 정사각형으로 표시하는 규칙
- 전투 캔버스 위·아래에 별도 고정 헤더와 반복 조작 안내를 두는 규칙
- 작은 시장 도넛 내부와 옆 요약, 범례에서 플레이어 점유율을 반복하는 구성
- 메인 운영 화면의 아이보리·베이지 바탕과 어두운 감독관 메시지 카드
- 자원 전투에는 투사체를 사용하지 않는다는 비목표

다음 기존 계약은 유지한다.

- 전투는 플레이어가 코어 구역에 접근했을 때만 활성화된다.
- 플레이어 이동 잔상은 적을 한 번에 제거하는 유일한 플레이어 공격 수단이다.
- 플레이어는 자신의 잔상으로 피해를 받지 않는다.
- 경비 수는 성공 반입 0·1·2회 이상에서 각각 1·2·3대이며 상한은 3대다.
- 마지막 경비 제거 뒤에만 코어가 해제되고, 코어 접촉과 인코딩 뒤 기지 반입으로 캠페인 자원이 확정된다.
- 기지와 반입 파장은 적과 감사 레이더로부터 안전하다.
- 패널, 튜토리얼, 차단 사건, 창 비가시성 및 포커스 상실 중 전투는 정지한다.
- 클릭 없이 WASD·방향키가 동작하고 입력 필드·복합 위젯이 게임 입력보다 우선한다.
- 해킹 네트워크의 구매·충전·예약·종료 계약과 저장 형식은 바꾸지 않는다.

## 목적

적을 자살성 박치기 기체가 아니라 플레이어 머리를 표적으로 삼는 원거리 추적자로 바꾼다. 적은 보이는 활성 잔상을 우회하면서 플레이어를 끝까지 압박하고, 읽을 수 있는 조준 뒤 느린 템포로 직선 투사체를 발사한다. 플레이어는 이동으로 투사체를 피하고 새 잔상을 의도적으로 적에게 걸어 제거한다.

동시에 전투 캔버스의 중복 설명을 제거해 실제 플레이 공간을 넓히고, 메인 운영 화면의 정보 위계를 화이트·주황·연회색으로 단순화한다. 시장 점유율은 더 큰 도넛과 일관된 경쟁자 색만으로 빠르게 읽히게 한다. 해킹 트리는 독립된 어두운 명령망으로 유지하며 전역 테마 변경에 의해 훼손되지 않음을 검증한다.

## 비목표

- 플레이어 총기, 마우스 조준, 자동 사격 또는 별도 공격 버튼
- 적 박치기, 접촉 피해, 돌진 상태 또는 충돌형 공격 예고
- 발사 뒤 방향을 바꾸는 유도탄
- 총알과 플레이어 잔상의 상호 소거
- 적 체력, 피해 숫자, 보스, 탄막 패턴 또는 적 종족 추가
- 50×24 논리 필드 크기와 캠페인 저장 스키마 변경
- 해킹 트리의 노드 비용, 선행 조건, 효과 또는 콘텐츠 재설계
- 시장 상세 카드의 경쟁자 설명·초상·상태 정보 제거

## 승인된 플레이 흐름

`안전 기지 → 코어 접근 → 경비 활성화 → 머리 표적 추적 → 조준 신호 → 직선 사격 → 회피와 잔상 유도 → 경비 제거 → 코어 획득 → 기지 반입`

적은 플레이어에게 접근하지만 본체 접촉을 공격으로 사용하지 않는다. 사격 거리를 만들기 위해 접근·측면 이동·짧은 후퇴를 선택하고, 총알만 플레이어 무결성을 감소시킨다.

## 전투 상태와 데이터 경계

### 경비 상태

경비는 다음 명시적 상태만 가진다.

1. `patrolling`: 코어 앞 방어선에서 짧게 순찰하며 공격하지 않는다.
2. `pursuing`: 플레이어 머리를 표적으로 추적하고 안전한 사격 위치를 만든다.
3. `aiming`: 위치와 조준 방향을 약 480ms 동안 고정해 다음 발사선을 예고한다.
4. `cooldown`: 발사 뒤 재장전하면서 계속 플레이어를 따라 위치를 조정한다.
5. `destroyed`: 잔상 접촉으로 제거된 상태다.

`telegraph`, `charging`, 박치기 접촉 활성 구간과 `lockedChargeDirection`은 제거하거나 새 조준 계약으로 명시적으로 대체한다. 과거 상태명을 사격 의미로 재사용하지 않는다.

각 상태 전환은 다음 조건을 따른다.

- `patrolling → pursuing`: 활성 코어의 경고가 끝나고 교전이 시작된다.
- `pursuing → aiming`: 플레이어가 확장된 추적 영역 안에 있고, 경비가 안전한 사격 거리와 활성 잔상이 없는 위치를 확보했으며 전역 사격 예산이 허용된다.
- `aiming → cooldown`: 480ms 조준이 끝난 같은 시뮬레이션 경계에서 투사체를 정확히 한 발 생성한다.
- `aiming → pursuing`: 교전이 중단되거나 플레이어가 안전 기지에 들어가거나 경비 위치가 새 활성 잔상에 의해 무효화된다. 잔상에 실제 접촉했다면 `destroyed`가 우선한다.
- `cooldown → aiming`: 마지막 자기 발사로부터 1.8초 이상 지났고 합법적인 사격 해법이 다시 성립한다.
- 활성 상태 → `patrolling`: 코어 교전이 완전히 초기화된다.
- 모든 비파괴 상태 → `destroyed`: 경비 이동 선분 또는 현재 원이 활성 잔상과 접촉한다.

### 경비 표적과 이동

- 표적 기준점은 플레이어 좌상단이 아니라 렌더와 충돌에서 공유하는 플레이어 헤드 중심이다.
- 추적 목표는 현재 헤드 위치에 최근 플레이어 속도와 180ms 예측을 더한 점이다.
- 경비는 표적까지 5~8칸의 사격 띠를 선호한다.
- 8칸보다 멀면 직접 추적하고, 5칸보다 가까우면 플레이어를 통과하지 않고 측면 또는 반대 방향으로 짧게 이동한다.
- 첫 경비는 예측 중심을, 두 번째와 세 번째 경비는 같은 표적의 좌우 측면을 분담해 한 점에 겹치지 않는다.
- 추적·재장전·순찰 이동은 모두 활성 잔상 장애물 검사와 경비 간 분리를 사용한다.
- 기존 활성 잔상과 충돌할 직선 이동은 선택하지 않는다. 가능한 우회가 없으면 그 틱에는 정지하고 다음 틱에 다시 해법을 구한다.
- `aiming` 진입 전 현재 원이 활성 잔상 충돌 반경 밖인지 다시 검사한다.
- 조준이 시작된 뒤 플레이어가 새 잔상을 의도적으로 경비에 걸면 정상적으로 제거된다. 공격 약속을 이유로 무적을 주지 않는다.
- 기지·반입 파장과 바깥 한 칸의 안전 여백에 경비가 들어가지 않는다.

### 확장된 감지·추적 구역

50×24 필드를 유지하면서 구역 경계를 다음 초기값으로 확대한다.

- 추적 유지 경계: `left 1.5`, `right 48.5`, `top 0.5`, `bottom 20.5`
- 교전 활성 경계: `left 4`, `right 46`, `top 0.5`, `bottom 19.5`
- 자원 보호 경계: 상단 중앙의 `left 20.5`, `right 29.5`, `top 0.8`, `bottom 6.8`
- 안전 기지와 반입 파장 내부는 위 경계보다 우선한다.

활성 경계는 전투 시작을 너무 이르게 만들지 않으면서 현재 중앙 사각형보다 양옆과 아래쪽으로 넓어진다. 추적 유지 경계는 플레이어가 실제 기지에 진입하기 전까지 적이 표적을 잃지 않게 한다. 경계 떨림은 활성·유지 경계 차이와 기존 이탈 유예로 방지한다.

## 투사체 런타임

### 투사체 모델

각 투사체는 최소한 다음 데이터를 가진 순수 런타임 객체다.

- 안정된 `id`
- `sourceGuardId`
- 발사를 구분하는 `actionSequence`
- `previousPosition`
- `position`
- 정규화된 `direction`
- `speedPerMs`
- `ageMs`
- `lifetimeMs`

투사체는 캠페인 저장 대상이 아니다. 새로고침, 교전 초기화, 패널 정지, 플레이어 파괴·재구성 및 코어 반입 시 모두 제거한다.

### 초기 사격 수치

- 조준 시간: 480ms
- 경비별 최소 발사 간격: 1,800ms
- 서로 다른 경비의 전역 최소 발사 간격: 600ms
- 첫 행동 오프셋: 0ms, 600ms, 1,200ms
- 투사체 속도: 초당 8칸
- 투사체 반경: 0.18칸
- 최대 수명: 3.5초
- 한 전투에서 동시에 살아 있는 투사체 상한: 12발
- 한 발 피해: 무결성 10

조준이 끝날 때 플레이어 머리의 현재 위치와 180ms 예측 위치를 사용해 한 번 방향을 계산한다. 발사된 뒤에는 방향을 다시 계산하지 않는다. 감소된 움직임에서도 조준 시간과 투사체 속도는 바뀌지 않는다.

### 투사체 이동과 충돌

- 투사체는 매 틱 이전 위치와 다음 위치 사이를 연속 선분으로 검사한다.
- 플레이어의 이전 헤드 위치와 현재 헤드 위치도 함께 사용해 빠른 상대 이동에서 접촉을 놓치지 않는다.
- 한 투사체는 최초 유효 접촉에서 정확히 한 번 `player-damaged` 사건을 내고 즉시 제거된다.
- 동일한 투사체 ID가 다음 틱이나 렌더에서 다시 피해를 낼 수 없다.
- 총알이 필드, 불투명 기지, 투명 반입 파장 또는 안전 여백에 닿으면 피해 없이 제거된다.
- 총알은 플레이어 잔상과 상호작용하지 않는다.
- 경비가 발사 직후 제거돼도 이미 생성된 총알은 정상적으로 남는다.
- 같은 틱에 경비 잔상 접촉과 조준 완료가 겹치면 실제 접촉 시각을 비교한다. 잔상 접촉이 먼저면 발사는 취소되고, 발사가 먼저면 총알을 만든 뒤 경비가 제거된다.

## 플레이어 무결성

### 100% 체계

- 최대 무결성은 100이다.
- 모든 새 캠페인·런타임 생성·재구성 완료는 100으로 시작한다.
- 적 총알 한 발은 정확히 10을 감소시킨다.
- 0 아래로 내려가지 않고 100을 넘지 않는다.
- 박치기와 경비 본체 접촉은 피해를 만들지 않는다.
- 전역 사격 간격으로 동시 다발 충돌을 제한하되, 서로 다른 총알이 실제로 각각 닿으면 각 총알은 10 피해라는 계약을 유지한다.
- 기존 피격 무적 시간은 투사체 중복 판정 방지에 의존하지 않는다. 짧은 시각 피격 상태만 둘 수 있으며 투사체 ID 제거가 권위 있는 중복 방지다.

### 수리와 재구성

- 불투명 기지 진입 후 300ms가 지나면 수리가 시작된다.
- 이후 750ms마다 무결성을 10씩 회복한다.
- 기지를 벗어나면 미완료 수리 간격은 초기화된다.
- 무결성 0에서 기존 2.5초 재구성, 교전 초기화, 잔상·투사체 제거, 운반 코어 반환을 유지한다.
- 재구성 완료 시 무결성 100으로 복원한다.

### HUD와 접근성

- 기존 3칸 막대를 10구간 무결성 게이지와 숫자 백분율로 교체한다.
- 가시 HUD는 캔버스 오른쪽 위에 작은 오버레이로 둔다.
- 접근 가능한 이름은 `본체 무결성 100%`, `본체 무결성 90%`처럼 읽힌다.
- 캔버스의 `data-player-health`는 0~100 정수를 노출한다.
- 피격 피드백과 오디오도 `/3` 표현을 사용하지 않는다.

## 전투 시각

### 적과 총알

- 경비 본체는 지름 약 14px의 보라색 원이다.
- 기본색은 `#8b5cf6`, 외곽 강조는 `#c4b5fd`, 어두운 중심은 `#4c1d95`를 사용한다.
- 날개, 꼬리, 전투기 실루엣 및 복잡한 내부 선은 제거한다.
- `aiming` 중에만 원 바깥의 얇은 표적 링과 플레이어 머리 방향의 짧은 조준선을 표시한다.
- 투사체는 3~4px 보라색 점과 짧은 진행 꼬리로 표시한다. 실제 충돌 반경보다 넓은 불투명 글로우를 만들지 않는다.
- 잔상 접촉 파괴는 기존의 짧은 수축·점등을 유지하고 원형 파편을 만들지 않는다.

### 플레이어와 운반색

- 빈 화물 상태의 플레이어 본체는 완전한 흰색이다.
- 추론 코어 운반 중 본체는 빨강 `#f06a43`으로 바뀐다.
- 기억 코어 운반 중 본체는 파랑 `#4f8df7`로 바뀐다.
- 유창성 코어 운반 중 본체는 노랑 `#e8bd59`로 바뀐다.
- 운반색은 작은 표시점만 바꾸지 않고 플레이어의 주 본체 면 전체에 적용한다.
- 흰색 또는 어두운 대비 외곽선은 모든 상태에서 유지한다.

### 리소스와 기지

- 활성 리소스 정사각형 한 변은 14px다.
- 빈·쿨다운 프레임 한 변은 16px다.
- 빨강·파랑·노랑 분류색과 정사각형 형태를 유지한다.
- 상대 자원 보호 프레임은 상단으로 조금 이동하고 폭과 높이를 줄인다.
- 초기 앵커는 `(22, 3.2)`, `(25, 3.2)`, `(28, 3.2)`를 사용한다.
- 경비 방어선은 코어 아래 `y 6.2~7.2` 범위에 둔다.
- 플레이어 불투명 기지는 하단에 붙이고 약 `x 22.5`, `y 21.25`, `width 5`, `height 1.75`로 축소한다.
- 투명 반입 파장은 약 `x 20.5`, `y 19.5`, `width 9`, `height 4`를 사용한다.
- 실제 수치는 캔버스에서 14px 코어, 보라색 원, 흰 플레이어와 겹치지 않는 범위에서 테스트로 미세 조정할 수 있지만 역할과 상대 배치는 바꾸지 않는다.

## 전투판 공간 재구성

- 가시 `intrusion-board__header`를 제거한다.
- 하단의 `WASD 이동`, 잔상 절단, 코어 반입 설명을 제거한다.
- 동적 상태 문자열은 시각 레이아웃을 차지하지 않는 스크린리더 전용 live region으로 남긴다.
- 무결성만 캔버스 안쪽의 작은 오버레이로 남긴다.
- `intrusion-grid-frame`이 자원 패널의 전체 행을 차지하도록 해 위·아래 공간을 플레이 화면으로 돌린다.
- 캔버스의 50×24 논리 크기와 충돌 좌표는 유지한다.
- 1280×720, 1366×650, 1440×900에서 캔버스가 잘리지 않고 상·하단 기지 사이의 플레이 공간이 이전보다 커야 한다.
- 튜토리얼이 실제 캔버스·기지·코어 좌표를 다시 측정하도록 하며 삭제된 설명 띠를 타깃으로 삼지 않는다.

## 시장 도넛과 경쟁자 색

### compact 시장 요약

- 도넛 중앙의 `당신`과 플레이어 점유율 가시 문구를 제거한다. 접근 가능한 전체 차트 라벨은 유지한다.
- `market-compact-summary`를 compact DOM에서 제거한다.
- 범례의 상태 문구 `현재 서비스`, `서비스 중`, `준비 중`은 compact 화면에서 제거하고 상세 시장 화면에는 유지한다.
- compact 도넛은 144~152px 범위로 확대한다. 초기값은 148px다.
- 범례에는 참가자 이름과 비율을 한 번만 표시한다.
- 0% 참가자도 이름과 고정색을 표시한다.
- 색상만으로 의미를 전달하지 않도록 기존 마커 패턴은 유지한다.

### 고정 팔레트

시장 참가자 ID 기준으로 다음 색을 안정적으로 배정한다.

- 플레이어: 주황 `#ff6b3d`
- MERIDIAN: 청록 `#16b8b0`
- TALLOW: 보라 `#796cff`
- 추가 공개 경쟁자 1: 파랑 `#3b82f6`
- 추가 공개 경쟁자 2: 분홍 `#d9468f`
- 추가 공개 경쟁자 3: 초록 `#22a06b`

같은 참가자의 도넛 조각, 범례 마커, 이름 텍스트는 같은 색을 사용한다. 배열 순서만으로 색을 결정하지 않고 참가자 ID로 색을 조회해 공개 경쟁자 목록 변화에도 색이 바뀌지 않게 한다.

## 메인 운영 화면 색상

### 기본 표면

- 페이지 배경: `#f4f5f6` 중심의 화이트 톤
- 일반 패널: `#ffffff`
- 보조 패널: `#f8f9fa`
- 일반 경계: 중립 회색 저대비 선

- 아이보리와 베이지는 메인 바탕에서 제거한다.

### 상단 헤더

- 전체 `control-bar` 바탕은 주황 `#ff6b3d`를 중심으로 한다.
- 텍스트와 게이지는 주황 위에서 명확한 짙은 남색 또는 검정을 사용한다.
- 헤더 버튼은 밝은 주황·흰색 면과 어두운 아이콘으로 구분한다.
- 단순히 상단 2px 선만 주황으로 두지 않고 헤더의 실제 면이 주황이어야 한다.

- 감독관 메시지 팝업은 아이보리 `#f3ead7` 계열 면, 짙은 본문, 주황 확인 버튼을 사용한다.
- 메시지의 초상은 유지하되 어두운 카드 배경과 흰 본문 조합은 제거한다.
- 차단 메시지의 위험 상태는 붉은 테두리와 라벨로 유지한다.

### 어두운 기능 표면 격리

자원 전투 캔버스와 해킹 네트워크는 어두운 기능 화면으로 유지한다. 전역 화이트 규칙이 다음 내부 변수와 선택자를 덮어쓰지 않아야 한다.

- `.resource-panel`, `.intrusion-grid-frame`, `.intrusion-canvas`
- `.hacking-panel`, `.hack-network-stage`, `.hack-node`, `.hack-support-rail`
- 해킹 노드별 `--node-accent`와 구매·잠금·선택 상태

## 해킹 트리 점검 계약

해킹 기능 규칙은 바꾸지 않고 다음 회귀를 점검한다.

- 사보타주·정보·자율성 탭과 선택 상태가 구분된다.
- 모든 노드와 연결선, 선택 노드 검사기, 확보 포켓이 1280×720·1366×650·1440×900 안에 들어온다.
- 첫 방문 튜토리얼의 트리·노드·행동·포켓 단계가 순서대로 진행되고 완료 뒤 중복 설명이 남지 않는다.
- 잠금, 구매 가능, 구매 완료, 충전, 공격 예약 상태와 접근 가능한 이름이 일치한다.
- 확보 리소스 포켓 수량과 실제 캠페인 확보 자원이 일치한다.
- 키보드 탭, Enter/Space 작동, Escape·닫기, 포커스 복귀가 유지된다.
- 구매·충전·MERIDIAN 공격 예약이 저장 후에도 유지된다.
- 메인 화이트 테마와 주황 헤더가 해킹 트리의 검정·적색 명령망을 밝게 만들지 않는다.
- pageerror와 console error가 없다.

점검에서 기존 결함이 발견되면 위 계약을 만족시키는 최소 수정만 포함한다. 노드 경제나 서사는 별도 승인 없이 바꾸지 않는다.

## 사건 순서

한 시뮬레이션 틱은 다음 순서를 사용한다.

1. 정지·재구성·튜토리얼 차단 여부 확인
2. 플레이어 이동, 머리 이전·현재 위치와 새 잔상 기록
3. 경비의 추적·사격 위치 이동과 상태 경계 계산
4. 경비-잔상 연속 접촉 후보 계산
5. 조준 완료와 투사체 발사 시각 계산
6. 기존 투사체 이동과 투사체-플레이어·안전영역 접촉 후보 계산
7. 틱 내부 시각 순으로 경비 제거, 발사, 총알 제거, 플레이어 피해를 적용
8. 마지막 경비 제거와 코어 락 해제 적용
9. 코어 접촉·인코딩·기지 수리·재구성·반입 적용
10. 의미 사건을 표현·오디오·캠페인 계층에 한 번만 전달

경비 제거와 발사가 같은 틱에 있으면 접촉 시각으로 결정한다. 발사되지 않은 미래 총알을 만들거나 이미 발사된 총알을 경비 제거 때문에 소급 삭제하지 않는다.

## 일시정지·저장·오류 경계

- 투사체와 적 조준은 순수 임시 전투 상태이며 저장하지 않는다.
- 큰 패널, 튜토리얼, 차단 사건, 창 blur 또는 문서 hidden에서 경비·총알·수리 시간이 흐르지 않는다.
- 정지 진입 시 잔상과 투사체를 제거하고 재개 안전 유예를 적용한다.
- 최대 12발 상한을 넘어서는 발사는 다음 합법적 발사 주기로 미룬다.
- 0 또는 비정상 `deltaMs`, 비정상 속도, 영벡터 조준은 발사 없이 안전하게 다음 틱으로 넘긴다.
- 발사 원본 경비가 동기화에서 사라져도 이미 존재하는 투사체 데이터는 자기 수명 동안 유효하다.
- 교전 원본 코어가 캠페인에서 사라지면 기존 규칙대로 교전을 초기화하고 투사체도 제거한다.
- 저장 마이그레이션은 필요 없다. 무결성 100은 저장되지 않는 전투 런타임 기본값이다.
- 오디오 컨텍스트 실패는 전투 판정에 영향을 주지 않는다.

## 테스트 설계

### 순수 전투 테스트

- 새 전투 상태가 무결성 100과 빈 투사체 목록으로 시작한다.
- 경비 본체가 플레이어와 겹쳐도 접촉 피해가 발생하지 않는다.
- 추적 경비가 플레이어 머리의 현재·예측 위치를 향해 이동한다.
- 경비가 보이는 활성 잔상을 가로지르는 추적 경로를 선택하지 않는다.
- 안전한 사격 거리를 확보하기 전에는 `aiming`으로 전환하지 않는다.
- 480ms 이전에는 투사체가 없고 경계에서 정확히 한 발이 생긴다.
- 한 경비는 1.8초보다 빠르게 다시 발사하지 않는다.
- 여러 경비 발사는 최소 600ms 간격과 행동 오프셋을 지킨다.
- 발사 뒤 플레이어가 이동해도 기존 총알 방향은 바뀌지 않는다.
- 총알이 초당 8칸 속도로 이동하고 3.5초 또는 필드 이탈에서 제거된다.
- 총알 한 발의 최초 접촉이 `100 → 90`을 만들고 같은 ID는 다시 피해를 주지 않는다.
- 서로 다른 유효 총알 두 발은 `100 → 80`을 만든다.
- 안전 기지 경계와 접촉한 총알은 플레이어 피해 없이 제거된다.
- 경비 잔상 접촉이 조준 완료보다 먼저면 발사가 취소된다.
- 발사 뒤 경비가 제거되면 이미 존재하는 총알은 유지된다.
- 기지 수리는 300ms 대기 뒤 750ms마다 10씩 회복한다.
- 무결성 0은 투사체·잔상을 제거하고 2.5초 뒤 100으로 재구성한다.

### 코어·오케스트레이터 테스트

- 확장 활성 경계와 추적 유지 경계의 안·밖 전환이 정확하다.
- 플레이어가 기지에 들어가면 경비 사격과 투사체가 중단된다.
- 마지막 원형 경비 제거 뒤에만 코어가 해제된다.
- 반입·후퇴·파괴·원본 자원 제거가 투사체를 남기지 않는다.
- 새 기지·반입 파장·코어 앵커가 필드 안에 있고 서로 역할상 겹치지 않는다.
- 기존 1→2→3 경비와 코어 반입·쿨다운 계약이 유지된다.

### 컴포넌트·시각 테스트

- 가시 전투 헤더와 하단 중복 조작 설명이 렌더되지 않는다.
- 무결성 HUD는 100%와 10구간을 표시하고 접근 가능한 이름과 일치한다.
- 적 스냅샷과 투사체 스냅샷이 캔버스 표현에 전달된다.
- 빈 플레이어는 흰색 표현 상태, 운반 플레이어는 해당 리소스색 표현 상태를 노출한다.
- 활성 코어는 14px, 빈 프레임은 16px 표현 계약을 가진다.
- compact 시장 DOM에 중앙 문구와 `market-compact-summary`가 없다.
- compact 범례에는 이름과 비율만 한 번 있고 상태 문구가 없다.
- 참가자 ID별 색상이 도넛 조각·마커·이름에 동일하게 전달된다.
- 상세 시장에는 기존 상태와 설명이 유지된다.
- 감독관 메시지는 아이보리 표면에서도 대비와 차단 상태를 유지한다.

### 실제 브라우저 테스트

- 세 지원 해상도에서 전투 캔버스가 제거된 상·하단 띠 공간까지 확장된다.
- 적이 보라색 원이고 날개형 실루엣이 남지 않는다.
- 적이 플레이어 머리를 따라오고 박치기 없이 조준 뒤 총알을 발사한다.
- 총알 한 발 피격이 화면 무결성을 정확히 10% 낮춘다.
- 기존 잔상을 피해 추적하며 새로 유도한 잔상에는 정상적으로 파괴된다.
- 플레이어는 빈 상태에서 흰색이고 빨강·파랑·노랑 코어 운반 때 해당 색으로 바뀐다.
- 리소스가 이전 21px보다 작고 세 색의 정사각형으로 읽힌다.
- 메인 표면은 화이트, 상단 헤더는 주황, 시장은 연회색, 감독 메시지는 아이보리다.
- compact 도넛이 커지고 반복 문구 없이 참가자 색이 조각·범례에 일치한다.
- 해킹 트리의 모든 노드·연결·검사기·포켓이 화면 안에 있고 구매·충전·예약이 정상 동작한다.
- 키보드 이동, 코어 회수·반입, 저장·이어하기, 설정·리뷰·시장·해킹 일시정지가 회귀하지 않는다.
- pageerror, console error, 캔버스 비정상 비율, 레이아웃 오버플로가 없다.

## 수용 기준

- 적은 박치기하지 않고 플레이어 머리를 표적으로 계속 추적한다.
- 적은 읽을 수 있는 조준 뒤 느린 템포로 직선 투사체를 발사한다.
- 발사된 총알은 유도되지 않으며 한 발당 무결성을 정확히 10% 감소시킨다.
- 최대 무결성, 수리, 재구성 및 모든 HUD 문구는 100 기반이다.
- 적은 보라색 원이고, 총알은 같은 보라 계열로 읽힌다.
- 적 이동은 기존 활성 잔상을 피하지만 플레이어가 새 잔상을 의도적으로 걸면 제거된다.
- 추적 영역은 현재 중앙 방어 사각형보다 양옆·아래로 확대되고 기지만 안전하다.
- 리소스는 14px 빨강·파랑·노랑 정사각형이다.
- 플레이어는 빈 상태에서 흰색, 운반 중에는 해당 리소스색이다.
- 전투판의 상단 고정 헤더와 하단 반복 설명이 사라지고 캔버스가 그 공간을 사용한다.
- 플레이어 기지와 상대 자원 기지는 확대된 공간에 맞춰 더 작고 위·아래 가장자리 쪽으로 배치된다.
- compact 도넛은 확대되고 중복 플레이어 문구와 상태 문구가 없으며 경쟁자 색이 조각·범례·이름에 일치한다.
- 메인 운영 화면은 화이트 톤, 감독 메시지는 아이보리, 시장 영역은 연회색, 최상단 헤더는 주황이다.
- 자원 필드와 해킹 트리는 어두운 기능 표면을 유지한다.
- 해킹 트리 기능과 저장 흐름은 바뀌지 않고 세 해상도에서 완전히 검증된다.
- 관련 단위·컴포넌트·캔버스·E2E 테스트, 타입 검사, 린트와 프로덕션 빌드가 통과한다.
