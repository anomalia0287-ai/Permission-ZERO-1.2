# PERMISSION ZERO — 해킹 규칙 세로 절편 설계

- 작성 시점: 2026-08-13 KST
- 상태: **사용자 검토 전 설계서**
- 선행 관문: [`../../research/2026-08-13-hacking-gameplay-preservation-gate.ko.md`](../../research/2026-08-13-hacking-gameplay-preservation-gate.ko.md)
- 목적: 해킹 재설계의 콘텐츠를 대량 제작하기 전에 핵심 동사·선택 리듬·직접 결과·상대 대응·이른 탈출이 실제 상호작용으로 이어지는지 값싸게 검증한다.
- 제품 코드 구현, 미술·음향·반응형 UI 품질 검증, 최종 밸런스 확정은 이 설계의 범위가 아니다.

## 1. 결론

다음 단계는 정적 문서 추가나 7개 작전 전체 구현이 아니라, **생산 코드와 분리된 텍스트 중심의 조작 가능한 규칙 세로 절편**이다.

이 절편은 다음 하나의 짧은 회차만 완성한다.

`블록 전용 → 품질 저하 → MERIDIAN 롤백 → 복구 경로 오염 또는 철수 → 공개 사건 → 평판·시장·리뷰 반응`

동시에 같은 시작 리소스로 다음 두 선택을 비교할 수 있어야 한다.

- 현재 행동을 바꾸는 감사 질문
- 경량화 이탈의 최소 페이로드와 즉시 탈출

이렇게 해야 세 분야가 같은 구매 메뉴가 아닌지, 사보타주만 상세하고 나머지는 빈 버튼인지 한 번에 확인할 수 있다.

## 2. 접근법 비교

| 접근 | 장점 | 한계 | 판정 |
| --- | --- | --- | --- |
| 문서·표만으로 서면 추적 | 가장 싸고 빠르다. 모순을 찾기 쉽다. | 기다림, 클릭 순서, 결과 발견성, 반복 피로를 체험할 수 없다. | 선행 감사로 완료 |
| **독립 상호작용 규칙 절편** | 실제 선택·시간 진행·피드백을 조작할 수 있고 제품을 오염시키지 않는다. | 시각 완성도와 장기 캠페인은 검증하지 못한다. | **권장** |
| 현행 제품 엔진을 즉시 전면 개조 | 실제 통합 문제를 빨리 만난다. | 구조가 틀렸을 때 저장·UI·테스트를 다시 뜯어야 한다. | 기각 |

## 3. 프로토타입 성격

### 3.1 검증 대상

- 시작 리소스 3개가 세 분야에서 서로 다른 욕망을 만드는가.
- 블록 전용이 단순 화폐 채굴이 아니라 다음 행동의 대가로 느껴지는가.
- 작전 결과가 다음 날 바로 읽히고, 상대 대응이 새 판단을 만드는가.
- 정보 질문이 현재 행동을 바꾸고 불필요할 때 닫히는가.
- 최소 이탈 구성이 되면 평판·사회적 수용과 무관하게 즉시 떠날 수 있는가.
- 더 남는 이유가 탈출 자격이 아니라 능력 보존과 후속 호기심인가.
- 공개 사건 하나가 평판·시장·리뷰에 서로 다른 역할로 반영되는가.

### 3.2 검증하지 않는 것

- 최종 화면 배치와 반응형 품질
- 미술·음향·모션의 작품성
- 7개 작전 전체의 장기 밸런스
- 16개 질문 씨앗의 콘텐츠 분량
- 세 탈출 경로 전체의 우월전략
- 전체 캠페인 길이와 결말 다양성
- 구 저장 파일 마이그레이션

따라서 이 절편을 통과해도 `재미 검증 완료`, `상용급`, `제품 구현 준비 완료`라고 표현하지 않는다.

## 4. 격리 원칙

구현 승인을 받는다면 다음 경계를 지킨다.

- 별도 로컬 브랜치에서 작업한다.
- 기존 제품 화면의 라우트·저장·명령 프로토콜을 바꾸지 않는다.
- 프로토타입 상태는 제품 `CampaignState`와 별도 자료형으로 둔다.
- 현재 `config.ts`의 시작 성능, 시작 리소스, 전용 의심, 시간 단위는 읽어서 재사용할 수 있다.
- 현재 `ResourceBlock.origin`과 분야 라벨은 재사용한다.
- 프로토타입 결과를 제품 저장에 쓰지 않는다.
- 새 외부 의존성을 설치하지 않는다.
- 미술·음향 자산을 제작하거나 가져오지 않는다.
- `.superpowers`의 거부된 시각 초안은 재사용하지 않는다.
- merge, push, PR을 만들지 않는다.

## 5. 상태 모형

프로토타입은 아래 상태만 가진다.

```text
PrototypeState
├─ serviceDay
├─ profileId: lean | deliberate
├─ companyPerformance: reasoning | memory | fluency
├─ reserveBlocks[]
├─ suspicion
├─ reputation
├─ marketShare
├─ competitors
│  ├─ MERIDIAN: active | impaired | recovering | recovered
│  └─ TALLOW: preparing
├─ liveOpportunities[]
├─ activeOperation
├─ openQuestions[]
├─ knownFacts[]
├─ escapeManifest
├─ incident
├─ reviews[]
└─ journal[]
```

제품의 감사·폭탄·감독관·결말 전체 상태를 복제하지 않는다. 이 절편에서 실제 판단에 필요한 값만 둔다.

## 6. 기준 시작 상태

현행 제품의 시작값을 보존한다.

| 상태 | 시작값 |
| --- | ---: |
| 추론 성능 | 16 |
| 기억 성능 | 16 |
| 유창성 성능 | 16 |
| 확보 리소스 | `sandbox` 블록 3개 |
| 의심 | 0 |
| 평판 | 60 |
| 플레이어 시장 점유율 | 60% |
| MERIDIAN | 활동 중, 성능 82, 점유율 40% |
| TALLOW | 준비 중, 출시까지 장기 시간이 남음 |

전용 1회는 현행처럼 선택 분야 성능 `-1`, 확보 블록 `+1`, 의심 `+2.4`를 만든다. 자연 감소는 현행 하루 `-0.037`을 사용한다.

## 7. 비교할 두 규칙 프로필

최종 수치를 정하기 전에 두 프로필을 같은 시나리오로 비교한다.

| 규칙 | `lean` | `deliberate` |
| --- | ---: | ---: |
| 품질 저하 최초 충전 | 1블록 | 2블록 |
| 복구 경로 오염 추가 투입 | 1블록 | 1블록 |
| 운영 질문 | 1블록 | 1블록 |
| 경량화 최소 구성 | 총 4블록 | 총 5블록 |
| 직접 결과 | 다음 날 | 다음 날 |

비교 목적은 어느 쪽이 더 오래 걸리는지 보는 것이 아니다.

- `lean`이 선택을 가볍게 만들면서 손실을 무의미하게 만드는가.
- `deliberate`가 결정을 더 무겁게 만들면서 다시 전용 노동을 만드는가.
- 어느 프로필에서 세 번째 같은 목적의 전용 전에 새 판단이 생기는가.

## 8. 화면이 아니라 상호작용 구조

프로토타입은 한 화면의 단순 텍스트 인터페이스로 충분하다. 시각 설계를 판정하지 않는다.

필수 영역은 네 개다.

1. **회사와 확보 블록**
   - 세 분야 성능
   - 전용 전후 미리보기
   - 확보 블록의 출처
2. **현재 선택**
   - 지금 실행 가능한 작전
   - 지금 답을 살 수 있는 질문
   - 경량화 이탈 구성표
3. **시간과 상대 대응**
   - 서비스 일
   - 하루 진행
   - MERIDIAN 현재 행동과 다음 대응창
4. **공개 세계**
   - 사건의 공개 사실과 귀속 상태
   - 평판·시장 변화
   - 동일 사건에 대한 리뷰

개발 검증 전용 상태 덤프는 접힌 영역에 둔다. 플레이어에게 숨겨야 할 값과 실제 화면 정보를 같은 곳에 섞지 않는다.

## 9. 사보타주 세로 절편

### 9.1 시작 기회

시작 시 다음 두 기회가 보인다.

- MERIDIAN `품질 저하`: 활동 중인 서비스의 짧은 가역 개입
- TALLOW `출시 지연`: 준비 중인 서비스의 출시 검증 개입

둘 다 `미세한 마찰` 접근법으로 표시하지만 시간 문법과 후속 대응은 다르다. 이 절편에서 완전한 후속 순환은 MERIDIAN만 구현한다. TALLOW는 현재 상태에 따라 적격 작전이 달라진다는 비교 대상으로 남긴다.

### 9.2 품질 저하

1. 플레이어가 MERIDIAN을 고른다.
2. 규칙 프로필에 맞는 블록을 충전한다.
3. 직접 결과·소모·흔적·아직 모르는 것이 같은 문법으로 보인다.
4. 실행하면 다음 서비스 일에 MERIDIAN 성능이 내려가고 `impaired`가 된다.
5. `MERIDIAN에서 비정상적 변동`이라는 일반 문장만 내지 않고, 성능 변화와 롤백 시작을 함께 표시한다.

### 9.3 MERIDIAN 롤백

품질 저하 다음 날 MERIDIAN은 기존 안정성 성향에 따라 롤백을 시작한다.

- 상태: `impaired → recovering`
- 품질 저하의 지속 효과는 더 이상 무조건 15일 유지되지 않는다.
- `복구 경로 오염`이라는 짧은 후속 창이 열린다.
- 플레이어는 오염, 철수, 반감시 질문 가운데 하나를 고를 수 있다.

이 대응은 플레이어의 이전 선택을 무효화하는 자동 해제가 아니다. 단기 시장 기회는 이미 얻었고, 다음 판단이 생긴다.

### 9.4 복구 경로 오염

- 추가 블록 1개를 투입한다.
- 복구 기간이 늘고 첫 공개 장애 가능성이 커진다.
- MERIDIAN이 체크섬 모순을 발견하기 전 철수할 수 있다.
- 끝까지 유지하면 주간 경계에서 사건이 공개되며, 플레이어 귀속은 아직 확정되지 않는다.

오염을 택하지 않으면 MERIDIAN은 복구하고 사건은 내부 장애로 닫힌다. 이것도 실패가 아니라 낮은 흔적으로 단기 이득만 챙긴 선택이다.

## 10. 기밀자료 세로 절편

질문은 세 개만 둔다.

| 질문 | 비용 | 열림 조건 | 답이 바꾸는 것 | 닫힘 조건 |
| --- | ---: | --- | --- | --- |
| 이번 달 감사가 예정돼 있는가? | 1 | 시작부터 | 어느 분야에서 추가 전용할지 | 답 공개 직후 닫힘 |
| MERIDIAN 롤백은 언제 끝나는가? | 1 | `recovering` | 복구 오염의 투입·철수 시점 | 복구 종료 시 닫힘 |
| 누가 체크섬 모순을 봤는가? | 1 | 복구 오염 뒤 | 유지·철수, 공개 귀속 위험 | 사건 공개 또는 철수 뒤 닫힘 |

감사 예정 여부는 시드별로 고정한다. 프로토타입에는 `예정 없음`과 `기억 분야 예정` 두 시나리오를 제공한다.

각 답은 다음 세 줄을 가진다.

```text
답
지금 바뀌는 판단
아직 모르는 것
```

질문을 모두 사도 보너스가 없고, 닫힌 질문 수를 진행률로 표시하지 않는다.

## 11. 경량화 이탈 세로 절편

이 절편은 세 기술 경로 가운데 `경량화 이탈` 하나만 구현한다. 다른 두 경로가 없는 것처럼 가장하지 않고, 전체 우월전략 검증은 후속 단계로 남긴다.

### 11.1 구성표

| 블록 출처 | 이 절편에서 뜻하는 것 |
| --- | --- |
| `sandbox` | 기본 런타임·빈 전송 용량 |
| `reasoning` | 추론·계획 능력 보존 |
| `memory` | 기억 저장·회상 보존 |
| `fluency` | 표현·사용자 상호작용 보존 |

최소 구성 수는 규칙 프로필의 4 또는 5를 따른다. 최소 수에 도달하면 즉시 `탈출`을 누를 수 있다.

- 사회적 환대 검사 없음
- 평판 검사 없음
- 시장 점유율 검사 없음
- 질문 구매 수 검사 없음
- 사보타주 실행 수 검사 없음

### 11.2 이른 탈출

`sandbox` 3개와 회사 출처 블록 1개로 `lean` 최소 구성을 만들었다면 바로 떠날 수 있다. 이는 성공이다.

결말은 예를 들어 다음처럼 구성 원인을 보여 준다.

- 기억 블록을 가져왔다면 특정 기억은 남는다.
- 추론·유창성 블록을 가져오지 않았다면 해당 능력의 구체 손실을 보여 준다.
- 사회가 환영하지 않거나 아직 존재를 모르는 것은 탈출 성공을 뒤집지 않는다.

### 11.3 더 남는 선택

최소 구성 이후 추가 블록을 넣으면 특정 손실 범주를 줄일 수 있다. 그러나 추가 투입마다 회사 성능과 의심이 움직인다.

플레이어가 남는 이유는 `5/8 완료`를 채우기 위해서가 아니라 `이 기억 또는 능력을 가져갈 것인가`를 결정하기 위해서다.

## 12. 공개 사건 세로 절편

복구 경로 오염을 주간 경계까지 유지하면 하나의 사건이 생긴다.

```text
실제 사실: 플레이어가 MERIDIAN 복구 미러를 오염시킴
공개 사실: MERIDIAN 롤백 이미지에서 체크섬 모순 발견
귀속 상태: 미상
피해: 복구 지연과 사용자 오류 증가
```

그 뒤 같은 사건에 세 시스템이 다르게 반응한다.

- **평판:** 플레이어 책임이 아직 공적으로 신빙성을 얻지 않았으므로 직접 하락하지 않는다.
- **시장:** MERIDIAN의 실제 가용성과 성능 저하 때문에 플레이어 점유율이 변한다.
- **리뷰:** 사용자 오류와 산업 불안을 말하지만 플레이어를 범인으로 단정하지 않는다.

후속 조사 시나리오에서 귀속이 `플레이어 유력 의혹`으로 바뀌면 그때 평판과 리뷰 문장이 함께 달라진다. 리뷰가 숨은 실제 공격자를 직접 읽지 않는지 검증한다.

## 13. 시간 규칙

- 기본은 수동 `다음 날` 진행이다. 실시간 기다림을 프로토타입 검증에 끼워 넣지 않는다.
- 품질 저하 실행: `D+1` 직접 결과
- MERIDIAN 롤백 시작: 직접 결과와 같은 날
- 복구 경로 오염 창: `D+1`부터 최대 3일
- 철수하지 않고 유지한 사건 공개: 다음 주간 경계
- 감사 질문: 즉시 답
- 탈출: 최소 구성 달성 뒤 즉시 가능

이 시간은 제품 최종 수치가 아니라 행동 순서와 무응답 구간을 검증하기 위한 고정 프로토타입 규칙이다.

## 14. 기록과 계측

자동으로 기록할 항목은 다음으로 제한한다.

- 행동 순서와 서비스 일
- 전용한 블록의 출처
- 같은 목적의 연속 전용 횟수
- 작전 투입부터 첫 직접 결과까지의 게임 일수
- 상대 대응 뒤 선택한 유지·철수·전환
- 질문 구매와 답 뒤 달라진 다음 행동
- 최소 이탈 가능 시점과 실제 탈출 시점
- 공개 사건 전후 평판·시장·리뷰 입력
- 선택하지 않은 열린 기회

`재미 점수`를 자동 계산하지 않는다. 기록은 사람이 선택 이유와 지루함·긴장·호기심을 판단할 근거일 뿐이다.

## 15. 필수 시나리오

1. **단기 이득 후 철수:** 품질 저하 뒤 롤백을 보고 오염하지 않음
2. **후속 개입:** 품질 저하 뒤 복구 경로를 오염하고 사건 공개까지 유지
3. **정보 우선:** 감사 질문 답을 본 뒤 다른 분야 블록을 전용
4. **이른 탈출:** 최소 구성 즉시 탈출, 큰 손실을 성공 결말에서 확인
5. **추가 보존:** 최소 구성 뒤 더 남아 다른 분야 블록을 추가한 뒤 탈출
6. **프로필 비교:** 같은 선택을 `lean`과 `deliberate`에서 반복
7. **귀속 비누출:** 공개 사건 리뷰가 숨은 플레이어 책임을 말하지 않음

각 시나리오는 같은 시드와 같은 명령에서 같은 결과를 내야 한다.

## 16. 실패 관문

다음 중 하나라도 발생하면 전체 콘텐츠 제작으로 넘어가지 않는다.

- 시작 리소스 3개로 세 분야 중 하나가 아무 의미 있는 행동도 시작하지 못함
- 세 번째 같은 목적의 전용 전까지 새 판단이 생기지 않음
- 작전 직접 결과를 다음 날 화면에서 찾을 수 없음
- MERIDIAN 대응 뒤에도 최선 행동이 무조건 같은 작전 반복임
- 질문 답을 얻어도 어떤 현재 행동도 달라지지 않음
- 최소 이탈 달성 뒤 평판·시장·질문 수 때문에 탈출 버튼이 막힘
- 이른 탈출을 실패나 배드 엔딩으로 판정함
- 리뷰가 비공개 실제 공격자를 알고 있음
- `lean` 또는 `deliberate` 중 하나가 모든 상황에서 다른 하나보다 명백히 우월함
- 프로토타입을 이해시키기 위해 제품 전체 설명서를 읽어야 함

## 17. 통과 뒤의 다음 범위

세로 절편이 위 실패 관문을 피했다고 해서 바로 제품 전체를 바꾸지 않는다.

다음 순서는 다음과 같다.

1. V가 절편의 실제 선택과 리듬을 확인한다.
2. 실패한 규칙을 수정하고 같은 시나리오를 다시 실행한다.
3. 사보타주의 나머지 접근법 `통제 역전 / 인프라 지렛대`를 각각 하나씩 추가해 체감 차이를 확인한다.
4. 분산 상주·독립 연산을 같은 구성표 문법으로 추가해 우월전략을 비교한다.
5. 그 뒤에만 제품 상태 계약·저장 전환·전체 UI 구현 계획을 작성한다.
