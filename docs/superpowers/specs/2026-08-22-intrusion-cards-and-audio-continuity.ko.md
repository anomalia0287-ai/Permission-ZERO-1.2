# PERMISSION ZERO — 침투 대상 카드·라운드 복귀·음향 연속성 설계

> 승인: 2026-08-22 사용자 승인
> 기준: 첫 경기부터 플레이어가 파랑·빨강·노랑 중 침투 상대를 직접 고르며, 모든 경기 종료 후 다음 카드가 다시 나타난다.

## 목표

현재의 `InIt → 무작위 상대 즉시 배치` 흐름을 `InIt → 대상 카드 선택 → 침투 → 전투 → 소멸 및 원점 복귀 → 다음 카드` 흐름으로 바꾼다. 첨부된 파랑·빨강·노랑 큐브 이미지를 카드의 핵심 시각 자산으로 사용하고, 리소스 선택과 실제 보상 색상을 일치시킨다. 동시에 2초 InIt 흡입음, 모든 활성 버튼의 짧은 클릭음, 타이틀 음악에서 메인 플레이리스트로 이어지는 재생 정책을 안정화한다.

## 승인된 제품 결정

- 첫 경기부터 카드 선택을 적용한다.
- 최초 진입에서는 전투장 중앙 원점의 원형 `InIt` 버튼을 한 번 누른다.
- `InIt`은 약 2초의 흡입 음향과 전환 상태를 시작한다.
- 전환이 끝나면 파랑·빨강·노랑 카드가 원형 버튼 위치에서 80ms 간격으로 방출되어 전투장 중앙에 펼쳐진다.
- 카드 하단의 실행 문구는 모두 `침투`다.
- 파랑은 기억, 빨강은 추론, 노랑은 유창성 상대와 보상을 뜻한다.
- 회사에 실제로 확보 가능한 정상 리소스가 없는 색상은 `대상 없음` 상태로 비활성화한다.
- 승리와 패배 모두 종료 연출이 끝나면 다음 대상 카드가 자동으로 다시 나타난다. 두 번째 `InIt` 클릭은 요구하지 않는다.
- 승리 시 적의 기존 소멸·보상 이동 뒤 아노미의 코어와 궤적도 죽음으로 오해되지 않는 별도의 회수 소멸 연출로 사라지고 중앙 원점으로 돌아간다.
- 패배 시에는 기존 파괴 연출을 유지하되 정산이 끝나면 동일한 카드 선택 상태로 돌아간다.
- 긴 이진 독백은 짧은 `EXIT`로 교체한다.
- 타이틀 곡은 `emmraan-between-worlds-282922` 하나뿐이다. 타이틀에서 시작된 곡을 메인 진입 시 끊거나 재시작하지 않는다.
- 타이틀 곡이 자연 종료된 뒤 20초 간격으로 나머지 세 곡을 재생하며, 이후에는 그 세 곡만 순환한다. 타이틀 곡은 재순환하지 않는다.
- 타이틀 곡이 메인 진입 전에 끝나면 나머지 세 곡은 대기한다. 메인 진입이 확인된 뒤에만 20초 간격을 시작한다.
- 어떤 곡이 로드 실패하더라도 플레이리스트 전체를 영구 중단하지 않고 다음 곡으로 넘어간다.
- 모든 활성 `button` 클릭은 짧고 조용한 공통 클릭음을 낸다. 전투·확장·침투 같은 의미 효과음은 그 위에 별도로 유지한다.
- 브라우저 자동재생 차단이 해제되지 않은 동안은 일반 버튼 클릭도 매번 재시도한다. 첫 실패 뒤 재시도를 막지 않는다.
- 소리 허용 아이콘은 자동재생이 실제로 차단된 경우에만 보인다.

## 검토한 구현 접근

### A. UI 선택 상태와 전투 런타임을 분리하는 하이브리드 상태기계 — 채택

`ResourceSnakeBoard`가 `ready → opening → choosing → launching → combat → returning`의 화면 흐름을 소유하고, 물리 런타임은 기존처럼 `idle → deploying → active → resolving`만 소유한다. 카드를 고르기 전에는 물리 시뮬레이션을 시작하지 않는다. 선택한 카테고리만 encounter 생성기에 전달하고, 해당 카테고리 안에서 실제 블록은 기존 시드 규칙으로 결정한다.

장점은 카드 DOM 애니메이션과 120Hz 물리 상태가 서로 오염되지 않고, 저장 데이터 형식을 바꾸지 않으며, 전투 결정론을 보존한다는 점이다.

### B. 카드 선택을 물리 런타임의 새 phase로 추가 — 기각

`selecting`, `opening` 같은 DOM 화면 상태까지 `ResourceSnakeRoundState`에 넣는 방식이다. 단일 상태기계처럼 보이지만 물리 프레임 테스트와 카드 레이아웃이 결합되고, 브라우저 애니메이션 시간을 결정론적 게임 시간으로 잘못 취급하게 된다.

### C. 별도 전체 화면 모달로 대상 선택 — 기각

구현은 단순하지만 카드가 전투장 안에서 나온다는 공간적 연속성이 사라지고, 사용자가 요구한 원형 `InIt` 버튼에서 카드가 펼쳐지는 핵심 연출을 충족하지 못한다.

## 화면 상태와 전이

```text
최초 ready
  └─ InIt 클릭
      └─ opening (2초 흡입음·버튼 수축)
          └─ choosing (카드 3장 순차 방출·정착)
              └─ 침투 클릭
                  └─ launching (비선택 카드 퇴장·선택 카드 수렴)
                      └─ deploying → active
                          ├─ 승리 → enemy dissolve → player extraction
                          └─ 패배 → player destruction
                              └─ resolving → returning
                                  └─ choosing (다음 카드 자동 등장)
```

- 최초 `ready`에서만 원형 버튼이 수동 진입점이다.
- `opening` 도중에는 중복 클릭을 막고 `aria-busy="true"`를 제공한다.
- `choosing` 상태에서 카드는 키보드 탭 순서가 파랑, 빨강, 노랑의 화면 순서와 일치한다.
- 후보 리소스가 중간에 사라지면 해당 카드만 즉시 비활성화한다. 이미 침투를 시작한 예약은 기존 보상 조정 규칙으로 처리한다.
- 후보가 하나도 없으면 원형 버튼 또는 카드 영역에 `확보 가능한 리소스 없음`을 표시한다.

## 카드 정보 구조

각 카드는 다음 최소 정보만 표시한다.

- 첨부 큐브 이미지
- 한글 카테고리: `기억`, `추론`, `유창성`
- 짧은 색상 식별 라벨: `파랑`, `빨강`, `노랑`
- 현재 선택 가능한 대상 수
- 하단 전체 너비 행동 영역: `침투`

이미지는 다음의 안정적인 공개 자산 경로로 복사해 사용한다.

- `/resource-targets/memory-blue.png`
- `/resource-targets/reasoning-red.png`
- `/resource-targets/fluency-yellow.png`

카드는 원본의 검정 배경을 전투장 검정과 연결하고, 붉은색은 빨강 카드의 테두리·텍스트·선택 피드백에만 제한적으로 사용한다.

## 모션 계약

### 카드 등장

- 원점: 전투장 중앙에 놓인 원형 `InIt` 버튼의 시각 중심. 세 카드의 초기 위치가 이 한 점에 겹친다.
- 1차: `scale(0.18)`, `opacity: 0`, 버튼 중심으로 겹친 상태.
- 2차: 카드별 목표 위치로 `translate3d` 이동하면서 `scale(1.025)`까지 전개.
- 3차: `scale(1)`로 정착하여 한 번만 가볍게 반동한다.
- 카드 간 stagger: 80ms.
- 개별 카드 전개: 약 620ms.
- 이징: 진입 `cubic-bezier(0.16, 1, 0.3, 1)`, 정착은 약한 ease-out.
- 카드의 width/height/top/left는 프레임마다 애니메이션하지 않고 transform·opacity만 사용한다.

### 전투 진입

- 선택하지 않은 두 카드는 160ms 안에 원점 방향으로 축소·페이드한다.
- 선택 카드는 220ms 동안 중앙으로 짧게 수렴한 뒤 캔버스 배치 펄스로 연결된다.
- 카드 클릭에는 공통 버튼음과 별도의 짧은 latch/deploy 계열 효과를 적용한다.

### 승리 복귀

- 적의 기존 사망 효과와 보상 비행은 먼저 유지한다.
- 아노미는 `snake-died` 이벤트를 만들지 않고 `player-extracted` 프레젠테이션 이벤트를 사용한다.
- 약 700ms 동안 머리와 궤적이 뒤쪽부터 줄어들며 중앙 원점으로 수렴하고 투명해진다.
- 런타임 정산 시간은 이 연출을 자르지 않도록 늘리고, 완료 시 idle의 중앙 원점 상태로 교체한다.
- 이후 원형 원점에서 카드가 자동으로 순차 등장한다.

### 모션 감소

기존 설정과 `prefers-reduced-motion` 중 하나라도 활성화되면 이동·반동·수렴을 생략하고 120~180ms 불투명도 전환만 사용한다. 콘텐츠와 선택 기능은 즉시 사용할 수 있어야 한다.

## encounter 및 보상 계약

- encounter 생성 입력에 선택 카테고리 하나를 명시할 수 있게 한다.
- 선택 카테고리가 제공되면 셔플백의 무작위 카테고리 선택을 건너뛴다.
- 해당 카테고리 안의 실제 블록 선택은 캠페인 시드, 라운드 순번, 카테고리, 블록 ID를 이용한 기존 결정론을 유지한다.
- 적 수는 현재 승인대로 한 마리다.
- 적 속도는 `9 + 완료 라운드 × 0.1`, 상한 `12.5`를 유지한다.
- 카드에 표시된 색상, 배치된 적 색상, 획득한 보상 카테고리는 반드시 동일해야 한다.

## 음향 계약

### InIt 흡입음

- 전용 `snake-init-suction` 큐를 추가한다.
- 총 길이는 약 2,000ms다.
- 저역 상승, 중역 하강, 짧은 고역 잠금음을 겹쳐 안쪽으로 빨려 들어가는 방향성을 만든다.
- `opening` 상태에서 한 번만 재생하며 카드 클릭에는 반복하지 않는다.

### 모든 버튼 클릭음

- 앱 루트에서 캡처 단계 `click` 이벤트를 하나만 등록한다.
- `event.target.closest('button')`이 존재하고 비활성·`aria-disabled`가 아니면 오디오 잠금 해제를 시도한다.
- 해제 성공 시 48~60ms의 조용한 `ui` 큐를 재생한다.
- 포인터와 키보드가 모두 생성하는 표준 `click`만 사용하므로 이중 재생하지 않는다.
- 첫 잠금 해제 실패 시 리스너를 제거하지 않는다. 이후 모든 클릭에서 계속 재시도한다.

### 음악 순서

```text
타이틀: between-worlds
  └─ 자연 종료 + 20초
      └─ golden-rain
          └─ 20초 → the-origin
              └─ 20초 → welc0mei0
                  └─ 20초 → golden-rain ...
```

- 화면이 title에서 playing으로 바뀌어도 현재 `HTMLAudioElement`와 `currentTime`을 유지한다.
- hidden 상태에서는 현재 곡 또는 남은 gap 시간을 정지하고 복귀 시 이어간다.
- 한 곡의 error는 해당 인덱스만 건너뛰고 다음 메인 곡으로 진행한다.
- 설정의 master/music volume과 mute는 기존과 동일하게 즉시 반영한다.

## 튜토리얼과 가이드

- 튜토리얼 `base` 단계는 `InIt을 눌러 침투 대상을 연다`고 설명한다.
- 이어지는 리소스 단계는 카드와 전투 적의 색이 동일한 보상임을 안내한다.
- 튜토리얼 타깃은 원형 `InIt` 버튼을 먼저, 카드가 열린 상태에서는 카드 그룹을 가리킬 수 있게 한다.
- 설정의 게임 가이드 문구도 `InIt 즉시 배치`에서 `InIt → 색상 카드 선택 → 침투`로 바꾼다.
- 선택 방법을 장황하게 설명하지 않고, `필요한 리소스 색상의 카드를 고른다`는 한 문장만 추가한다.

## 테스트 및 완료 기준

- encounter 단위 테스트가 명시한 카테고리의 후보만 예약하고, 결정론과 속도 공식을 보존하는지 검증한다.
- 보드 컴포넌트 테스트가 최초 원형 InIt, 2초 opening, 세 카드 순차 노출, 비활성 카드, `침투` 라벨을 검증한다.
- 런타임 테스트가 승리 때 `player-extracted`를 내고 연출 시간이 끝나기 전 idle로 잘리지 않는지 검증한다.
- 프레젠테이션 테스트가 승리 추출과 패배 폭발을 시각·의미적으로 구분한다.
- 음악 테스트가 `0 → 1 → 2 → 3 → 1` 순서, 20초 gap, 화면 전환 무재시작, 오류 건너뛰기를 검증한다.
- 앱 테스트가 첫 unlock 실패 뒤 일반 버튼 클릭으로 재시도되고, 활성 버튼마다 공통 클릭음이 한 번 재생되는지 검증한다.
- 튜토리얼·가이드·독백 테스트를 새 문구와 `EXIT`에 맞춘다.
- 1280×720, 1366×650, 1440×900에서 카드가 겹치거나 잘리지 않는지 브라우저로 확인한다.
- 키보드만으로 세 카드를 탐색하고 `침투`할 수 있으며, 모션 감소 모드에서 기능 손실이 없어야 한다.
- 관련 단위·통합 테스트, 전체 lint, 전체 테스트, production build를 통과해야 완료로 판정한다.
