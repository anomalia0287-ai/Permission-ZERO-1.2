# PERMISSION ZERO — 후속 해킹 프로토타입 정본화 및 본편 통합 매뉴얼 설계

- 승인일: 2026-08-16
- 승인자: V
- 상태: 사용자 승인 완료
- 범위: 해킹 관련 문서 권위, 본편 통합 매뉴얼, 상충 문서 정리
- 구현 범위: 문서만 수정. 본편 `src/`와 프로토타입 동작은 변경하지 않음
- 작업 방식: 현재 세션에서 직접 수행하며 하위 에이전트를 사용하지 않음

## 1. 확정 판정

후속 프로토타입은 기존 본편 해킹 명세를 참고하는 보조 실험이 아니다. 기존 본편에 있던 여러 문제를 검수하고 규칙·게임성·정보 구조·화면 표현을 개선한 **후속 정본**이다.

따라서 해킹 범위에서 기존 본편 명세와 후속 프로토타입이 충돌하면 다음과 같이 처리한다.

1. 타협값을 만들지 않는다.
2. 기존 본편 규칙을 보존하기 위해 프로토타입 규칙을 축소하지 않는다.
3. 코드·저장 호환성이 불편하다는 이유로 구형 경제를 유지하지 않는다.
4. 후속 프로토타입의 규칙, 콘텐츠 구조, 인과, 탈출 계약, UI 계약을 채택한다.
5. 기존 본편은 프로토타입이 다루지 않은 비해킹 시스템의 자료로만 남긴다.
6. 비해킹 시스템도 프로토타입의 해킹 결과를 왜곡하거나 차단한다면 해킹 정본에 맞게 접점을 수정한다.

이는 두 설계의 절충안이 아니라 **영역별 명시적 대체**다.

## 2. 해결해야 하는 문서 문제

현재 저장소에는 서로 다른 시점의 판단이 함께 남아 있다.

- `PERMISSION_ZERO_STANDALONE_FINAL_SPEC.md`는 2026-08-11 기준의 구형 통합 명세다.
- 2026-08-13~14 후속 프로토타입 문서와 구현은 7개 사보타주, 16개 기밀자료, 3개 자율성 경로, 사건 기반 단계적 공개, 공개 세계 인과, 작전 장면 UI를 검증했다.
- `docs/design/2026-08-14-hacking-integration-verdict.ko.md`는 후속 프로토타입의 인과만 취하고 구형 12노드·3~18 비용 경제를 유지하는 C안을 적었다.
- `HANDOFF_COMMERCIAL_GRADE.ko.md`는 최신 체크포인트를 상단에 덧붙였지만 본문 여러 절에서 여전히 구형 경제와 화면 구조를 정본으로 지시한다.
- `docs/REPOSITORY_GUIDE.ko.md`는 구형 통합 명세를 후속 프로토타입 문서보다 위에 둔다.
- `prototypes/hacking-rules/README.ko.md`는 실행 상태는 정확히 설명하지만 후속 정본이라는 권위와 본편 통합 대상이라는 상태를 명시하지 않는다.

상단에 새 주석 하나만 더 추가하면 담당자가 아래의 상충 지시를 다시 채택할 수 있다. 정본 문서를 모듈화하고 모든 진입 문서에서 같은 권위 관계를 가리키게 해야 한다.

## 3. 검토한 문서 구조

### 접근 A — 기존 인수인계서에 추기만 추가

- 장점: 수정량이 작다.
- 실패: 1,000줄이 넘는 본문에 구형 12노드·비용·화면 지시가 그대로 남아 정본을 오인하기 쉽다.
- 판정: 기각.

### 접근 B — 구형 최종 명세 전체를 즉시 다시 작성

- 장점: 단일 파일만 보면 된다.
- 실패: 해킹과 무관한 시간·감사·폭탄·감독관·저장 규칙까지 한 번에 다시 검증해야 하며, 이번 문서 보완의 범위를 불필요하게 넓힌다.
- 판정: 기각.

### 접근 C — 후속 해킹 통합 매뉴얼을 새 정본으로 만들고 진입 문서를 정리

- 장점: 후속 해킹 규칙을 한곳에 완전하게 고정하면서 비해킹 명세를 불필요하게 복제하지 않는다. 구형 문서는 역사 자료로 보존하되 권위는 명확히 제거할 수 있다.
- 비용: 최종 명세, 인수인계서, 저장소 안내, 과거 C안, 프로토타입 README의 포인터를 함께 갱신해야 한다.
- 판정: 채택.

## 6. 구현 기술과 게임 규칙의 분리

후속 규칙을 채택한다고 프로토타입 파일을 본편에 통째로 복사해야 하는 것은 아니다. 본편의 React, 캠페인 시계, 저장, 접근성, 리뷰 콘텐츠, 결정론 기반은 재사용할 수 있다. 다만 재사용은 다음 조건을 따른다.

- 본편 타입이 후속 규칙을 표현하지 못하면 타입과 저장 포맷을 확장한다.
- 구형 노드 ID 호환성을 이유로 후속 콘텐츠를 구형 노드 아래에 숨기지 않는다.
- 프로토타입의 `@deprecated` 호환 필드는 새 제품 저장 포맷으로 가져오지 않는다.
- 프로토타입의 고정 검증 시나리오는 제품 기능이 아니라 결정론적 픽스처로 분리한다.
- 본편의 기존 리뷰 항목과 프로토타입의 공개 인과를 연결하되 중복 리뷰 모델을 만들지 않는다.
- 프로토타입의 단일 `marketShare`를 복제하지 않고 본편 시장을 단일 소유자로 유지하되, 작전 직후 사라진 수요를 플레이어에게 자동 보상하지 않도록 `unservedRequestShare`를 시장 어댑터에서 보존한다.
- 작전 옵션·귀속 출처·자비 선택은 UI나 TypeScript 유니온이 아니라 도메인·저장 경계의 중앙 허용 목록으로 검증한다.
- 프로토타입 `RouteTuning`의 `buffer`는 실제 조율이 아니라 경량화 이탈 슬롯 ID가 타입에 남은 것이므로 본편 조율 타입에는 복제하지 않는다.
- UI 선택·hover·스크롤·서랍 상태를 엔진 명령이나 결정론 기록에 넣지 않는다.

이 원칙은 구형 설계와의 타협이 아니라 후속 규칙을 유지보수 가능한 제품 구조로 구현하는 방법이다.

## 7. 검증 설계

문서 보완은 다음 검사를 통과해야 한다.

1. 모든 진입 문서와 명세–테스트 매트릭스가 새 해킹 통합 매뉴얼을 정본으로 가리킨다.
2. C안 문서가 현재 판정으로 검색되지 않고 폐기 상태로 검색된다.
3. 구형 `12노드`, `3~18`, `영구 해금` 문장이 현재 구현 지시로 남아 있지 않는다.
4. `7개 / 16개 / 3경로`, 탈출 독립성, 공개 인과, 단계적 공개가 새 매뉴얼에 명시된다.
5. 본편 미통합과 규칙 정본이라는 서로 다른 상태를 혼동하지 않는다.
6. 상대 링크가 실제 파일을 가리킨다.
7. `git diff --check`가 통과한다.
8. 제품 코드와 프로토타입 코드가 변경되지 않는다.
9. 프로토타입 콘텐츠 26개, 자율성 슬롯 15개, 소스 조율 문자열 8개, 명령 19개, 작전 옵션 12개가 정본 매뉴얼에서 각각 채택·슬롯 오염 제거·호환 제외로 전수 추적된다. 정본 조율 상태는 `untuned`와 실제 선택 6개이며 `buffer`는 슬롯으로만 남긴다.
10. 현재 타입·린트·단위·브라우저 실행 결과와 문서–코드 수치 불일치를 성공으로 과장하지 않고 현재 상태에 기록한다.
11. 작전별 옵션·귀속 출처·자비 선택의 런타임 허용 목록이 현재 미완성이라는 사실과 필요한 위조 입력 거부 회귀를 기록한다.

## 8. 승인 기록

V는 2026-08-16 다음을 확정했다.

> 후속 프로토타입은 기존 본편에 있던 여러 문제를 검수하고 개선한 버전이다. 기존 본편과 타협점을 찾지 않고 프로토타입을 기준으로 한다.

이 결정으로 문서 접근 C를 승인하며, 이후 해킹 본편 통합과 진행도 평가는 새 매뉴얼을 기준으로 수행한다.
