# PERMISSION ZERO — 현행 메인라인 상태

- 결정일: 2026-08-18
- 유일한 현행 개발선: `main`
- 플레이어 경험 기준점: `4f2a43762ffd65ed2c1b0ea97122df35c1b2180a`
- 승격 방식: 다른 개발 브랜치 병합 없이 기준점의 선형 후손을 검증 후 승격

## 현재 판정

`main`에 있는 게임이 현재 개발 대상이다. 다른 로컬·원격 브랜치는 비교 자료와 복구 자료로만 보존하며, 명시적인 재개 결정 없이는 서로 합치거나 그 위에서 후속 기능을 개발하지 않는다.

과거 브랜치명·문서명에 남은 `prototype`, 단계 번호, WIP, 정본 후보 같은 표현은 당시 이력을 식별하는 원문일 뿐이다. 현행 개발 결과를 분류하는 용어로 사용하지 않는다. 새 작업은 `main`에서 분기한 구체적인 기능 또는 수정 이름을 사용하고, 완료 뒤 검증된 변경만 다시 `main`에 반영한다.

## 플레이어 경험 기준

현재 게임은 다음 한 덩어리의 경험을 유지한다.

1. 왼쪽 리뷰·시장, 중앙 500×300 자원 절도 필드, 오른쪽 운영 도크가 한 화면을 이룬다.
2. 플레이어는 중앙 필드에서 이동하고, 별도 유지 입력으로 자원을 훔친 뒤 하단 상자까지 직접 운반한다.
3. 신호는 예고이며 활성 감시만 절도·운반을 적발한다. 벽은 플레이 시간에 따라 누적된다.
4. 확보한 자원은 분야별 비용을 맞춰 해킹 노드를 구매하고, 사보타주를 별도 충전해 대상에게 예약하는 데 사용한다.
5. 공식 감사의 위장 배치와 감사 뒤 원래 분야 복구는 끊기지 않는다. 위장 또는 복구 중인 블록이 있으면 복구 가능한 자원 작업대를 유지하고, 복구 완료 뒤 중앙 침투 필드로 돌아간다.
6. 숨은 폭탄, 감독관 심문, 기밀 파일, 감독관 결정, 경쟁 AI 자비 요청과 복수 결말은 기존 저장·명령 의미를 유지한다.
7. save v8, PZ8, command v4, 기존 콘텐츠 ID와 한국어 대사는 그대로 유지한다.

세부 보존 계약과 구조적 수정 범위는 [메인 안정화 설계](superpowers/specs/2026-08-18-main-stabilization-design.md)에 기록되어 있다.

## 문서 우선순위

충돌이 생기면 다음 순서로 판정한다.

1. 현재 `main`에서 실제로 실행되는 게임 동작과 통과하는 테스트
2. 이 문서와 2026-08-18 메인 안정화 보존 계약
3. 현재 콘텐츠·시스템 명세
4. 날짜가 붙은 과거 계획, 인수인계, 거부 설계, 브랜치별 기록

과거 문서는 삭제하거나 문맥을 고쳐 쓰지 않는다. 대신 현재 결정을 소급해 덮어쓰지 않는 역사 자료로 읽는다.

## 검증 기준

승격 후보는 다음 단일 명령을 새로 실행해 모두 통과해야 한다.

```powershell
pnpm verify
```

2026-08-18 승격 검증에서 확인한 범위는 다음과 같다.

- TypeScript 타입 검사 통과
- ESLint 전체 검사 통과
- Vitest 55파일, 1,070개 테스트 통과
- 프로덕션 빌드 통과
- Chromium 1280×720 및 1440×900에서 Playwright 42개 테스트 통과
- 기준 캡처와 현재 1440×900 화면의 세 열 구성, 중앙 격자, 반출 상자, 우측 도크 직접 대조

Node.js 기준 버전은 저장소에 고정된 `24.14.0`이다. 다른 패치 버전에서 통과했더라도 릴리스 환경에서는 고정 버전을 우선한다.

## 이력 동결

승격 시점의 모든 고유한 비-main 브랜치 끝과 일반 브랜치 밖의 보존 스냅샷은 `frozen/2026-08-18/` 주석 태그로 고정한다. 태그 메시지에는 원래 참조 이름과 정확한 커밋을 기록한다.

- 기존 브랜치를 삭제하지 않는다.
- 기존 브랜치끼리 병합하지 않는다.
- 동결 태그를 이동하거나 재사용하지 않는다.
- 과거 결과를 다시 검토하려면 동결 태그에서 별도 브랜치를 만들고, 현재 `main`의 지위를 자동으로 부여하지 않는다.
- 승격 결과 자체는 `release/2026-08-18-main-unification` 주석 태그로 식별한다.

정확한 현재 커밋은 문서에 복사된 짧은 해시가 아니라 `git rev-parse main`과 원격 `main`을 조회해 확인한다.
