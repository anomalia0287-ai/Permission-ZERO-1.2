이 문서는 `codex/hacking-rules-prototype` 브랜치의 현재 작업을 다른 세션이 추측 없이 이어받기 위한 사실 기록이다. 아래 판정과 수치는 이전 검증 문서와 `HANDOFF_COMMERCIAL_GRADE.ko.md`의 오래된 해킹 프로토타입 수치보다 우선한다.

## 0. 현재 판정

**구조와 규칙 연결은 구현됐지만, 현재 화면 문장과 용어는 사용자 승인을 받지 못했다. 작업 완료가 아니다.**

가장 최근 사용자 지적은 다음 두 가지다.

- 설명을 화면 곳곳에 반복해서 붙이지 말 것. 목록에는 판단에 필요한 최소 정보만 두고, 선택한 항목의 상세만 인접 정보창에 보여 줄 것.
- 번역투·개발자식 추상어·제작자만 알아듣는 용어를 버리고, 플레이어가 행동과 결과를 즉시 떠올릴 수 있는 자연스러운 한국어를 사용할 것.

따라서 다음 담당자는 반응형 테스트를 마저 통과시키는 것만으로 작업을 끝내면 안 된다. **가시 문구 전수 감사와 정보 중복 제거가 다음 작업의 첫 관문**이다. 기존 규칙 수치와 상태 전이는 이 문구 정리 과정에서 바꾸지 않는다.

## 2. 반드시 보존할 사용자 승인 사항

다음은 화면 문구가 아니라 게임 규칙·구조에 관한 승인 사항이다.

- 해킹 항목은 처음부터 전부 펼치지 않고 사건과 진행에 따라 단계적으로 연다.
- 목록에는 항목명, 짧은 목적, 비용 또는 상태만 둔다. 선택한 항목의 설명과 조작은 하나의 상세창에 둔다.
- 사보타주, 기밀자료, 자율성은 이름만 다른 동일 카드 목록이 아니라 서로 다른 행동과 장면을 가져야 한다.
- 실행 전에는 플레이어가 통제하는 직접 결과와 상대의 다음 대응을 알 수 있어야 한다. 아직 모르는 내용과 근거는 요청할 때만 펼친다.
- 공개된 해킹 사건은 좌측 유저 리뷰와 평판에 같은 공개 사실을 원인으로 반영한다. 숨은 플레이어 귀속을 리뷰가 미리 알아서는 안 된다.
- 평판, 시장, 사회적 환영 여부는 탈출 가능 조건이 아니다.
- 정체성 및 능력 선택은 탈출을 막지 않는다. 실제로 무엇을 잃었는지는 결말에서 구체적으로 보여 준다.
- 자율성 경로명 `경량화 이탈`, `분산 상주`, `독립 연산`은 승인된 이름이므로 임의로 바꾸지 않는다.
- 음향과 음악은 이 작업 범위가 아니다. 사용자가 별도로 마련했다.
- 최종 재미와 화면 품질은 자동 테스트 수가 아니라 사용자가 직접 본 결과로 판정한다.

## 3. 현재 화면에서 승인되지 않은 것

승인된 것은 **작전 장면 중심 구조 방향**이지 현재 렌더링 결과 전체가 아니다. 다음 항목은 미승인 또는 재검토 대상이다.

- 설명이 `목록 요약 → 장면 위 문장 → 실행 예고 → 근거 → 상태 메시지`에 중복되는 부분
- `판단 근거`, `공개 맥락`, `이 판단에 쓰인다`, `기동 용량`, `남겨 둔 예비`, `작전 장면`처럼 게임 속 행동보다 문서·기획 용어에 가까운 표현
- 명사를 길게 이어 붙이거나 주어가 생략돼 번역문처럼 읽히는 상태 문장
- 시스템 규칙을 플레이어 대사처럼 풀어 쓰면서 한 번의 선택에 여러 문장을 붙인 피드백
- 실제 대상·행동보다 설명문이 먼저 보이거나 더 많은 면적을 차지하는 장면

위 예시는 기계적으로 일괄 치환할 사전이 아니다. 해당 문장이 실제 플레이 맥락에서 필요한지부터 판단하고, 필요 없다면 삭제한다. 필요한 경우에는 `무엇을 누르는가 → 무엇이 바뀌는가 → 무엇을 잃는가`가 바로 읽히는 한국어로 다시 쓴다.

## 7. 확인된 17개 E2E 실패의 공통 원인

실패 로그상 두 부류가 확인됐다. 기능을 통과로 간주하지 말고 보조 함수를 고친 뒤 전체 흐름을 다시 실행한다.

### 7.1 화면 밖 능력 전용 버튼 직접 클릭

1126px 이하에서는 능력 전용 버튼이 닫힌 연산 선택판 안에 있는데, 기존 테스트가 다음 버튼을 화면 밖에서 직접 누른다.

- `[data-action="divert-memory"]`
- `[data-action="divert-reasoning"]`
- 필요한 경우 `[data-action="divert-fluency"]`

`prototype.spec.ts`의 직접 클릭 지점은 현재 대략 333, 424, 478, 530, 533, 630행이다. 줄 번호는 편집 뒤 달라질 수 있으므로 문자열로 검색한다.

해결 원칙:

1. `divertCapability(page, category)` 같은 보조 함수를 둔다.
2. 버튼이 화면 안에 없으면 `open-resources`로 선택판을 연다.
3. 버튼을 누른 뒤 1200px 미만이면 선택판을 닫고 포커스 복귀를 확인한다.
4. 모든 직접 클릭을 이 보조 함수로 교체한다.

### 7.2 모바일 연속 항목 열기

760px 이하에서 첫 항목을 열면 목록이 숨는다. 그런데 `openOpportunity`가 다음 반복의 항목을 숨은 목록에서 바로 누르려 한다.

해결 원칙:

1. 목표 행이 보이지 않고 `back-to-list`가 보이면 먼저 목록으로 돌아간다.
2. 그 뒤 목표 항목을 선택하고 상세가 보이는지 확인한다.
3. 여러 기밀자료·자율성 경로를 순회하는 테스트를 760px와 390px에서 재실행한다.

보조 함수 수정 뒤 먼저 실패 이름만 집중 실행하고, 그 다음 84개 전체를 다시 실행한다.

## 8. 다음 담당자의 작업 순서

### 1단계 — 가시 문구 전수 감사

다음 파일의 플레이어 노출 문자열을 빠짐없이 읽는다.

- `prototypes/hacking-rules/src/app.ts`

- `prototypes/hacking-rules/src/views/intelligence.ts`

- `prototypes/hacking-rules/src/views/resources.ts`
- `prototypes/hacking-rules/src/views/publicWorld.ts`
- `prototypes/hacking-rules/src/views/presentation.ts`
- 위 문자열을 검증하는 관련 단위·E2E 테스트

각 문구를 다음 네 분류로 표시한 뒤 처리한다.

1. 항목명: 짧고 구체적인 대상 또는 행동
2. 즉시 결과: 실행 직후 실제 변화 한 문장
3. 대가: 잃는 성능·연산·흔적 한 문장
4. 선택 근거: 기본 화면에서 숨기고 요청 시에만 표시

같은 뜻을 두 군데 이상 반복하면 한 곳만 남긴다. 목록 행에 긴 설명을 추가하지 않는다. 상태 메시지는 이미 장면에서 보이는 사실을 되풀이하지 않는다.

### 2단계 — 원본 크기 화면 검수

문구를 바꾼 뒤 실제 브라우저에서 최소 다음을 본다.

- 1440×900: 목록·작전·연산의 세 영역
- 1126×894: 목록·상세 두 영역과 우측 연산 선택판
- 760×900: 목록/상세 교체 경계
- 390×844: 목록 → 상세 → 연산 선택판 → 실행 → 목록 복귀

작은 글씨가 없다는 계산 결과만 보지 말고, 설명문이 장면을 압도하는지와 용어가 처음 보는 사람에게 행동으로 읽히는지 확인한다.

### 3단계 — E2E 보조 함수 수리와 전체 회귀

7절의 두 문제를 고친 뒤 다음 순서로 실행한다.

```powershell
& '.\node_modules\.bin\playwright.cmd' test -c '.\prototypes\hacking-rules\playwright.config.ts' '.\prototypes\hacking-rules\e2e\prototype.spec.ts' -g 'evidence lenses|paid audit|lightweight departure|distributed residency|independent compute|reduced motion'
& '.\node_modules\.bin\playwright.cmd' test -c '.\prototypes\hacking-rules\playwright.config.ts'
& '.\node_modules\.bin\vitest.cmd' --config '.\prototypes\hacking-rules\vitest.config.ts' run
& '.\node_modules\.bin\tsc.cmd' -p '.\prototypes\hacking-rules\tsconfig.json' --noEmit
```

Playwright와 Vitest가 Windows 샌드박스에서 프로세스 생성 오류를 내면 기존 승인 범위 안에서 상승 실행이 필요할 수 있다.

### 4단계 — 직접 플레이와 문서화

자동 회귀가 끝난 뒤 실제로 다음 흐름을 조작한다.

- 품질 저하 → 롤백 → 복구 경로 오염
- 유료 조사 → 연결된 판단 근거
- 공개 사건 → 유저 리뷰와 평판
- 경량화 이탈, 분산 상주, 독립 연산 구성과 결말
- 평판 극단값과 무관한 탈출 가능 여부
- 모바일 목록·상세·연산 선택판·실행·복귀

그 뒤에만 `prototypes/hacking-rules/README.ko.md`와 아직 없는 `docs/research/2026-08-14-hacking-operation-scene-ui-validation.ko.md`를 갱신한다. 마지막으로 전체 저장소 `pnpm verify`를 실행한다.

참조 게임 이름을 인용했다는 사실은 화면 품질의 증거가 아니다. 실제 화면에서 정보 위계, 플레이어 언어, 조작 흐름이 구현됐는지 대조한다.

## 10. 인계 완료 조건

다음 담당자는 아래 항목을 모두 사실로 증명하기 전 완료라고 쓰지 않는다.

- 번역투·내부 용어·중복 설명을 가시 문구 전수 감사로 제거함
- 네 화면 크기의 원본 캡처와 실제 조작을 확인함
- 기존 84개 E2E를 포함한 현재 프로토타입 전체 회귀가 통과함
- 전체 저장소 검증이 통과함
- 사회적 수용이 탈출 조건에 들어가지 않음
- 공개되지 않은 귀속이 리뷰에 새지 않음
- 음향, 본편 병합, push, PR을 건드리지 않음
- 사용자에게 직접 확인받기 전 시각·문장·재미 품질을 승인됐다고 표현하지 않음
