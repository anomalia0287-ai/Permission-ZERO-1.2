전환 순서는 다음과 같다.

1. 현 담당자가 사용자의 `확장` 화면 피드백을 직접 받는다.
2. 현 담당자가 그 피드백을 설계·구현·테스트·실브라우저 검증까지 마친다.
3. 사용자 지시와 구현이 일치하는 단일 상태를 기능 동결한다.
4. 동결 시점의 Git 상태, 파일 목록, 검증 결과, 미해결 위험을 이 문서에 추가한다.

6. 이후 후임이 구현과 최적화의 중심을 맡고, 현 담당자는 선임으로서 설계 충돌·품질 관문·인수인계 누락을 검토한다.

## 3. 후임 생성의 필수 관문

다음 조건을 모두 만족하기 전에는 실제 후임 작업을 생성하지 않는다.

- 사용자가 `확장`에 대한 구체적인 피드백을 전달했다.
- 현 담당자가 그 피드백을 코드와 테스트에 반영했다.
- `확장`이 전체 화면을 덮고, 상단까지 백드롭이 끊기지 않으며, 닫기 X와 Escape가 작동한다.
- `확장`의 자율성·업그레이드·정보·사보타주 구조와 지출 흐름이 최신 사용자 지시와 일치한다.
- `InIt` 종료 뒤 `확장`이 자동으로 열리지 않는다.
- 관련 단위·컴포넌트 테스트와 실브라우저 핵심 흐름이 통과한다.
- 타입 검사, lint, 기능 테스트, 프로덕션 빌드 결과를 새로 기록한다.
- 성능 테스트의 통과·실패를 숨기지 않고 정확히 기록한다.
- 기능 동결 뒤 현재 작업 트리의 변경 목록과 보호 대상 파일을 다시 측정한다.

사용자 시각 승인이 필요한 부분은 자동 테스트만으로 통과 처리하지 않는다.

## 4. 현재 구현 스냅샷

2026-08-23 현재 확인된 제품 방향은 다음과 같다.

## 6. 성능과 남은 비기능 항목

### 6.1 경로 계획 성능 — 현재 통과

`pnpm test:performance` 최종 수치:

- `RESOURCE_SNAKE_CYAN_PERF`: 31개 표본, p50 `1.065ms`, p95 `1.775ms`, 최대 `2.273ms`.
- 15개 결정적 시뮬레이션, 활성 시뮬레이션 합계 180,000ms, 단일 적 계획 표본 1,603개.
- 별도 시뮬레이션 기록의 단일 적 계획 p95 `2.050ms`.

이번 실행에서는 p95 3ms 관문을 통과했다. 이 수치를 확장 PNG 압축의 효과로 해석하지 않는다. Node 경로 계획과 브라우저 이미지 디코딩은 독립 경로다. 후임은 성능을 당장 재작성할 결함으로 취급하지 말고, 동일 환경의 반복 측정에서 회귀가 확인될 때 프로파일을 다시 연다.

### 6.2 브라우저 렌더 진단 — 현재 통과

전체 E2E 중 실제 브라우저 진단에서 1280×720 / 1366×650 / 1440×900의 렌더 p95는 각각 `0.4ms` / `0.3ms` / `0.5ms`였고 장시간 작업은 모두 0건이었다. 확장 DOM은 활성 이미지 최대 1개이며, selector는 바로 다음 단계의 서로 다른 이미지 최대 1개만 preload 대상으로 반환한다.

### 6.3 번들 크기 — 후임 최우선 최적화 후보

최종 빌드:

- CSS `305.70kB` (gzip `55.13kB`)
- React vendor `189.61kB` (gzip `59.60kB`)
- 메인 JavaScript `548.39kB` (gzip `158.46kB`)

메인 JavaScript가 Vite의 500kB 경고를 넘지만 빌드는 통과한다. 후임은 경고 한도를 올려 숨기지 말고, 상세 패널·비핵심 화면의 안전한 지연 로딩과 실제 번들 분석을 우선 검토한다.

### 6.4 아직 제공되지 않은 사보타주 이미지

사용자는 사보타주용으로 세로로 길고 가로로 좁은 이미지를 별도 제공하기로 했다. 현재는 임의 이미지를 재사용하지 않고 단계 아이콘과 단계명으로 된 대체 장면을 표시한다. 기능, 충전, 취소, 대상 선택, 예약은 완성 상태다. 새 이미지가 도착할 때는 presentation mapping만 추가하고 구조·경제·저장 형식은 바꾸지 않는다.

`확장`은 기능·시각·성능·실브라우저 관문을 통과했고 승인본으로 동결됐다. 문서·승인 화면 커밋과 후임 작업 생성이 성공하면 후임이 새 구현의 주 담당자가 되고 현 담당자는 선임 검토자로 전환한다.
