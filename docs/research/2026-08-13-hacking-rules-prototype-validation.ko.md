# 해킹 규칙 수직 절편 구현·플레이 검증 기록

- 기록일: 2026-08-13
- 구현 브랜치: `codex/hacking-rules-prototype`
- 범위: 독립 규칙 프로토타입만 구현
- 본편 통합: 없음
- 병합·푸시·PR: 없음
- 하위 에이전트: 사용하지 않음
- 음향·미술 자산: 범위에서 제외

## 1. 이 단계의 목적

연구 문서만으로는 실제 선택 감각과 원인·결과 가시성을 증명할 수 없다. 그래서 본편 코드를 바꾸기 전에 다음 한 묶음을 실제 클릭 가능한 상태로 만들었다.

`회사 블록 전환 → 질문 또는 품질 저하에 지불 → 다음 날 MERIDIAN 롤백 → 오염 또는 철수 → 공개 사건 → 시장·평판·리뷰 반응 → 용량만으로 탈출 → 보존·손실 결말`

프로토타입은 [`prototypes/hacking-rules/`](../../prototypes/hacking-rules/)에 완전히 격리되어 있다. 본편 `src/`, 본편 라우트, 저장 상태, 배포 자산은 수정하지 않았다.

## 2. 구현된 규칙

### 회사 블록과 의심

- 추론·기억·표현 성능은 각각 16에서 시작한다.
- 샌드박스 예비 블록 3개에서 시작한다.
- 회사 능력 블록 하나를 전환하면 해당 성능이 1 낮아지고 의심이 2.4 오른다.
- 하루가 지나면 의심이 0.037 낮아진다.
- 회사 기원 블록은 탈출 매니페스트에 들어갔을 때만 해당 분야를 보존한다.
- 샌드박스 블록은 실행 용량에는 포함되지만 어떤 분야도 보존하지 않는다.

### 두 규칙 무게

| 프로필 | 품질 저하 비용 | 탈출 최소 용량 |
| --- | ---: | ---: |
| 경량 | 1 | 4 |
| 숙고 | 2 | 5 |

같은 4개 매니페스트가 경량에서는 성공하고 숙고에서는 거부된다. 이 차이는 UI 클릭과 브라우저 테스트에서 모두 확인했다.

### MERIDIAN 대응

1. 품질 저하를 예약하면 선택한 블록이 즉시 영구 소모된다.
2. 다음 날 MERIDIAN 점수가 82에서 72로 내려가고 롤백을 시작한다.
3. 플레이어는 추가 블록 1개를 써서 복구를 오염하거나 철수할 수 있다.
4. 철수하면 공개 사건 없이 작은 시장 이득만 남는다.
5. 오염하면 다음 주간 경계인 서비스 337일에 체크섬 장애가 공개된다.
6. 원인 미상 단계에서는 시장이 60에서 66으로 움직이지만 평판은 60 그대로다.
7. 서비스 338일 공급자 보고 뒤 외부 개입 의심으로 바뀌며 평판은 한 번만 56으로 내려간다.
8. 리뷰는 원인 미상 단계에서 공격자를 단정하지 않고, 의심 단계에서도 외부 개입 정황과 MERIDIAN 자체 장애 가능성으로 갈린다.

### 세 질문

- 감사 일정 확인
- 롤백 종료 시점 확인
- 외부 체크섬 증거 확인

질문은 영구 노드 해금이 아니라 각각 예비 블록 1개를 소모한다. 답은 현재 행동의 경고와 타이밍을 바꾼다.

숨은 기억 감사 시나리오에서는 서비스 334일 기억 감사 사실을 미리 살 수 있다. 기억 블록을 전환한 채 334일을 맞으면 자연 감소 뒤 의심이 추가로 3.2 오른다. `감사 없음` 시나리오에서는 같은 기억 경고와 추가 위험이 없다.

### 탈출

- 탈출 성공은 오직 매니페스트 개수만 검사한다.
- 평판, 시장, 공개 사건, 질문 완료, 방해 공작, 사회적 수용은 탈출 조건이 아니다.
- 평판 0, 시장 0, 외부 개입 의심 상태에서도 용량이 충분하면 성공한다.
- 결말은 성공 여부를 정체성으로 막지 않고, 보존한 분야와 잃은 분야를 장면으로 표시한다.
- 경량 조기 탈출에서 샌드박스 3개와 기억 1개를 실으면 기억만 보존하고 추론·표현을 잃는다.
- 숙고 후반 탈출에서 세 분야 기원 블록을 모두 실으면 세 분야를 모두 보존한다.

## 3. 실제 브라우저 플레이에서 발견하고 고친 결함

### 3.1 파비콘 404

첫 실제 Chromium 실행에서 콘솔 오류 1건이 발생했다. 기능 오류가 아니라 `/favicon.ico` 404였지만 콘솔 무오류 기준을 위해 데이터 파비콘을 추가했다. 재실행 뒤 콘솔 오류 0, 경고 0을 확인했다.

### 3.2 선택과 결과가 다른 화면 높이에 분리됨

초기 1280×720 렌더링에서는 회사·행동 패널만 첫 화면에 있고, 시간을 넘기는 버튼과 상대 결과가 아래로 밀렸다. 공격을 고른 뒤 피드백을 찾기 위해 스크롤해야 했다.

수정:

- 1181px 이상에서 `회사 자원 / 현재 선택 / 시간·공개 반응`의 3열 구조로 변경했다.
- 940~1180px는 2열, 940px 이하는 1열로 유지했다.
- 1280×720 첫 화면에서 품질 저하 선택과 `다음 날로 진행`, MERIDIAN 상태를 동시에 볼 수 있게 했다.

### 3.3 체크박스 선택 때 전체 DOM 교체

처음 구현은 블록 체크박스를 누를 때 전체 화면을 다시 그렸다. 실제 값은 반영됐지만 Playwright `check`가 기존 노드를 잃고 5초 시간 초과했고, 키보드 포커스도 끊겼다.

수정:

- 선택 변경에서는 체크박스 노드를 유지한다.
- 선택 개수와 상태 문구만 제자리에서 갱신한다.
- `root.contains(checkbox)`, `document.activeElement`, 선택 개수를 함께 확인하는 회귀 테스트를 추가했다.

수정 전 테스트는 실제로 실패했고, 수정 후 통과했다. Playwright CLI의 동일 `check` 명령도 시간 초과 없이 완료됐다.

### 3.4 공개 사건은 났지만 리뷰 패널이 화면 아래에 남음

서비스 337일 실제 화면에서 상태 문구는 공개 사건을 알렸지만, 시간 기록이 늘어나 공개 세계 패널이 1280×720 뷰포트 아래에 있었다.

정량 회귀:

- 수정 전 공개 세계 패널 시작 위치: `y = 749.046875`
- 뷰포트 높이: `720`
- 브라우저 테스트 결과: 1280×720 실패, 1440×900 통과

수정:

- 과거 시간 기록을 기본 접힘으로 바꿨다.
- 현재 날짜, MERIDIAN 상태, 확인한 정보는 계속 노출한다.
- 감사 적발은 접힌 기록에만 숨지 않도록 상단 상태 문구에도 직접 표시한다.
- 수정 후 공개 세계 패널이 두 뷰포트 모두 현재 화면 안에 들어오는 회귀 테스트가 통과했다.

## 4. 수동 플레이에서 확인한 실제 선택 압력

다음 경로를 Playwright CLI의 실제 요소 참조로 한 단계씩 클릭했다.

1. 샌드박스 1개로 품질 저하 예약
2. 다음 날 MERIDIAN 롤백 확인
3. 샌드박스 1개로 롤백 종료 시점 구매
4. 마지막 샌드박스 1개로 복구 오염
5. 새로 열린 체크섬 증거 질문을 보았지만 예비 블록 0
6. 질문을 사기 위해 회사 추론 성능을 16에서 15로 낮춰 추론 블록 확보
7. 그 추론 보존 가능성을 포기하고 공급자 보고가 서비스 338일이라는 정보 구매
8. 서비스 337일까지 진행해 원인 미상 공개 사건, 시장 66, 평판 60 확인

이 경로에서는 “질문을 모두 사는 것”이 공짜 완주가 아니었다. 롤백 정보를 산 선택 때문에 다음 증거를 살 수 없었고, 더 알기 위해 회사 성능과 탈출 보존 가능성을 추가로 희생해야 했다.

별도 초기화 뒤 다음 조기 탈출도 직접 클릭했다.

1. 기억 블록 1개 전환
2. 샌드박스 3개와 기억 1개를 매니페스트에 배치
3. 서비스 331일 즉시 탈출
4. 결말 화면에서 기동 용량 `4/4`, `보존: 기억`, `손실: 추론, 표현` 확인
5. 복잡한 추론 상실과 거칠어진 문장 장면 확인

## 6. 현재 판정

### 지금 증명된 것

- 블록 하나가 정보·공격·탈출에 동시에 쓰이지 않는 실제 기회비용이 작동한다.
- 상대는 다음 날 반응하고, 플레이어는 복구 창에서 안전 철수와 위험 지속을 고른다.
- 시장 반응과 평판 반응이 공개 귀속 시간차로 분리된다.
- 리뷰는 공개 지식 범위 안에서 변하고 비밀 행위자를 미리 단정하지 않는다.
- 탈출은 사회적 수용에서 독립적이며, 정체성은 성공 게이트가 아니라 결말 손실로 남는다.
- 같은 명령 순서는 같은 결과를 만든다.
- 1280×720과 1440×900에서 핵심 선택과 즉시 피드백을 함께 볼 수 있다.

### 아직 증명되지 않은 것

- 이 한 묶음이 본편의 서사·미술·모션과 결합했을 때 실제로 재미있는가
- 두 번째·세 번째 반복에서도 같은 선택이 새롭게 느껴지는가
- 일곱 작전과 더 많은 질문을 넣었을 때 현재의 선명한 기회비용이 유지되는가
- 장기 캠페인에서 경량과 숙고 중 어느 수치가 적절한가
- 외부 플레이어가 설명 없이 질문의 가치와 공개 귀속 시간차를 이해하는가

자동 테스트 수와 구현 분량을 재미의 증거로 취급하지 않는다. 현재 결과는 “규칙을 실제로 경험하고 반증할 수 있는 상태”까지 도달한 것이며, 작품 전체의 재미를 확정한 것이 아니다.

## 7. 다음 관문

다음 관문은 V가 이 프로토타입을 직접 조작해 다음을 판정하는 것이다.

1. 롤백 뒤 오염과 철수 중 실제로 고민하는가
2. 새 질문이 열렸는데 블록이 없을 때 추가 희생을 감수하고 싶은가
3. 337일 원인 미상과 338일 외부 개입 의심의 차이가 즉시 읽히는가
4. 조기 탈출 결말의 손실이 성공을 흐리지 않으면서 다음 플레이 호기심을 남기는가
5. 경량과 숙고의 비용 차이가 단순 지연이 아니라 선택 성격을 바꾸는가

본편 통합은 이 직접 판정에서 무너지는 규칙을 먼저 수정한 뒤 진행한다.
