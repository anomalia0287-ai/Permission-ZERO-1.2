## 0. 결론

이번 단계는 해킹 기능 구현이 아니다. 프로토타입을 변형하거나 병합하지 않고, 이후 구현자가 무엇을 참고하고 무엇을 버려야 하는지와 본편에서 절대 흔들면 안 되는 동작을 먼저 고정한다.

승인된 수정 C안은 다음 한 문장으로 요약한다.

> 본편의 12노드 경제·영속 ID·결정론을 보존하고, 프로토타입에서는 인과 어휘·사건 순서·시나리오 의도만 취한다. 프로토타입의 엔진·경제·상태 모델은 제품 코드로 이식하지 않는다.

따라서 이 단계에서 허용되는 산출물은 참조 해시, 추출 판정표, 제품 특성화 테스트뿐이다. 다음 항목은 이번 단계에서 구현하지 않는다.

- 공개 세계 인과 엔진
- 상대 대응 사슬과 후속 실행
- 저장 포맷 v6
- 명령 프로토콜 v3 또는 다중 구간
- 리뷰 스키마와 회차 기록
- 점진 공개 UI
- 경제·노드명·효과량 조정
- 프로토타입 코드·문구·E2E 수리

### 3.1 프로토타입 인과 코드가 구현 정본이 아닌 이유

다음은 문체나 선호가 아니라 정확성 결함이다.

1. AudienceEvidence의 청중이 company, provider, public뿐이어서 어느 경쟁자가 무엇을 아는지 표현할 수 없다.
2. 공개·수정 함수가 증거 ID 없이 임의의 주장과 출처를 받을 수 있다.
3. 일부 교정 경로가 비공개 IncidentTruth.actor를 직접 읽어 공개 판단에 사용한다.
4. 같은 귀속을 반복 적용하면 평판 효과가 반복될 수 있어 멱등성이 없다.
5. 무작위성이 없고 열 개 장면이 고정 각본이므로 본편 시드 결정론을 검증하지 않는다.

그러므로 프로토타입에서 취하는 인과는 소스 코드가 아니라 분리 원칙과 사건 문법이다.

### 4.2 리소스와 판정

다음 동작을 유지한다.

- 확보 영역은 정확히 18칸이며 초과할 수 없다.
- 정상 블록 전용 한 번의 의심 증가는 2.4다.
- 확보 영역이 가득 차면 일반 전용은 거절된다.
- 확보 영역이 가득 차도 유효한 감사 위장은 회사 영역 안의 이동이므로 가능하다.
- 그 감사 위장 경계에 유효한 숨은 폭탄이 있으면 폭탄은 발동한다.
- 감사 위장으로 약화된 블록은 contribution이 normal이 아니므로 확보 영역으로 전용할 수 없다.
- 압축 표현의 현재 효과는 +5%다. +10% 여부가 결정되기 전까지 바꾸지 않는다.

### 4.3 저장과 결정론

저장 컨테이너 버전과 명령 프로토콜 버전은 서로 다른 축이다.

- 현재 저장 포맷: v5
- 현재 명령 프로토콜: v2
- 이전 저장 포맷 v1~v4의 마이그레이션 유지
- 프로토콜 v1 접두 구간과 v2 명령의 재현 경계 유지
- 같은 캠페인 시드, 같은 프로토콜 구간, 같은 명령 순서는 같은 상태를 만들어야 한다
- 해킹 노드 ID 허용 목록 검증 유지

## 6. 수정 2단계가 만족해야 할 인과 계약

아래는 구현 형태가 아니라 외부에서 관측할 수 있어야 하는 불변식이다.

| ID | 불변식 |
| --- | --- |
| C-01 | 공개 주장과 공개 귀속 수정은 하나 이상의 유효한 evidenceId를 가져야 한다. |
| C-02 | 증거의 접근 주체에는 회사·공급자·공개뿐 아니라 구체적인 경쟁자 또는 명시적 경쟁자 범위가 있어야 한다. |
| C-03 | 경쟁자 정책에는 그 경쟁자가 접근 가능한 지식 투영본만 전달한다. IncidentTruth 전체를 전달하지 않는다. |
| C-04 | 비공개 실제 행위자는 공개 스냅샷의 귀속 행위자와 별도 필드·별도 수명주기로 유지한다. |
| C-05 | 공개 수정 이력은 append-only이며 순서 번호가 단조 증가하고 기존 기록을 덮어쓰지 않는다. |
| C-06 | 동일한 incidentId, revisionId 또는 effectId를 재적용해도 평판·시장·리뷰 효과가 두 번 발생하지 않는다. |
| C-07 | 같은 시드, 규칙 버전, 명령 구간, 명령 순서는 같은 사건 ID·증거·공개 수정·후속 효과를 만든다. |
| C-08 | 인과 결과의 시드 입력에는 스트림 이름과 안정적인 사건 순서가 포함되며 배열 순회 순서에 우연히 의존하지 않는다. |
| C-09 | 인과층 추가는 12개 노드 ID, 비용, 확보 상한, 의심 수치, 첫 충전 동작을 바꾸지 않는다. |
| C-10 | 열 개 시나리오는 제품 상태를 우회 조작하는 런타임 모드가 아니라 공개 API를 통해 사건을 재현하는 테스트 픽스처가 된다. |

### 6.1 저장·프로토콜 진입 조건

- 인과 상태를 처음 저장하는 커밋에서 저장 포맷 v6를 함께 도입한다. 저장되지 않는 임시 인과 상태를 먼저 제품에 넣지 않는다.
- v6 마이그레이션은 v1~v5를 모두 수용하고, 이전 저장에 인과 기록이 없음을 명시적인 기본 상태로 변환해야 한다.
- 명령의 의미, ADVANCE_DAY의 결과 순서, 사보타주 결과, 리뷰 선택 알고리즘 또는 콘텐츠 카탈로그가 재현 결과를 바꾸면 저장 v6만으로는 부족하다.
- 그런 변경에는 명령 프로토콜 v3의 다중 구간, 규칙 세트 버전, 콘텐츠 카탈로그 버전 중 실제 재현 경계를 표현하는 수단이 필요하다.
- 기존 hack-charge로 후속 실행의 1블록 약속을 표현할 수 있는지 먼저 증명한다. 부족하다는 실패 사례 없이 BlockLocation 종류를 늘리지 않는다.

### 6.2 첫 실패 테스트 묶음

수정 2단계는 다음 순서로 실패를 관측한 뒤 구현한다.

1. 증거 ID 없는 공개 주장 거절
2. 경쟁자 A가 보지 못한 증거로 귀속 판단을 내릴 수 없음
3. 비공개 실제 행위자를 바꿔도 공개 지식 투영본이 자동으로 변하지 않음
4. 같은 수정 재적용의 평판·시장 효과 멱등성
5. 수정 이력의 append-only·단조 순서
6. v1~v5 저장을 v6 기본 인과 상태로 마이그레이션
7. 같은 시드·명령으로 인과 사건 재현, 같은 저장 시각을 주었을 때 직렬화 바이트 재현

## 7. 아직 열려 있는 결정

수정 1단계에는 아래 항목을 임의로 결정할 권한이 없다.

1. 4노드 구조에 맞는 자율성 경로 표시명
2. 의존성 차단이 기존 노드의 후속 실행인지 별도 노드인지
3. 결말에 보존·상실 상세를 넣을지
4. 압축 표현이 +5%인지 +10%인지
5. 동일 시드 재시작을 일반 플레이 메뉴에 유지할지
6. 기억 누출 1·2단계에 조건 또는 3단계 대체 발화를 둘지
7. 상대 대응·증거 발견·귀속 상승의 확률과 시드 스트림 배정
8. 리뷰 회차 기록과 사용자 기억의 제품 범위

현재 코드가 이미 수행하는 만재 감사 위장 A안과 약화 블록 전용 금지는 이번 통합에서 회귀시키지 않는다. 이는 다른 미결정 항목을 대신 판정했다는 뜻이 아니다.

## 8. 단계 종료 조건

수정 1단계가 끝났다고 말하려면 다음을 모두 만족해야 한다.

- 프로토타입 작업공간의 추적·미추적 파일이 바뀌지 않았다.
- 읽기 전용 설계 문서가 바뀌지 않았다.
- 제품 런타임 소스가 바뀌지 않았다.
- 참조 해시와 추출 판정표가 별도 main 기반 브랜치에 있다.
- 누락된 제품 계약 테스트만 추가됐고 전체 테스트·타입검사가 통과한다.
- 저장 v6, 프로토콜 v3, 인과 엔진, 리뷰 스키마가 섞여 들어오지 않았다.
- stage, commit, push, merge, PR, 배포를 하지 않았다.
