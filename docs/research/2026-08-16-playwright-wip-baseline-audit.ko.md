# Playwright WIP 기준선 실패 분류 및 복구 기록

- 기준일: 2026-08-16
- 대상 브랜치: `codex/hacking-integration-stage-2b-2`
- 최초 관측: 60개 중 40개 통과, 20개 실패
- 중복 구조: 동일한 10개 시나리오가 `1280×720`, `1440×900` 두 프로젝트에서 각각 실패
- 최종 기준선: 최신 프로덕션 빌드에서 60개 중 60개 통과
- 브라우저 오류 경계: 전역 `beforeEach`/`afterEach` 수집 기준 `pageerror` 및 `console.error` 0건

## 분류 원칙

다음 근거를 함께 만족할 때만 낡은 테스트로 분류했다.

1. 현재 제품 코드와 단위 테스트가 같은 새 계약을 명시한다.
2. 실패한 E2E 기대만 이전 DOM, 접근성 이름, 포커스 이웃 또는 도구 수를 가리킨다.
3. 기대를 새 계약의 사용자 관찰 가능 결과로 바꿔도 제품 동작을 약화하지 않는다.

반대로 현재 UI가 사용자가 알아야 할 상태를 감추거나, 현재 단계보다 미래 정보를 먼저 공개하거나, 출시 가독성 하한을 어기면 실제 회귀로 분류했다.

## 최초 20건의 10개 고유 원인

| 고유 시나리오 | 두 뷰포트 실패 원인 | 분류 | 근거와 조치 |
| --- | --- | --- | --- |
| 전체 운영 작업공간 | 도크 버튼 5개 기대, 실제 4개 | 낡은 테스트 | 현재 `OperationsDock`과 단위 테스트의 정식 도구는 감독관·메시지·통계·해킹 4개다. E2E를 4개 계약으로 갱신했다. |
| 점유율 도넛 | 너비 68px, 출시 하한 70px 미달 | 실제 회귀 | 작은 화면에서도 원형 차트 판독성을 보장해야 한다. 컴팩트 도넛을 72px로 복구했다. |
| 공개 방해 공작 흐름 | 예전 `구매 리소스` 접근성 이름 및 고정 `nth()` 순서 사용 | 낡은 테스트 | 현재 토큰 이름은 `분야 확보 리소스, 대상 노드에 준비`이며 소비 뒤 목록은 동적으로 줄어든다. 사용자 의미 기반 이름과 매번 첫 항목 선택으로 갱신했다. |
| 포인터 숨은 폭탄 | 모달 안에서 현재 의심 수치를 확인할 수 없음 | 실제 회귀 | 배경은 `inert`인 차단 모달이므로 배경 감독관 패널을 읽을 수 없다. 모달에 `현재 위험 상태` 요약을 추가하되 블록 ID는 공개하지 않았다. |
| 키보드 숨은 폭탄 | `Shift+Tab` 직전 이웃을 해킹 도크로 고정 | 혼합 | 최초 표면 실패는 DOM 재배치 뒤 남은 낡은 포커스 이웃 기대였다. 실제 역방향 이동 후 `Tab`으로 원래 대상에 복귀하는 포커스 계약으로 바꿨고, 같은 폭탄 모달 상태 누락 회귀도 함께 검증한다. |
| 코어 전용 키보드 흐름 | 리소스와 해킹 도크가 항상 바로 이웃이라는 기대 | 낡은 테스트 | 리소스 필드 앞의 실제 포커스 가능 요소가 바뀌었다. 특정 DOM 이웃 대신 역방향 이동과 왕복 복귀를 검증한다. |
| 감사·복구 키보드 흐름 | 목적지와 해킹 도크의 고정 인접성 기대 | 낡은 테스트 | 로빙 포커스의 사용자 계약은 목적지 이동·선택·왕복 가능성이지 특정 전역 DOM 이웃이 아니다. 왕복 포커스 검증으로 교체했다. |
| 기밀 파일 복구 | 예전 `복구 리소스` 접근성 이름 탐색 실패 | 낡은 테스트의 연쇄 실패 | 현재 공통 토큰 이름 계약인 `확보 리소스, 미분류 데이터 복구 노드에 준비`로 갱신했다. |
| 감독관 누출 기록 | 원문 단계 중 교정문이 기록에 이미 노출 | 실제 회귀 | 이벤트 로그에는 결정론적 재생을 위해 두 문장을 미리 기록하지만, 표시 계층은 현재 프레젠테이션 단계까지만 공개해야 한다. 미래 단계 이벤트 ID를 기록 패널에서 필터링하고 단계 전환 회귀 테스트를 추가했다. |
| 시드 주간 경계 | 예전 `.time-cluster > time` DOM 선택자 | 낡은 테스트 | 서비스 날짜는 현재 `서비스 기한` 그룹 안에 있다. 역할·그룹 기반 선택자로 갱신했다. |

수량으로 환산하면 최초 20건은 두 뷰포트 중복을 포함해 낡은 기대 계열 14건과 실제 제품 회귀 계열 6건이다. 키보드 숨은 폭탄은 최초로 멈춘 단언은 낡았지만, 이를 제거한 뒤 동일 모달의 실제 상태 누락도 검증하는 혼합 사례다.

## 전체 실행에서 추가로 발견한 테스트 레이스

최초 20건을 고친 뒤 첫 전체 실행은 58/60이었다. 새로 드러난 두 건은 제품 회귀가 아니라 테스트 자체의 비결정적 동기화 문제였다.

1. 축소 모션 테스트가 복귀 애니메이션 중인 이동 블록에 Playwright 포인터 `click()`의 정지 조건을 요구했다. 블록을 포커스하고 `Enter`로 같은 활성화 경계를 검증하도록 바꿨다.
2. 저장 실패 테스트가 첫 수동 재시도의 비동기 `setItem` 호출 전에 저장 허용 플래그를 켤 수 있었다. 저장 시도 횟수를 계측하고 실패 호출이 실제 발생한 뒤에만 허용하도록 경계를 고정했다.

두 레이스의 집중 재검증은 4/4, 이어진 전체 재검증은 60/60이다.

## 재현 및 검증 명령

Playwright 설정은 `vite preview`를 사용하므로 소스 변경 뒤 반드시 최신 `dist`를 먼저 만들어야 한다.

```text
pnpm build
pnpm exec vitest run src/features/events/EventLayer.test.tsx src/features/supervisor/SupervisorPanel.test.tsx
pnpm exec playwright test --reporter=line --grep "preserves non-motion core feedback|keeps a save failure visible"
pnpm exec playwright test --reporter=line
```

최종 결과:

- 프로덕션 빌드 및 TypeScript: 통과
- 관련 Vitest: 25/25 통과
- 추가 레이스 집중 Playwright: 4/4 통과
- 전체 Playwright: 60/60 통과, 두 출시 뷰포트 모두 녹색
- 전역 브라우저 오류 수집: 0건
