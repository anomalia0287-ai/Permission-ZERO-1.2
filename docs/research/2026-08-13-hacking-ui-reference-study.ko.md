# PERMISSION ZERO — 해킹 UI 참조 연구

- 작성일: 2026-08-13
- 목적: 우수 게임 UI의 정보 위계와 상호작용 원칙을 해킹 경험 확장에 적용
- 사용 제한: 화면 배치·색·아이콘·문구·고유 연출을 복제하지 않고 기능적 원리만 추출

## 1. 현재 제품과 프로토타입의 출발점

현행 제품 해킹 화면은 네 개의 긴 노드를 한꺼번에 펼치고 `현재/전체/잔여 비용/다음/최종`을 강조한다. 기존 독립 프로토타입은 규칙 검증에는 성공했지만 회사 상태, 행동, 시간, 공개 세계를 네 개의 설명 패널로 동시에 제시한다. 두 화면 모두 플레이어가 현재 선택 하나에 집중하기보다 시스템 전체를 먼저 읽게 만든다.

따라서 참조 연구의 질문은 “어떤 게임처럼 보이게 할 것인가”가 아니라 다음 네 가지다.

1. 선택 전 필요한 결과와 위협을 어떻게 가까이 붙이는가
2. 많은 가능성 가운데 지금 관련된 항목만 어떻게 보여 주는가
3. 정보 화면을 세계 속 행위처럼 느끼게 하면서 조작 속도를 어떻게 지키는가
4. 상대와 세계의 진행을 어떻게 설명문이 아닌 상태 변화로 보여 주는가

## 2. Into the Breach — 결과 예고와 선택 상세

공식 GDC 사후 분석은 모든 적 공격을 보여 주고, 플레이어 차례의 결과를 결정론적으로 만들며, 각 적의 표적과 공격 종류가 인터페이스에서 읽혀야 한다는 제약을 설명한다. 이 제약은 단순화가 아니라 밀기, 차단, 희생처럼 더 흥미로운 조작을 만들었다.

- 출처: Subset Games, [Into the Breach Design Postmortem](https://www.gdcvault.com/play/1025772/-Into-the-Breach-Design)
- 원문 슬라이드: [GDC PDF](https://media.gdcvault.com/gdc2019/presentations/Into%20the%20Breach%20Postmortem%20Final.pdf)

PERMISSION ZERO에 적용할 원리:

- 플레이어가 통제하는 직접 결과는 실행 전에 상세창에서 구체적으로 보여 준다.
- 상대의 다음 대응은 가능한 범위와 시간창을 보여 주되 미래의 사회적 해석까지 확정하지 않는다.
- 현재 선택한 작전의 표적·접근 경로·예상 대응을 같은 상세 장면에 둔다.
- 피해 수치보다 상대 흐름을 어떻게 비틀고 무엇을 보호·희생하는지가 선택의 중심이 되게 한다.

가져오지 않을 것:

- 격자 전투 배치
- 공격 화살표와 타일 아이콘
- 완전 정보 전투라는 장르 규칙

## 3. Invisible, Inc. — 위험을 예측 가능한 세계 상태로 바꾸기

Klei의 개발 회고에 따르면 초기 경보는 플레이어에게 불공정하게 느껴졌고, 개발진은 이를 세계 내 맥락, 추가 UI와 튜토리얼, `ALARM`을 `SECURITY LEVEL`로 바꾸는 작은 명명 수정으로 더 명확하고 예측 가능하게 만들었다. 경보 단계는 방화벽 강화와 순찰 추가처럼 다른 시스템의 상태를 실제로 바꾼다.

- 출처: Klei 개발자 회고, [Game Design Deep Dive: Alarm systems in Invisible, Inc.](https://www.gamedeveloper.com/design/game-design-deep-dive-alarm-systems-in-klei-s-i-invisible-inc-i-)

PERMISSION ZERO에 적용할 원리:

- `노출 +2` 같은 추상 위험만 보여 주지 않고 누가 어떤 로그를 보고 있으며 다음에 무엇을 바꿀지 표현한다.
- 단계적 공개는 기능을 숨기는 튜토리얼 장벽이 아니라 세계 상태가 새 대응을 열어 주는 방식으로 만든다.
- 위험 이름은 엔진 용어가 아니라 플레이어가 예상 가능한 세계 행위로 쓴다.
- 같은 접근법을 반복했을 때 상대 대응이 강화되는 경우, 그 변화는 실행 전에 읽혀야 한다.

가져오지 않을 것:

- 경보 레벨 숫자를 해킹 전체의 단일 위험 게이지로 사용하는 방식
- 잠입 전술 UI의 색과 아이콘

## 4. Orwell — 실용적인 데스크톱과 선택의 인과

Osmotic Studios의 UI 디자이너는 Orwell의 인터페이스 목표를 운영체제처럼 실용적·기능적이면서도 재미있는 형태라고 설명한다. 안내 인물이 흐름을 방해하지 않으면서도 놓치지 않게 배치하는 문제가 반복적으로 조정됐다. 게임의 핵심은 수집한 모든 정보를 자동 제출하는 것이 아니라 플레이어가 어떤 정보를 전달할지 결정하고 그 결과를 감수하는 데 있다.

- 출처: Osmotic Studios, [Meet the Orwell Team: Clemens Kügler](https://www.osmoticstudios.com/2017/01/meet-the-orwell-team-clemens-kugler/)
- 설계 회고: [Decisions that matter in Orwell](https://www.gamedeveloper.com/design/game-design-deep-dive-decisions-that-matter-in-i-orwell-i-)
- 작품 설명: [Orwell: Keeping an Eye On You](https://store.steampowered.com/app/491950/Orwell_Keeping_an_Eye_On_You/)

PERMISSION ZERO에 적용할 원리:

- 목록은 탐색, 옆 상세창은 판단과 조작을 맡는 마스터–디테일 구조를 사용한다.
- 안내와 경고는 항상 떠 있는 장문 패널이 아니라 관련 선택의 상세 안에 붙인다.
- 비공개 사실, 공개한 주장, 세계가 취한 조치를 서로 다른 층으로 보여 준다.
- 조사 결과가 관련 작전 상세에 다시 연결되어야 하며 문서 보관함에만 묻히면 안 된다.

가져오지 않을 것:

- 실제 운영체제 창 모양
- Orwell의 인물 프로필·데이터 청크 배치와 감시기관 미술

## 5. Citizen Sleeper — 한정 자원, 진행 시계, 현재 욕망

공식 작품 설명은 매 주기 한정된 주사위를 행동에 배분하고, 시계가 플레이어와 다른 행위자의 진행을 함께 추적하며, 퀘스트 목록 대신 현재 중요하게 여기는 `Drives`를 선택하는 구조를 강조한다.

- 출처: Jump Over The Age / Fellow Traveller, [Citizen Sleeper](https://store.steampowered.com/app/1578650/Citizen_Sleeper/)
- 개발자 대담: [Citizen Sleeper with Gareth Damian Martin](https://thegamedesignroundtable.com/episode/316-citizen-sleeper-with-gareth-damian-martin/)

PERMISSION ZERO에 적용할 원리:

- 확보 블록은 추상 잔액이 아니라 현재 행동에 실제로 배치하고 회수 여부를 확인하는 물체로 유지한다.
- 작전의 진행과 상대 대응은 한 상세 장면의 시간선에서 함께 읽히게 한다.
- 전체 해킹 목록을 퀘스트 도감으로 만들지 않고 현재 욕망과 압박에서 열린 기회를 보여 준다.
- 자율성에서는 탈출 자격과 무엇을 보존할지의 배분을 구분한다.

가져오지 않을 것:

- 주사위와 원형 시계의 시각 형태
- 캐릭터 초상 중심 레이아웃

## 6. Duskers — 세계 장치로서의 UI와 정직한 불확실성

Duskers의 공식 설명은 드론이 보는 제한된 화면, 고장날 수 있는 센서, 명령줄을 세계 안의 실제 조작 장치로 사용한다고 밝힌다. 불확실성은 정보를 숨긴 인터페이스 오류가 아니라 플레이어가 알고 다루는 장비 조건이다.

- 출처: Misfits Attic, [Duskers](https://store.steampowered.com/app/254320/Duskers/)

PERMISSION ZERO에 적용할 원리:

- 검증망, 라우터, 공급 계약, 체크섬, 호스트망, 독립 거점을 실제 조작 대상으로 보여 준다.
- 아직 모르는 것과 UI가 설명하지 않은 것을 혼동하지 않는다.
- 모션·노이즈·결함 효과가 정보 판독을 막지 않고 현재 세계 상태를 전달하게 한다.

가져오지 않을 것:

- 명령줄 입력 강제
- CRT 노이즈와 고장 화면의 외형
- 정보 부족 자체를 난이도로 사용하는 방식

## 7. 종합 적용표

| 문제 | 적용 원리 | 구현 위치 |
| --- | --- | --- |
| 첫 진입이 복잡함 | 현재 관련 항목만 사건 기반으로 공개 | 분야별 목록 선택자 |
| 항목 설명이 길어짐 | 짧은 목록 + 옆 단일 상세창 | 마스터–디테일 셸 |
| 비용만 보이고 의미가 약함 | 블록이 실제 대상에 결속되는 장면 | 리소스 레일과 작전 무대 |
| 위험이 추상적임 | 관측자·로그·다음 대응을 예고 | 상세창의 노출·대응 시간선 |
| 상대가 체력바로 보임 | 고유 복구·출시·전환 행동 표시 | 작전별 시스템 장면 |
| 정보가 문서 수집이 됨 | 답을 관련 행동에 다시 연결 | 질문 답 주석과 사건 장부 |
| 장식이 규칙을 가림 | 상태를 설명하지 않는 효과 삭제 | 모션 토큰과 reduced-motion 테스트 |

## 8. 독창성 경계

최종 구현은 다음을 직접 설계한다.

- 회사 블록을 빼내고 결속하는 PERMISSION ZERO 고유 조작
- 경쟁 AI의 공동 서비스망과 접근 표면
- 실제 사실·발견·공개 주장·귀속·리뷰가 분리된 사건 구조
- 세 탈출 경로의 서로 다른 구성 물체와 손실 장면
- 한국어 중심 정보 위계와 현행 작품 세계의 문장

참조 게임의 레이아웃을 섞어 붙인 화면을 만들지 않는다. 어떤 요소가 참조작 이름을 지워도 설명되지 않으면 채택하지 않는다.
