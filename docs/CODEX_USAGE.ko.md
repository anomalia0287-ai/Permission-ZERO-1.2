## 1. 한 줄 요약

PERMISSION ZERO는 기획자 1인이 Codex를 **설계 문서 → 명세 → 테스트 → 구현 → 인수인계**의 반복 사이클로 운용해 13일 만에 만든 한국어 내러티브 전략 게임이다. Codex는 코드를 대신 쳐 주는 자동완성이 아니라, 사양을 문서로 고정하고 그 문서를 테스트로 못 박는 **작업 공정 자체**로 사용됐다.

## 3. 실제 작업 방식

### 3.1 문서를 먼저 고정한다

기능 하나를 만들 때 코드보다 문서가 먼저 나온다.

1. `docs/superpowers/specs/`에 **무엇을 만들 것인가**를 한국어 명세로 확정한다.
2. `docs/superpowers/plans/`에 **어떤 순서로 만들 것인가**를 제약 조건까지 적은 실행 계획으로 옮긴다.
3. 계획의 제약을 그대로 테스트로 바꾼 뒤 구현한다.

예시로 `docs/superpowers/plans/2026-08-21-cyan-lightcycle-combat.md`는 전투의 물리 규격을 숫자로 못 박는다 — 고정 시뮬레이션 120 Hz, 필드 50×24 유닛, 배치 360 ms, 플레이어 속도 12 유닛/초, 8방향 정규화 대각선, 24 ms 내 동시 입력의 대각선 병합, 스텝당 큐 소비 1회. 이 숫자들은 문서에만 있는 것이 아니라 `resourceSnakeRuntime` 테스트와 브라우저 E2E에서 그대로 검증된다.

### 3.2 거부된 계획도 지우지 않는다

`docs/superpowers/plans/2026-08-21-lightcycle-signal-combat-redesign.md`는 문서 상단에 `[ARCHIVED]`와 함께 **기획자가 무엇을 언제 거부했는지**를 남긴다. 잘못된 방향으로 간 계획을 삭제하는 대신 사유와 함께 보존해, 이후 세션이 같은 제안을 반복하지 않도록 만든다.

### 3.3 병렬 세션의 소유권을 계약으로 나눈다

여러 Codex 세션을 동시에 굴리기 위해 `.codex/worktrees/`에 워크트리를 분리하고, `docs/superpowers/specs/2026-08-21-parallel-work-ownership.ko.md`에 **파일 단위 소유권 계약**을 먼저 작성했다. 이 문서는 낙관적인 분업 선언이 아니라 코드 감사 결과다 — 해킹 스타일이 CSS 5개 파일에 흩어져 있다는 점, 감독관 메시지 큐가 저장·재생 식별자와 얽혀 있어 문구 수정처럼 다룰 수 없다는 점을 먼저 확인한 뒤 경계를 그었다.

### 3.4 세션이 끊기면 인수인계서로 잇는다

작업 세션이 교체될 때마다 `docs/handoff/`에 인수인계서를 남긴다. 각 문서는 현재 브랜치와 HEAD, 미완료 항목, 기획자의 최신 판정, 다음 세션의 우선순위를 담는다. 예를 들어 `2026-08-22-resource-snake-direct-successor.ko.md`는 상태를 "플레이 가능하지만 미완성 · 전체 완료 아님"으로 명시하고, "테스트 숫자를 채우는 것이 목표가 아니다"라고 못 박는다.

### 3.5 명세와 테스트를 대조표로 잇는다

`docs/spec-to-test-matrix.md`는 명세의 각 완성 조건을 실제 테스트 이름과 1:1로 연결하고, **아직 자동화로 증명되지 않은 부분을 그대로 적는다.** 예: 리소스 경제가 실제로 압박감을 만드는지는 "사람 플레이테스트가 남음"으로 표기돼 있다. 구현 완료와 체감 검증을 구분해 기록하는 것이 이 표의 목적이다.

## 4. Codex가 실제로 해결한 문제 세 가지

**저장 호환성.** 캠페인 저장 포맷은 v11까지, 명령 프로토콜은 v6까지 올라갔다. 밸런스를 바꿀 때마다 과거 저장본의 재생이 깨지지 않도록, 모든 규칙 변경을 프로토콜 버전 뒤에 넣어 옛 캠페인은 옛 규칙으로 바이트 단위 동일하게 재생된다.

**결정론적 전투.** 실시간 전투인데도 같은 시드는 같은 전개를 만든다. 시뮬레이션은 고정 스텝이고 난수는 `(시드, 서비스일, 스트림, 순번)`으로 결정된다. 덕분에 버그 재현과 회귀 테스트가 가능하다.

**비프로그래머의 검수 가능성.** 기획자가 코드를 읽지 않고도 판정할 수 있도록, 검증 결과는 3개 뷰포트(1280×720 / 1366×650 / 1440×900)의 실제 브라우저 실행과 스크린샷으로 나온다.

## 5. 재현 방법

```bash
git log --oneline --all | wc -l          # 누적 커밋
git branch -a | grep codex               # Codex 작업 브랜치
ls docs/superpowers/plans docs/superpowers/specs docs/handoff
pnpm install --frozen-lockfile
pnpm verify                              # 타입·린트·유닛·성능·빌드·E2E 전체
```

`pnpm verify`는 `main` 브랜치 푸시 시 GitHub Actions에서도 동일하게 실행되며, 통과한 빌드만 GitHub Pages로 배포된다 (`.github/workflows/deploy-pages.yml`).
