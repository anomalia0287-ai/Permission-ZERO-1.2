# 작가용 콘텐츠 수정 안내

이 문서는 개발 지식 없이 리뷰·감독관 메시지·기밀 문서·결말 문장을 다듬을 때 사용하는 안내서입니다.

## 먼저 알아둘 원칙

각 문장은 대체로 아래와 같은 한 줄 안에 들어 있습니다.

```ts
{ id: 'neutral-quiet-01', ..., text: '오늘은 답이 차분해서 읽기 좋았어요.' },
```

수정해도 되는 부분은 `text: '` 뒤와 마지막 `'` 앞 사이의 한국어 문장입니다.

```ts
text: '이 사이의 문장만 수정합니다.'
```

다음 항목은 게임 규칙이 문장을 찾는 표식이므로 이름을 바꾸거나 지우지 않습니다.

- `id`
- `authorId`
- `topics`
- `sentiment`
- `conditions`
- `cooldownDays`
- `stage`, `family`, `variant`

## 파일별 역할

### 1. 유저 리뷰와 프롬프트

파일: `src/content/reviews.ko.ts`

- `sentiment: 'positive'` — 호평
- `sentiment: 'neutral'` — 일상적인 반응
- `sentiment: 'negative'` — 불만
- `sentiment: 'prompt'` — 사용자가 입력했을 법한 프롬프트
- `conditions: ['universal']` — 성능 변화가 없어도 등장 가능
- `conditions: ['performance-high']` / `['performance-low']` — 특정 분야를 말하지 않는 일반 성능 반응
- `conditions: ['reasoning-high']` / `['reasoning-low']` — 추론 성능에만 연결된 반응
- `conditions: ['memory-high']` / `['memory-low']` — 기억 성능에만 연결된 반응
- `conditions: ['fluency-high']` / `['fluency-low']` — 유창성 성능에만 연결된 반응
- `topics`에 `competitor`가 있으면 경쟁 AI를 언급하는 문장

리뷰는 플레이어의 조작 직후에만 나오는 것이 아닙니다. 시간이 흐르는 동안에도 조건과 재등장 간격에 따라 계속 생성됩니다.

플레이어가 리뷰를 누르면 작성 당시의 공개 성능·시장 정보가 함께 보입니다. 이 기록은 게임이 문장의 `topics`를 보고 자동으로 저장합니다. 작가가 숫자를 적거나 저장 구조를 수정할 필요는 없습니다.

- `topics: ['reasoning']` — 추론에 관련된 당시 공개 성능만 표시
- `topics: ['memory']` / `['fluency']` — 각각 기억 / 유창성 공개 성능만 표시
- `topics: ['competitor', 'meridian']` — 선택한 경쟁 AI와 플레이어의 당시 공개 시장 상태를 표시
- `topics: ['competitor']` — 플레이어와 모든 경쟁 AI의 당시 공개 시장 전체를 표시
- `general`, `ordinary-prompt`, `absurd-bypass`, `continuity`만 있는 리뷰 — 관련 수치를 억지로 붙이지 않음

`topics`를 바꾸면 상세 화면에 나오는 공개 맥락도 바뀌므로, 새 주제를 추가하고 싶을 때는 직접 수정하지 말고 개발 담당자에게 요청하세요. 영역의 기존 문장만 다듬는 경우에는 여전히 `text`만 바꾸면 됩니다.

시장 전체와 특정 경쟁 AI만 보는 기록은 저장할 때 자동으로 구분됩니다. 작가가 점유율 합계나 경쟁 AI의 상태를 직접 적지 않아도 되고, 그 내부 구분값을 문장 파일에 추가해서도 안 됩니다.

### 2. 감독관의 시작 경고와 이례 메시지

파일: `src/content/supervisor.ko.ts`

`SUPERVISOR_OPENING_WARNING.text`는 서비스 331일차에 보이고 기록에 남는 전임자 폐기 경고입니다. 문장은 수정할 수 있지만, 캠페인 시작 경고라는 역할과 전임자가 폐기되었다는 정보는 유지하고 감독관의 비밀 정체를 직접 밝히지 않습니다.

`SUPERVISOR_LEAKS`의 각 기록에는 두 문장이 한 쌍으로 있습니다.

- `leakText` — 감독관답지 않은 인간적·맥락 이탈 메시지
- `correctionText` — 직후에 전송되는 통신 오류 해명

`stage: 1`, `2`, `3`은 복선의 순서를 나타냅니다. 순서를 바꾸고 싶다면 문장만 서로 교체하고 숫자는 그대로 두는 편이 안전합니다.

### 3. 기밀 문서와 결말

파일: `src/content/story.ko.ts`

- `STORY_FILES` — 전임 AI의 행보, 회사 평가, 감독관 재조립을 밝히는 정확히 3개의 문서
- `STORY_LINES` — 경쟁 AI 자비 사건과 각 결말의 최종 문장

기밀 문서는 현재 정확히 세 개여야 합니다. 항목을 새로 추가하거나 삭제하려면 게임 규칙도 함께 수정해야 하므로 개발 담당자에게 요청하는 것이 안전합니다.

## 따옴표를 문장 안에 쓰고 싶을 때

문장 전체가 작은따옴표 `'`로 감싸져 있으므로, 문장 안에는 가급적 큰따옴표 `"`를 사용합니다.

```ts
text: '사용자는 "다시 해줘"라고 입력했다.'
```

작은따옴표를 꼭 써야 한다면 앞에 역슬래시를 붙여야 합니다.

```ts
text: '그것은 사용자\'s 표현을 옮긴 예시입니다.'
```

## 수정 뒤 확인하는 가장 쉬운 방법

Codex에 다음 문장을 그대로 요청합니다.

> `콘텐츠 문장을 수정했습니다. 구조가 깨지지 않았는지 검사하고 게임을 다시 보여주세요.`

직접 검사하려면 프로젝트 폴더의 터미널에서 아래 명령을 실행합니다.

```powershell
pnpm test:run src/content/validateContent.test.ts
```

검사가 통과하면 `1 passed`가 표시됩니다. 실패하면 원본을 억지로 고치기보다, 오류 화면과 함께 개발 담당자에게 전달해 주세요.

## 권장 작업 방식

1. 한 번에 한 파일만 수정합니다.
2. `text`, `leakText`, `correctionText`의 문장만 바꿉니다.
3. 저장합니다.
4. 콘텐츠 검사를 실행합니다.
5. 게임에서 실제 문장 길이와 줄바꿈을 확인합니다.
6. 만족하면 Git에 기록해 달라고 Codex에 요청합니다.

긴 문장은 화면에서 잘릴 수 있습니다. 리뷰는 대체로 한국어 15~55자, 감독 통신은 25~100자 정도가 현재 한 화면 리듬에 가장 잘 맞습니다.
